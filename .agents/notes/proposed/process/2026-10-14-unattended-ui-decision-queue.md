# Agent Note: 无人值守 UI 修复的已确认规则与人工待决项

Status: proposed

## Problem

工作空间升级的 API 和 CI 已通过，但实际 UI 仍有作答输入丢失、结果信息缺失、
草稿误判、教学更新和导航等问题。用户要求继续无人值守修复，并将需要人工决策的
事项留到次日讨论。此记录是决策队列，不表示这些功能已经实现。

## Decision

### 用户已确认

- 以 `syupslzz` 的最新提交 `9b2e3d4c` 为开发基线。
- 参考本地 HydroOJ 的域内导航、域管理和用户菜单组织，保留 NOJ 的题型、
  LLM、版本、五种赛制及教练工作台。
- `/` 进入明确的 `/d/:slug` 地址；业务列表、成绩、进度和统计均在当前域内。
- 移除跨域提交汇总入口，不以全实例汇总作为用户首页。
- 点击右上角头像进入用户菜单，在二级菜单切换域。
- 当前域显示在用户名后，例如 `sakura_madoromi@main`，不另设常驻域切换区。
- 创建域只提供 `community`、`education`、`team`，移除 `custom`。
- 三种域都提供社区；域类型在创建后固定。
- 各类型能力由代码定义，不允许域管理员任意组合模块开关。
- 只使用 edit/apply_patch 编辑源文件，使用签名 jj 小提交；不启动 subagent。

### 无人值守的实施默认值

- 三种域共有题库、题单、五种赛制、提交、域排行、社区和本域 LLM；教学域额外
  提供班级、作业、学情和教练工作台。成员身份继续决定具体操作权限。
- 域名称、简介、访问方式、发现和加入政策、成员、Provider 与配额可管理；
  删除模块自定义和重新应用 Preset 的操作。实例治理限制仍有效。
- 根入口使用实例默认域；仅登录实例中有一个可用域时直接进入该域。明确域 URL
  始终优先，不由 Cookie、菜单选择或导航偏好覆盖。
- 域内页面使用一致的主导航和域管理入口；长题面使用适合编码的布局。
- 先修复实际流程，再检查视觉、移动端和键盘操作。验收必须覆盖真实浏览器交互，
  不能以组件构建或 API 通过替代。
- 普通错误、输入保护和真实并发按现有契约处理，不为不可能的状态增加复杂兜底。

2026-10-14 23:15 只读清点：本地开发库 `noj` 与独立恢复验收库
`noj_main_integration` 均未发现 `custom` 域，亦未发现非教学域的班级记录。
此结论只覆盖这两个库，不能代表其他部署或尚未检查的备份；D01/D02 不进行猜测迁移。

## Alternatives considered

- 保留任意模块组合和自定义类型：用户已明确取消。
- 照搬 Hydro 的自定义角色和作业模型：超出本次确认范围；保留 NOJ
  现有权限和教学模型。
- 无人值守时自动转换历史类型或绕过 PR
  审批：缺少具体授权，且与已确认的数据保留约束冲突。
- 遇到一般实施选择就停止询问：不符合无人值守要求；采用现有工程约定并留可 review
  记录。

## Consequences

导航和域类型的修复以这份确认记录为准，替代原方案中“Preset 仅初始化可修改配置”
以及跨域本人提交汇总的产品行为。历史数据转换和最终合入仍留待明确处理。
完成的代码行为另写 implemented Agent Note，本记录保持
proposed，直到人工待决项关闭。
