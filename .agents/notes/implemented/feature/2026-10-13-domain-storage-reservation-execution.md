# Agent Note: 域存储预留结算与上传崩溃核对

Status: implemented

## Problem

成员和题目容量已在创建事务检查，存储还没有在物理写入前落实额度。上传后崩溃或重复内容上传可能漏计或重复计量，旧对象未知大小也不能当作零字节。

## Decision

工作空间门面提供持久预约、流式增补、实际大小结算、失败释放、对象归属和计量核对。域计数在数据库行锁下原子检查当前实例及域上限。内容已知上传在写入前记录预留字节和对象地址；同域已保留内容不重复占用容量。

系统存储上传封装、删除守卫及 Domain 题包／OI 作者上传接入计量。系统后台每 30 秒处理有限批次：核实存量物理大小，对有业务引用的崩溃上传结算，对无引用对象执行删除守卫后释放预约。网络故障保留持久依据。归属外键建立先于域计数锁，结算与删除均采用对象到计数的锁顺序。

## Alternatives considered

只在上传完成后检查会先消耗真实存储。仅凭超时释放已定位预约会漏计崩溃遗留字节。给目标域共享题复制存储归属会重复计量。进程内计数无法协调多副本。

## Consequences

PostgreSQL workspace 标准测试通过 40 项，PGlite 通过 32 项、8 项 PostgreSQL 专用检查跳过；system 标准测试通过 157 项、1 项跳过。真实独立数据库连接竞争最后额度只成功一次；真实本地存储验证超额在 put 前拒绝、失败释放、内容复用、崩溃删除和存量大小核实。迁移安全、快照链、schema parity 及新增服务 lint 通过。

流式产物上传由提交模块后续接入；这里交付其所需门面，未将 T4.08 整体标为完成。浏览器、S3 故障旅程和完整恢复验收仍待执行。
