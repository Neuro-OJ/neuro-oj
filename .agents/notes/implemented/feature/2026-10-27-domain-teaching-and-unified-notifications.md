# Agent Note: 域级教学、作业来源与统一通知

Status: implemented

## Problem

Issue #696 的三个评论共同要求简化教学角色、明确作业计分来源、提供班级比赛榜，
并统一教学与普通通知及相应页面体验。原有班级教练和助教授权、双通知模型及固定
导航折叠方式不能表达这些要求。

## Decision

- 教练使用当前域角色管理同域全部班级、作业、题目和比赛；班级只保存学生名单。
  教练可接收本域现有成员，但不获得域外邀请、域成员治理、封禁或 LLM 配置权限。
- 作业默认 `domain_any`，历史提交默认关闭；`assignment_only` 要求提交携带相同
  作业和条目来源，并禁止历史提交。进度和提交依据采用相同来源限制。
- 比赛关联同域多个班级，赛制引擎完成授权与成绩选择后按当前学生名单分组，
  去重并保留同分排名；单班筛选不改变其他参赛者的补集定义。
- communication 拥有统一 `notifications` 表与 CRUD。HTTP 组合根组合普通和
  教学资源的当前授权，列表、未读数、已读、详情及 SSE 重放均复用该条件。
  域权限撤销只隐藏相应通知，不关闭整个账号的其他通知入口。
- 注册事务在邀请消费后同样加入 main；不回填既有账号。题库展示历史最高有效
  分数，历史发布版本可独立阅读与提交，有效成绩继续由域策略决定，比赛保留固定版本。
- 导航按实际宽度折叠，班级研练中心紧随首页；版本选择放入题面工具栏，移除作业
  比较和版本沿革按钮，强化求助入口并增加卡片间距。

## Alternatives considered

保留助教能力组合会继续造成两套授权事实；只在前端合并两个通知列表会导致分页、
未读数及撤权行为分叉；以比赛快照保存班级成员会使离班与入班后的分组失真，因此
均未采用。已有成绩事实及后端沿革保留，不以隐藏按钮删除审计依据。

## Consequences

本变更针对尚未上线的 rc/v0.11，按用户确认无需迁移业务数据。使用生成的 schema
迁移调整空环境结构，删除旧通知表和助教结构，不提供旧通知数据搬运或角色转换。
测试仅使用本任务专有 PostgreSQL、Redis 和存储目录，不修改既有服务。
本工作不发布版本标签、不合并 main，也不代表生产或真实浏览器验收已完成。
