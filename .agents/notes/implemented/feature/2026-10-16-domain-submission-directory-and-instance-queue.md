# Agent Note: 全题型域提交目录与实例评测队列

Status: implemented

## Problem

域提交目录原先固定查询本人，客观题使用另一份列表，无法按用户名查阅授权摘要。 原队列端点固定
main，无法表达其他域的队列与实例整体负载。

## Decision

域提交列表复用原本人历史中的 SQL 联合来源及结果投影，在数据库计数与分页前
加入域、题库绑定、比赛及查看者条件。用户名筛选不改变实际查看者身份；本人保留
资源撤销后的受控摘要，他人只保留有权访问题目的摘要，不返回原代码或答案。
教学关系消失后可以保留普通成员本来可见的摘要，但不能继续读取学生源码。

队列提供显式域及实例接口。实例数字反映整体负载，明细继续按当前成员关系、
资源授权和自测归属过滤，且区分可见任务数量。共享资源池统计不伪装成本域资源。 SSE
使用域频道或只含失效信号的实例频道，每次推送和重放都重新授权。

Web 统一为“提交”目录，用户名默认本人，清空后将空值保存在 URL；普通与客观题
沿用各自详情能力。队列在同一页面切换当前域与实例，提示全局计数和授权明细的
区别；域或范围切换后忽略旧请求的结果，并关闭旧 SSE 订阅。

队列响应与查询范围类型集中在 submission/types/queue.ts，服务及原公开门面继续
导出相同类型。服务文件由此保持在仓库规模阈值内，不提高行数基线，也不改变查询 与评测行为。

## Alternatives considered

不在浏览器合并分页结果，也不先取全实例提交再逐条过滤；不以筛选用户名充当
查看者。没有为不可见私有任务返回占位行，没有添加原始评测日志或新详情抽屉。

## Consequences

授权逻辑同时约束结果和计数，新增其他用户摘要不扩大源码、答案及教学权限。 API
验收覆盖短码注册、三类邀请、统一客观题目录、跨域拒绝及队列范围；模块 测试继续覆盖赛制裁剪、本人历史及教学撤权。评测
Worker 和提交受理系统保持复用。
