# Agent Note: 公开题单引用与作业发布展开

Status: implemented

## Problem

题单授权不等于其中每一道源题的共享授权。提前复制题目集合会使草稿无法跟随
最新题单，发布时部分导入失败又可能遗留无用绑定或消耗额度。

## Decision

题单引用只保存来源关系，提供独立共享政策、定向目标和实时读取检查。域题单
创建和完整编辑使用 revision，题目仍引用源题主键；新准备 API 使用显式域路径。
公开题单不能收录目标域未公开展示的题目。

作业草稿在手工题目和题单来源之间二选一，题单来源保存默认达标要求。发布事务
重新读取当前题单，逐题检查授权，建立必要的目标域绑定，固定集合、顺序、版本
依据和学生名单。超过额度、共享失效等任何错误回滚整个事务。源题单后来调整
或停止共享不修改已发布任务；已有条目继续服从源题各自授权。

发布按稳定 ID 先锁所有涉及的域，再取班级和任务锁，题单宿主锁及 revision
保护展开期间的集合。旧题单修改入口也递增宿主 revision。草稿复制保留题单
来源；已发布任务复制使用固定条目，独立计算补题成绩。

教学人员具有公开资源引用能力，不因此获得源题编辑、发布或全域源码权限。
仅有班级作业能力的助教可用已有题库绑定；新增题库引用仍要求域资源引用能力。

## Alternatives considered

- 草稿阶段建立所有绑定：会过早消耗题库额度，因此延迟至发布事务。
- 复制题单及题目内容：会产生多份源数据，因此保存来源并只固定任务条目。
- 题单撤销时删除已有作业条目：会破坏教学历史，因此题单与题目授权分别处理。

## Consequences

追加迁移 0123，题单增加 revision，作业增加可空的来源及要求字段，运行时 PGlite
DDL 同步更新。开发库与恢复库保留原资源完成追加迁移。

题库条目数量限制直接参与事务。测试验证在第二道题超过额度时第一道题的绑定
也回滚，连续修改题单只影响尚未发布任务，题单撤销不破坏已有任务及补题复制。
准备路由等待全入口隔离验收；域题单分页、完整 Web 和客户端入口另行交付。

验证：catalog PostgreSQL 354 项、education PostgreSQL 45 项、workspace
PostgreSQL 34 项通过；PGlite 教学专项同样通过。完整 core 类型、受影响格式和
lint、迁移安全、Schema parity（98 表 / 876 列）、快照链、模块边界、CI 路径
及导出文档门禁通过。开发库升级后仍保留 3 道 P 题、22 个账号，U 题及旧比赛 仍为
0；未重建数据库。
