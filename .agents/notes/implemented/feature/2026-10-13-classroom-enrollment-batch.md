# Agent Note: 班级申请与 CSV 批量入班

Status: implemented

## Problem

班级只有单人邀请，教师不能预览并执行整班导入。本域普通成员也没有申请班级的入口，不能用内部账号创建替代学生自主注册或接受邀请。

## Decision

已有本域成员通过专用链接申请学生身份，链接只显示班级名称和本人申请。成员管理能力允许分页审核，批准复用学生入班与作业接收者同步，拒绝及注销身份保留历史。审核使用班级
revision 和幂等键，不授予域管理或教学角色。

CSV 每批 1–500 条、512 KiB，使用固定版本标准 CSV 解析器，支持 BOM、CRLF
和引号。email／username
仅定位已有账号或邮箱邀请。预览区分本域账号入班、邀请、已加入、已有邀请、重复和逐行错误；教学人员另行调整，不被批量学生操作降级。

执行持有账号、域和班级锁并重新验证预览事实，变化返回冲突。有效行在业务事务内完成，错误行明确跳过；不创建平台账号，不绕过注册政策、全站封禁、Domain
成员额度或邀请消费检查。

账号使用 NO KEY UPDATE 保护注销和身份变化，同时允许其他教学写入需要的外键 KEY
SHARE，避免等待域／班级时阻塞另一位教师的审计外键。真实 PostgreSQL
测试观察物理锁等待，再验证另一事务完成审计且批量入班继续完成。

邀请明文只在首次响应出现，幂等记录只保存邀请 ID
和结果事实。重试返回原执行结果而不恢复令牌；需要新链接时显式预览重签，原链接同事务撤销。标准依赖锁由
Deno 解析生成，没有手动编辑锁文件。

## Alternatives considered

- 批量创建全站账号：违反已确认的学生注册和实例政策。
- 把邀请令牌存入幂等 JSON：破坏邀请仅持久保存哈希的约束。
- 只锁班级不检查匹配事实：预览后的注销、成员退出或身份变化可能导致错人入班。

## Consequences

准备接口已完成申请、审核、预览和执行，生产入口仍等待完整域隔离。专用浏览器旅程、满批负载和通知联动继续验证；40
条邀请测试不等于 40 人完成教学闭环。
