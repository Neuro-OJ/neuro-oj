# Agent Note: 作业草稿发布与补题 Web 流程

Status: implemented

## Problem

教学准备页面已有成绩和互动，但教师无法从界面创建任务、预览发布依据、管理截止或复制部分学生的补题。编辑与发布还必须保留并发版本，不能静默使用别人修改后的内容。

## Decision

新增草稿创建／编辑、题库分页选择、精确来源题号添加、已引用题单预览、达标要求和部分目标学生选择。显示分精确转为
×100 整数，拒绝多余精度；时间在客户端按当地时区编辑并转为 UTC。使用已有
MarkdownEditor 和管理表单组件。

草稿详情展示题目、要求、历史提交选项及实际学生预览。发布、定时发布、延长截止、提前结束和归档复用已有事务接口，发布和复制携带幂等键，所有规则修改携带原
revision。表单保存冲突保留输入，重新读取须由教师明确丢弃未保存内容。

复制／补题明确选择当前学生及原条目，生成独立草稿供再次预览发布，保留原任务。确认或请求期间切换域／账号不会把旧结果应用到新页面。发布成功后进度数据键包含发布事实，自动触发首次矩阵读取。

## Alternatives considered

- 从旧全站题库选择：会丢失使用域、共享授权和成绩口径。
- 发布时重新读取新 revision 并自动重试：可能发布未审阅的修改，保留冲突。
- 在截止时冻结作业成绩：与已确认的持续策略和重测规则不一致。

## Consequences

这些页面仍随准备后端等待完整域隔离后开放。整班未达标自动筛选、比赛来源补题、变化通知和浏览器旅程仍在后续工作中。本记录只涵盖已实现的手动选题／学生与作业生命周期。

测试覆盖精准分数、本地时间、域内题单定位、冲突草稿、学生稳定
ID，以及确认期间切换和原发布 revision；组件与构建不是完整教学浏览器验收。
