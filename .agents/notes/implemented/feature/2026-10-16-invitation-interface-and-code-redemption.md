# Agent Note: 三种邀请界面与短码兑换

Status: implemented

## Problem

原成员页只提供指定邮箱邀请，无法分发通用或一次性凭据。持有短码的用户也缺少
手动查询入口。域和班级各自实现邀请表单，状态与后端使用次数契约容易分歧。

## Decision

Gemini 编写共享 InvitationManager，负责三种模式、有效期、使用人数、分页和撤销。
域与班级宿主页负责权限及可写状态。邀请链接和短码只在创建响应后展示，历史列表
不声称能够再次读取明文。通用邀请以使用次数及上限判断是否耗尽，最后使用时间
不代表邀请失效。

加入页支持手动输入短码，先通过 POST 预览，再由用户确认接受。新用户注册入口
服从服务器 can_register，不从邀请模式推断注册权限。班级成员页复用此组件，保留
CSV 导入、成员角色和申请审核功能。

## Alternatives considered

没有继续复制域和班级两份表单，也没有加入自动邮件发送、管理角色授予、永久
邀请或批量生成一次性邀请码等未批准能力。

## Consequences

邀请组件、加入页、班级接入及凭据辅助函数有直接测试，完整组件集本轮通过 309
项。整合后的域设置页及真实浏览器旅程仍在独立验收中；本记录不表示整个
设置改造或远程 CI 已通过。
