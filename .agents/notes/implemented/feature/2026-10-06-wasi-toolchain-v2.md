# Agent Note: 修复 WASI 标准库开销并冻结 v2 工具链

Status: implemented

## Problem

SDK 34 的标准流关闭同步并未切换缓冲；整数解析包含宽整数溢出乘法和通用字符
搜索，使普通 cin 提交承担不合理的额外 fuel。只改变换算尺度会同时放宽其他算法。

## Decision

基于固定 SDK 和 LLVM 提交，定向回移标准流缓冲补丁，优化整数解析并保留边界、
locale 和流状态语义。统一构建入口校验来源、补丁和组件清单，Worker 启动时验真实
内容，编译时固定 SDK 路径及清单；生产 SDK 对 Worker 只读，不新增配置缓存。

新增 noj-wasm-v2，保留 v1 的完整清单及历史结果，不改算子成本、换算单位或运行
保护。v2 绑定构建配置、补丁和组件摘要，并规范化 SDK 路径；旧任务拒绝后可重测。

## Alternatives considered

要求选手采用快读、扩大所有程序预算、改写提交源码或免除标准库 fuel 都不能保持
兼容性与统一计量边界，未采用。本次也不将本机 CPU 测量拟合为统一成本规则。

## Consequences

普通 cin 的成本由平台标准库优化承担。修补库需要独立构建与冻结验收；不同目录
产物、独立 Worker 结果、整数边界、locale、文件 IO 和解析成本均进入 CI 检查。
部署须先排空旧任务，避免混合标准；旧成绩不自动重测，跨版本不能直接比较。

本地完整正式 club 数据 20/20 AC，原算法和 cin/cout 不变；此前大样本的 fuel 由
9,163,992,998 降至 2,113,128,811（降低 76.9%），不扩大预算。整数解析成本
低于完整边界对照的三倍。独立目录 SDK、独立进程评测和生产镜像验收一致； 未修补
SDK 与被替换的头文件都被启动校验拒绝。P4 的 AC/WA/CE/TLE 和 P3
原生链路通过服务器端回归；本轮网页验收因浏览器访问权限校验不可用而未完成。

提交域搜索事件测试改用用例专用 Redis，消除同一进程其他队列测试残留 mock
造成的假失败；不改变生产连接实现，也不增加测试跳过数。

CI 另用固定生成的 club 类输入覆盖普通 cin 与优先队列算法，答案可独立求和。
同一源程序和输入的 v1 对照消耗 11,607,613,534 fuel，v2 消耗 2,544,615,827 （降低
78.1%）；输入/源码摘要防止基准漂移，CPU 时间只报告，不作为门槛。
