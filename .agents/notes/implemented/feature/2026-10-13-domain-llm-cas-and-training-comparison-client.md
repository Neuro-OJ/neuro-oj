# Agent Note: 域 LLM 并发配置与训练记录比较客户端

Status: implemented

## Problem

Provider 与额度的远端并发接口升级为资源修订号，客户端此前没有发送前置条件。
配额要求手输用户／题目 UUID；保存 Provider
后整体重读还会覆盖其他未保存的模型草稿。 教学时间窗比较 API 已就绪，但 Web
没有明确选择时间窗并解释候选和达标的入口。

## Decision

- Provider／quota 新建发送 If-Match 零，更新和停用发送打开时冻结的资源
  revision。 模型默认配置仍使用自己的 revision，不借域配置 revision。 旧 main
  管理写接口同步携带资源版本；Provider／用量旧页固定进入 main 的新域管理页，
  global 实例配额页面继续保留。
- 每种成功写操作只重新读取该类资源，保持其他尚未保存表单。
  冲突保留原输入和编辑依据；显式重读列表不自动提升打开的旧表单版本。
  列表以替换整体异步数据对象更新，兼容 Nuxt 默认的浅层响应；成功写入后的编辑版本
  来自自己的写响应，不借随后列表中其他操作者的新版本。
- 配额用户、题目及组合采用分页的当前域成员和绑定题目选择，显示用户名与来源题号，
  内部仍使用稳定主键。展示实例日／月上限，空额度发送
  null，不转换为零或环境默认值。
- 实例总额度的新输入只允许 null 或非负 PostgreSQL integer；历史负数仍显示不限，
  打开编辑先转换为 null，不回传负数。兼容题目入口的实际 404 转为中文题目不存在，
  其余鉴权或系统错误仍传播，不寻找其他域。
- 作业矩阵选定学生与学生本人作业页提供独立训练比较组件，用户显式选择两段时间窗并读取。
  本地时间转换为 UTC ISO，请求保留目标域、作业和学生身份，不逐单元自动扫描。
- 对比只展示服务端当前策略和权威结果，包括分数、正式通过、达标、候选、排队及版本不匹配。
  最高分和通过来源独立解释；缺分不转零分，缺少两窗正式分数不生成变化值。
  结果属于训练记录比较，不修改原作业统计，也不当作能力评价。

## Alternatives considered

- 用重新读取的最新 revision
  提交旧表单：会覆盖别人更新，保留原编辑依据并返回冲突。
- 每次写入后重载全部 LLM 数据：会丢失未保存模型，改为按资源重读。
- 将客户端题号直接作为额度对象主键：来源展示号与稳定题目 ID
  分开，仍由域授权接口解析。
- 自动比较整张成绩矩阵：请求量随学生与题目数增长，仅对所选学生按需读取。
- 用最低分达标推断 AC：与确认的正式通过规则不符，独立呈现服务端判定。

## Consequences

域 LLM 编辑会清楚暴露并发冲突，跨域／账号切换不使用旧操作结果或密钥表单。
自然选择仍尊重资源实时授权；分页之外既有配额对象保留稳定位置，不猜测另一个来源题号。
训练比较明确展示时间窗、版本口径和受理提交依据，策略或重测变化后重读可能改变结果。
组件回归验证冲突保留、组合配额、单项刷新、资源版本、身份变化、缺分和独立达标。
真实 Gateway／Judge／浏览器旅程及性能验收仍由整体验收阶段执行。
