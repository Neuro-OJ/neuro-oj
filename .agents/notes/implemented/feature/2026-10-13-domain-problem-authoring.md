# Agent Note: 域源题草稿目录、数据编辑与事务题包导入

Status: implemented

## Problem

域题库普通列表只返回已发布题目，创建草稿后无法从正常入口找回。 旧 OI
数据和题包接口使用全局题目权限，不能由学校编辑者管理本域源题。 旧题包按 P/U
与数字编号匹配，可能把同一数字的既有题目当成不存在并绕过题型不可变约束。

## Decision

新增仅返回可编辑本域源题的草稿目录。OI 数据列表、文本预览和下载都解析路径
Domain， 共享引用不授予源数据编辑权。保存文件复用现有 ZIP
安全与对象引用守卫，草稿 revision
和编辑授权在最终写入事务中复核，配置、逐文件引用与支持包同时切换。

域题包支持导入新源题及按路径替换已有草稿。指定数字匹配只使用 Domain 和数字；
更新已有草稿必须提供原 revision。新建沿用统一创建校验、原子编号和容量检查，
初始题包内容、文件引用、本域绑定与策略依据共用创建事务，失败不留下源题或占用编号。
题包不隐式发布；预检校验当前 revision，显式发布复用不可变版本流程。

CLI 容器导入接受 `--domain`，缺省 `main`；运维更新先读取已授权的当前草稿基线，
实际写入仍检查捕获的 revision。`--publish` 显式调用同域发布服务。
格式转换提示从解析器传到 API 和 CLI。LLM 题不再由 P/U 分类决定，
网络和敏感评测能力继续要求实例授权，Provider 与模型仍由使用域执行配置决定。

## Alternatives considered

- 转发旧全局文件入口会把平台权限与域角色混用，采用域入口和现有底层编辑服务。
- 先创建题目再另事务写题包会留下失败身份，采用受控初始草稿参数共用创建事务。
- 导入直接发布会使上传与正式作答版本切换混在一起，保留独立预检和发布动作。

## Consequences

标准 catalog PostgreSQL 回归 361 通过、0 失败。真实 HTTP 场景覆盖未发布题找回、
OI 上传及文本读取、外域拒绝、revision 冲突、预检和发布、套卷题包替换、
按域编号导入、创建草稿失败回滚，以及普通域负责人经真实实例角色授予网络能力后创建
LLM 题。 相关路由、CLI 和测试类型检查通过。格式 v2 与 CLI 校验同步另有独立记录。

这些测试不替代真实浏览器上传、Judge 执行或存储容量验收。域业务路由仍须在全入口
隔离检查后由组合根统一开放；存储预约容量与跨域历史保留属于后续批次。
