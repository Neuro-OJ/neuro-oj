# Agent Note: 竞赛最终成绩结算门禁与正式成绩入口

Status: implemented

## Problem

已有竞赛排名快照支持版本化和 CSV 导出，但管理员可以在竞赛结束前发布，
也无法在发布前看见待处理/失败评测。普通参赛者没有独立的正式成绩入口，
修订版本的核对与导出范围也不够明确。

## Decision

- 发布快照前强制检查竞赛状态必须为 ended；pending/judging、缺少评测结果的任务
  计入待处理并拒绝发布。
- error 评测默认拒绝发布；管理员必须填写说明并显式确认允许带失败评测发布。
  管理端提供计数和最多 500 条任务明细，便于处理后重试或留痕。
- 正式成绩通过独立的 `final-ranking` API 展示版本、说明和发布时间；实时排名
  继续使用原接口，前端明确标记实时成绩与正式成绩。
- 保留不可变快照历史，新增历史元数据查询和 JSON 导出；每次修订继续生成新版本，
  审计记录携带上一版本和失败任务数量。
- 本次不新增数据库字段或迁移，复用已有快照、提交和评测状态模型。

## Alternatives considered

- 只在前端禁用发布按钮：不能防止直接调用 API，也无法处理并发或管理员脚本。
- 遇到失败评测一律拒绝：无法覆盖已经人工确认的永久失败任务，因此保留说明+显式
  确认的受控例外。
- 将正式成绩覆盖实时排名接口：会让缓存、轮询和重测结果混淆，因此使用独立入口。

## Consequences

正式成绩发布具备服务端硬门禁，失败评测的例外发布可通过说明和审计追溯；
用户能够区分实时与冻结版本。任务明细当前最多返回 500 条，完整计数仍返回，
超大竞赛后续可按提交查询接口增加分页。
