# Agent Note: 五赛制计分与基础结果裁剪

Status: implemented

## Problem

原比赛仅支持 Kaggle，无法表达最后受理提交、ACM 解题数与罚时、OI 隐藏反馈，
也没有跨普通和客观题的可靠受理序号。客观题旧赛期隐藏总分，与批准规则不符。

## Decision

扩展五种类型与统一计分输入。数据库共享序列分配两类正式提交的受理顺序； OI、IOI
和严格模式先选最后受理提交，再读正式判定，未完成或平台失败明确待
处理，不回退早期高分。已有正式判定不因平台重测失败抹去。

ACM 按首次有效 AC 和此前计罚失败计算，CE 与平台错误不计罚；默认 20 分钟，
默认最后一小时封榜，短赛裁剪为整场。冻结视图保留窗口前成绩并标记后续提交
pending。OI 系列同分并列，ACM 同解题数与罚时并列，ID 只稳定显示顺序。

编程题采用整数满分换算；客观题一次交卷及原始百分制分直接相加。Kaggle 默认
本人榜，支持赛前完整榜配置。创建及编辑检查固定版本题型，开赛后锁定赛制与
计分配置；只改赛制也检查现有选题。

OI 本人详情与列表采用中性回执，结果筛选不能推断隐藏判定。IOI 仅返回允许的
测试点及子任务元数据，严格模式和 ACM 只返回汇总字段。执行历史、原始输出和 任意
evaluator details 不通过这些视图透传。比赛组织权限与普通提交读取权限
分开。Kaggle 客观题赛期返回总分，仍隐藏标准答案、解析和逐题正确性。

正式成绩继续版本化保存，不因后续重测改写；重新发布必须提供原因。按文件
规模门禁将固定题目读取与作答状态拆到独立服务。

## Alternatives considered

按评测完成时间取最后提交会受排队影响。每种赛制复制评测 Worker 会分裂正式
判定事实源。采用共享评测链和 core 计分策略，裁剪在读取边界执行。

## Consequences

迁移 0118 在开发库、恢复库和隔离 PostgreSQL 测试库通过。全 core 并行回归 unit
373、db 1633 项通过，0 失败、17 项跳过。后续赛制切换校验、模块拆分及
重新发布原因规则由 contest 专项复核；静态检查、迁移安全及 Schema parity 通过。
最终 PostgreSQL contest 专项 106 项通过、0
失败，覆盖客观题不加权和重新发布理由。

控制、域比赛归属、前端赛制页面和浏览器旅程。不得把此记录或全量旧行为回归
