# Agent Note: 评测教学事件与数据库租约消费者

Status: implemented

## Problem

作业进度需要跟随提交和重测，但评测事务不能直接更新教学页面或所有矩阵。
进程重启、消息重复和并发消费者不能丢失待计算的进度或以旧事件分数覆盖新事实。

## Decision

普通与客观题的提交投影入口在同一业务事务中写入教学 outbox，从已存提交读取
不可变使用域、学生和源题，不接受客户端或 evaluator 覆盖 Domain。

消费者以短事务及 SKIP LOCKED 领取数据库事件，使用 60 秒租约和随机租约标识。
每步只重算一份作业的一页 50 名实际学生，持久保存任务及学生游标，然后释放
租约继续领取。重启或中途崩溃重算同一页仍幂等；过期租约可接管，旧租约不能
提交游标。失败保留事件、记录错误类别并退避，避免保存可能包含源码的原始异常。

后台循环同时执行定时发布。待处理事件持续排空，空闲时每 1.5 秒检查；无需 Redis
通知才能推进。消费者接入 core 启动和停止，只有本进程生命周期句柄留在内存，
业务计数、游标、租约和重试状态全部在数据库。

## Alternatives considered

- 在评测回调同步更新所有作业：延长结果事务并产生跨模块耦合，因此只写共享事件。
- 单次事务处理全班或全域：可能产生无界事务，因此分学生页并保存游标。
- 从事件成绩累加：重复或乱序会损坏成绩，因此每次读取最新正式判定。

## Consequences

教学 PostgreSQL 和 PGlite 各 31 项通过，提交模块 334 项通过、10 项忽略。
测试覆盖真实投影事务产生事件、业务事务回滚、后台自动更新、并发领取、过期
接管、旧租约提交被拒和重复重算。小场景自动更新在 5 秒内完成；这不替代完整 矩阵
p95、规模及恢复性能验收。类型、格式、lint、域边界、CI 路径覆盖通过。

已接入发布、名单变化与普通／客观题单条投影变化。源版本、策略、共享撤销、
提交删除、比赛结束及模块停用的完整事件覆盖仍需补齐；过期矩阵读取、通知和 Web
教学流程仍在实施。本记录不标记整个作业或教学阶段完成。
