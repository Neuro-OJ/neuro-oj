# Agent Note: 显式域比赛管理与固定版本访问

Status: implemented

## Problem

原比赛入口依赖全站角色及全局题库，无法表达同一用户在不同学校的组织权限，也不能阻止把另一域比赛 ID 填入当前域路径。固定比赛版本的读取必须同时服从当前源题共享授权。

## Decision

- 增加暂未挂载的 `/domains/:slug/contests` 路由，域访问先于比赛定位。创建、修改、报名及参赛名单操作在事务内重新读取域成员和能力，创建题目关联保存目标域及绑定 ID。
- 比赛修改采用 `If-Match` revision，缺少前置条件返回 428、旧 revision 返回 409。开赛后禁止修改赛制、题目、受理窗口及封榜配置。
- 五种赛制复用既有计分与快照引擎，组织者权限来自当前域角色及比赛创建者的 `contest:manage_own` 能力。正式成绩发布检查在途任务，失败发布及重新发布保留说明。
- 题面、代码模板和客观题小题读比赛固定版本，引用题保持来源题号。模板不回退最新版本，客观题作答卷面不返回答案或解析。底层题面读取同样检查已有绑定的当前共享状态，避免旧默认域入口绕过撤销。
- SSE 每次推送及持久提交事件重放重新授权；提交事件只返回允许的定位字段，组织者身份降级后不再返回他人提交 ID。成员移除后关闭私有比赛长连接。
- 旧无域入口只定位默认域比赛。迁移扩展期仍存在旧 NULL 绑定测试记录；收缩与旧分类移除由后续阶段统一完成。

## Alternatives considered

- 在 JWT 存当前域或组织角色会导致撤权延迟，并使多个标签页相互影响，因此使用请求路径和数据库当前角色。
- 独立开发域比赛计分器会产生两套赛制规则，因此继续使用统一引擎，仅增加授权、定位和题库绑定门面。
- 复制源题或模板到目标域会令共享撤销失效，因此读取不可变源版本，并实时检查当前授权。

## Consequences

显式域比赛 CRUD、报名、题面、模板、客观题卷面、实时/封榜/正式榜、结算与 SSE 已有服务及 HTTP 测试。标准 contest 任务同时用于 PGlite 和专属 PostgreSQL 测试库，测试覆盖固定版本、共享撤销、域路径隔离、角色降级和 SSE 重放。

本记录只签收上述后端行为；比赛提交接口由 submission/objective 模块接入，浏览器旅程、完整查询隔离、生产路由开放及协调发布仍待整体验收。
