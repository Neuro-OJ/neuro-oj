# Agent Note: WASM v3 参考毫秒与整数预算换算

Status: implemented

## Problem

v2 固定每等效毫秒一百万 fuel，与本地原生评测存在明显尺度差异。用户根据 club 对照样本批准采用每参考毫秒两千万 fuel，并恢复 club 官方每点 1000ms。正式执行、checker 和独立分析工具曾分别包含写死的旧预算尺度，仅修改清单会造成预算与展示不一致。

## Decision

新增不可变的 noj-wasm-v3 清单与 Core/Worker 内置副本，固定 20,000,000 fuel/ms 和参考毫秒说明。v1/v2 清单及快照保持原样；v3 保持 v2 的全部算子、内存、IO 程序成本、修补工具链与运行保护。整数预算换算集中到标准模块，正式执行、checker 与分析工具使用当前标准；界面根据结果版本保留历史单位名称。独立分析所需的内嵌 Python 资源与 Rust 模块放在同一源码目录，保证仅复制 src 的生产和 E2E 构建也包含运行资源。新增 v3 基准与独立分析快照，检验产物及实际成本未变、预算为旧尺度的二十倍。

## Alternatives considered

- 原地修改 v2：破坏历史结果与跨实例可比标识，拒绝。
- 只改展示或题目时限：掩盖预算尺度残留，拒绝。
- 排除标准库 IO：尚未验证可靠来源隔离与普适计费规则，本次保留全部成本。
- 将比例视为真实 CPU 时间模型：样本只覆盖部分选手，存在截断与未定义行为，明确限制其含义。

## Consequences

新任务绑定 v3，旧标准任务被 Worker 拒绝并提示重测；部署需排空旧任务并配套升级 Core/Worker。历史结果不自动改写；本地 P5/P7 恢复 1000ms 后仅按用户要求重测原来的 50 份样本。原生计量及 SDK 内容不变，无数据库迁移或新增配置缓存。参考毫秒不保证等于真实 CPU 毫秒，后续校准仍需独立逐点与更多算法样本。
