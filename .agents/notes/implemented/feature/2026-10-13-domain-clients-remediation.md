# Agent Note: 全班未达标补题候选客户端

Status: implemented

## Problem

矩阵快捷补题仅覆盖当前页，教师无法据此确认整个班级的未达标学生。
独立补题需要明确成绩口径、学生和题目范围，并在创建前检查候选依据仍有效。

## Decision

新增全班补题预览入口，要求作业管理和学情读取能力。预览独立调用
assignment remediation-preview 接口，选择按时成绩或当前补做进度，
不逐页读取矩阵。展示每名候选学生未达标题号、统一达标要求，允许分别调整学生和题目范围。
页面明确每名所选学生收到全部所选题目，任务创建为独立草稿，仍需预览和发布。
可选题目只包含有稳定未达标候选的有效资源；选题变化时移除没有相应未达标题目的学生。

创建携带来源 revision、事实 preview_token 和幂等键，保留原作业和提交。
相同请求重试沿用幂等键；候选冲突保留选择和标题，提示教师刷新候选。
待更新单元、不可用题目和历史学生由服务端排除并展示数量。
部分单元 updating 不阻断稳定候选的创建。

## Alternatives considered

保留手工复制和当前页快捷补题供教师明确选取；全班入口使用批量服务端候选。
不以浏览器矩阵翻页替代全班接口，不在客户端累积计算成绩，不自动刷新并提交变化后的候选。

## Consequences

组件及 API 契约测试覆盖末页候选、学生与题目筛选、独立 revision/token 请求、
无学情能力时隐藏入口、局部更新仍允许稳定候选、冲突保留表单和相同重试幂等键。
客户端已接入实际约定的批量接口；数据库全班聚合、组合根和浏览器旅程由后端及整体验收验证。
