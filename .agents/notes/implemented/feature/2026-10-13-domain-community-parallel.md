# Agent Note: 域社区内容隔离与实时撤权

Status: implemented

## Problem

原社区的板块、帖子、题解、评论、治理与通知使用全站数据和角色。私有学校中的内容可能通过帖子 ID、列表计数、收藏、通知或全局治理接口被其他域读取；学校比赛还可能暂停整个公共社区。

## Decision

- 复用既有社区 CRUD，增加请求局部 `CommunityScope`，包含明确域、当前成员与治理身份及数据库事务。新增暂未挂载的 `/domains/:slug/community` 路由，写入重新授权并与成员及域状态操作共享数据库锁。
- 板块 slug 只在域内唯一。帖子、评论、题解、治理与通知保存所属域，评论和回复使用同域同帖复合约束。旧无域服务固定默认域，扩展阶段的 NULL 旧记录保留默认域兼容口径；统一账号关注及私信举报不改成域关系。
- 题解引用当前域题库绑定，来源题号和源题 ID 保持稳定。列表、计数、收藏及通知在分页前调用 catalog 的绑定可用性 SQL 门面，源共享撤销、源域停用或题库绑定禁用即时停止展示。评论编辑、互动和举报同样检查父帖的当前授权。
- 题解通过门槛只读取同使用域的代码与客观题有效通过记录，尚未结束的比赛提交不用于门槛，避免通过布尔字段泄露 OI 成绩。比赛保密与社区静默只检查当前使用域，不扩大到源公共域或其他学校。
- 域社区管理员只能治理本域内容和禁言，不授予平台密码、RBAC、全站封禁或私信管理。板块修改使用 revision；缺失和冲突分别返回 428、409。
- 社区通知与持久 SSE 定位事件在同一事务写入，提交成功后才广播定位消息。长连接每次推送和持久重放重新检查账号、成员、模块和具体通知访问权，不透传原始事件内容。关注动态使用数据库相关子查询，不把全实例关注名单载入应用。

## Alternatives considered

- 新建一套域社区 CRUD 容易使内容审核、状态转换和互动规则漂移，因此扩展既有服务的可选已授权上下文。
- 读取列表后再过滤失效引用会泄露计数、游标及摘要，因此将当前授权条件放入分页前的数据库查询。
- 广播正文或依赖 JWT 中的旧角色无法及时撤权，因此 SSE 仅发送通知 ID，并重新授权后由客户端读取详情。

## Consequences

后端域社区浏览、发帖、评论、题解、互动、收藏、动态、通知、板块与治理已有服务和 HTTP 验证。标准 community 任务在 PGlite 及专属 PostgreSQL schema 运行，覆盖跨域路径、同 slug 板块、不同域身份、成员移除、模块停用、源引用撤销、域比赛保密与 SSE 重放。

本记录签收这些后端行为；社区 Web 域页面、全局搜索索引和公共用户主页投影由相应模块继续接入。旧 NULL 归属收缩、协调发布、真实浏览器旅程与生产路由开放仍等待整体验收。
