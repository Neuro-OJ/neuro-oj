# Agent Note: 独立 WASM IO 分类分析与来源验证

Status: implemented

## Problem

v2 修补标准库后仍有 cin 成本差距，但函数名或标准库调用上下文不足以证明哪些成本
可豁免。直接排除 IO 可能误免选手回调、字符串流或算法代码，并改变现有标准成绩。

## Decision

提供独立 wasm-analyze 工具，正式 v2 运行和插桩运行分开。校验 SDK 内容，以受控
lld 链接映射、实际对象和归档成员确认最终函数体来源。分析编译关闭 LTO，保留普通
内联；每个函数追加独立 global 计数，按 v2 固定成本累计原指令和批量变量成本。

共享 IO 函数仅标候选。选手模板、回调、弱符号覆盖及内联代码保持选手来源。无法
唯一确认的成员保守标为未确认。分析超限返回部分统计，不改变原始 verdict。

固定生成基准验证两个独立进程/SDK 的计数与摘要，并单独保存分析快照。club、road
正式数据仅在本地使用，原生 CPU 对照运行在独立 Docker 中。保持 v1/v2 清单、正式
编译参数、题目预算、接口和成绩不变。

## Alternatives considered

拒绝按函数名或调用者身份免计费，因为选手能覆盖符号或实现标准流回调。拒绝全局
关闭内联，因为会改变算法成本。拒绝将插桩 raw fuel 用作正式成绩，因为它包含
分析开销。暂不实现 v3：共享解析的外部 IO 上下文和统一费率仍需要证据。

## Consequences

能够观察可信来源和 IO 候选成本，并保留独立原始成绩。分类总量不等于 Wasmtime
fuel，内联后的算法不能精确按源函数拆分。road 负解在原生对照中仍超限，插桩部分
统计由选手算法主导；不能靠排除 cin 解决。后续 v3 需要独立设计和验收。
