# Agent Note: 作业变化通知与历史读取

Status: implemented

## Problem

反馈和求助通知已有持久投递，但作业发布、补入学生、截止调整、版本策略及资源失效没有通知，学生与教师也缺少可读取的变化依据。

## Decision

发布、学生补入及生命周期变更在业务事务登记通知。不可变绑定历史首次补入作业时登记变化通知，版本／可用性投影变化同事务保存依据；重复重算不会重复通知。新生通知仅面向本人，不重新通知原名单。

任务通知面向实际接收者及当前教练、获学情／作业管理能力的助教。数据库 UNION
去重后按 50
人分批，游标、租约和唯一键保持重启及重试幂等。每位收件人投递时重新读取授权，列表和已读仍按当前关系过滤。

作业历史接口分页返回来源题号、作答版本号、策略
revision、操作者、时间与理由，不返回题面、模板、评测配置、测试数据或原始输出。源题撤销和学生离班不删除既有任务依据，错误域和教师离职仍无法读取。

## Alternatives considered

- 在评测回调中直接群发：采用持久事件，业务事实与通知共同提交。
- 每次进度重算都通知：只对新历史或实际条目变化登记，避免重复提醒。
- 通知中存入成绩或私人正文：只保存定位，点击后重新读取受控接口。

## Consequences

后端及历史准备接口已接入。SSE
长连接、邮件投递及完整通知浏览器旅程继续实施，教学生产入口仍等待完整域隔离。测试明确区分发布通知与进度事件，不能再把
outbox 第一条或单条记录当成固定契约。
