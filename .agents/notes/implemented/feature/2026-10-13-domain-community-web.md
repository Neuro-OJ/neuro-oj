# Agent Note: 域社区 Web 入口与账号通知分工

Status: implemented

## Problem

后端已有显式域社区接口，但空间导航没有社区入口，Web 社区页面仍请求旧全局接口。
用户在学校空间无法完成发帖、评论、收藏与举报；原配置及通知角标使用单一缓存键，
切换空间或账号后可能沿用之前的权限与未读数量。

## Decision

- 保留现有社区页面的内容组件，拆为共用组件和薄路由页。
  `/d/:slug/community` 下提供列表、帖子、收藏、通知、通知详情、举报详情和社区管理。
  请求使用 URL 的明确 Domain，内容链接、题解关联题和浏览器数据键保留同一使用域。
- 旧社区列表、帖子和收藏入口固定重定向 main，保留 type 搜索参数。
  `/community/notifications` 与 `/community/reports/:id` 继续承担账号通知及私信举报，
  不将 follow、ban 和私信举报记录转换为 main 内容。
- 关注与私信继续使用原账号接口。域通知的帖子、举报和比赛跳转留在当前域，
  关注目标仍指向统一用户主页。
- 配置缓存键包含 Domain 和账号；结果携带捕获的作用域，过期结果不作为当前权限。
  未读角标检查作用域，SSE URL 和连接 key 随域及账号切换。
  页内操作捕获使用域，确认框期间切域、切账号或卸载后不再提交旧操作。
- 域管理员管理本域板块、帖子和评论审核以及举报处理。
  板块编辑保留打开表单时的 revision，通过 If-Match 提交；冲突保留输入。
  域归档后的管理按钮只读，后端每次请求继续检查实际权限。
- 题解关联题使用已授权帖子 DTO 的 problem_reference，保留来源题号并生成使用域链接，
  不根据 UUID 或旧 P 号猜题目地址。题解搜索使用域搜索接口。

## Alternatives considered

复制一套学校社区页面会使后续帖子、评论和通知规则维护两份；共用内容组件能保持交互一致。
把所有旧通知及举报地址重定向 main 会丢失账号关系与私信工单，因此账号入口保留独立授权。
不引入全局可变权限缓存或出错后回退公开域的逻辑；当前域接口失败时显示不可用或错误。

## Consequences

空间社区入口由本域 community 开关决定。模块关闭时遵循现有社区后端拒绝读取的规则，
客户端不额外开启历史访问。账号通知入口不依赖 main 是否可以进入。

单元与组件回归覆盖内容路由、通知目标、缓存作用域、导航开关、迟到的未读数和确认期间切域。
生产构建与真实 Public/Mixed 浏览器旅程的结果由本批冻结后的集成验收另行记录，
组件通过不表示实际多域用户旅程已经验收。
