# Agent Note: 竞赛榜单封榜与公开/私有视图

Status: implemented

## Problem

竞赛结束前的实时排名可能通过 REST、SSE 或提交事件旁路泄露；比赛结束也不代表所有评测
已经完成，直接解封会把未结算结果误认为正式成绩。

## Decision

- 在 `contests` 增加榜单可见性、显式冻结起点和结束前冻结秒数，使用 ISO 8601 UTC 边界，
  起点包含、结束点不包含。
- 所有普通用户榜单请求统一经过 `getContestRankingView`：封榜期间按冻结起点截断提交，
  比赛结束但未发布正式快照时继续保持冻结；管理员始终得到带 `admin_live` 标识的实时榜。
- REST 与 SSE 共用同一服务函数和视图元数据；冻结期间普通 SSE 不推送提交创建事件，避免
  通过旁路推导实时变化。
- #435 正式成绩快照发布后，公开/参赛者按同一权限策略切换至不可变 `official` 视图。
  没有配置封榜的旧竞赛在结束后同样等待正式快照发布；未发布前普通用户不获得实时榜。

## Alternatives considered

- 只在前端隐藏榜单：接口仍可直接读取实时结果，不能满足安全边界。
- 在封榜开始时异步写一份快照：需要额外调度器和故障恢复；当前按时间截断提交生成
  确定性冻结视图，不受服务重启影响。
- 结束即发布正式成绩：会固化待评测或失败评测，故继续由 #435 结算门禁和管理员确认发布。

## Consequences

冻结视图无需后台定时任务且幂等，配置更新和时区边界由服务端校验；管理员实时榜可能包含
  尚未完成评测，页面与接口均明确标记。真实生产部署仍需在发布流程中配置合适的封榜时长，
  并由管理员处理待结算/申诉后发布正式快照。
