# Agent Note: 教学通知的授权 SSE 与持久邮件投递

Status: implemented

## Problem

教学通知已有持久目录和事件分页投递，但缺少浏览器实时刷新与邮件发送链路。
通知发布后成员或助教授权可能变化，不能把原始反馈、成绩或求助正文作为广播载荷，
也不能仅在创建通知时授权后直接发送邮件。

## Decision

通知创建事务同时写入现有 userChannel SSE 事件日志与邮件待发送任务。Redis 只
负责实时扇出，断线重放读取数据库；重复教学事件不重复创建通知、邮件任务或日志。
`/domains/:slug/notifications/events` 使用当前账号和明确域上下文，每条实时事件
及 Last-Event-ID 重放重新检查通知和资源授权。只返回通知、作业及域定位，客户端
收到同步提示后重新读取受授权 REST 目录。实时事件也携带持久事件 ID，撤权时
停止长连接，重连重新执行域政策。

邮件使用新增持久队列表、SKIP LOCKED、租约和退避。发送前重新读取通知授权、
当前账号邮箱验证状态及退信抑制；邮件关闭、权限撤销或未验证地址保存明确跳过
状态，临时错误仅保存错误类型并重试。正文为固定通知提示和 APP_URL 下的作业
定位，不包含私人标题、评分、答案、反馈或求助正文。system 只提供通用通知邮件
门面，不依赖 education 业务。邮件队列随既有教育 worker 启动，无额外进程内
业务计数器或去重状态。

## Alternatives considered

- 只发布 Redis 通知：连接中断或服务重启会永久丢失更新，继续使用持久 SSE 日志。
- 从事件载荷直接发送邮件或浏览器摘要：旧授权及私人正文可能泄露，发送前重新授权。
- 在请求内等待批量邮件：外部服务延迟阻塞教学事务，改为持久异步队列。
- 承诺邮件严格只发送一次：当前邮件 Provider 无外部幂等协议，崩溃发生在上游发送
  成功与本地完成记录之间时可能重复。采用可重试投递，保留数据库依据，不声称
  外部发送恰好一次。

## Consequences

实时与邮件使用相同受控定位，权限撤销不恢复私有资源。教学历史目录继续遵守当前
关系；域成员离开后不能仅凭仍保留的教学任职行看到公开域里的旧私有通知。
已送达用户邮箱的固定定位提示不能撤回，链接打开仍重新授权。未配置 APP_URL 时
邮件只给固定提示，生产部署既有配置检查继续负责正确的站点地址。

实际回归覆盖 Redis 实时通知丢失后的持久重放、错误域载荷过滤、字段裁剪、长连接
撤权及重连拒绝；邮件覆盖失败退避、租约回收、旧租约失效、已完成不重发、排队后
撤权与邮件关闭。完整 education PostgreSQL / PGlite 回归以及类型、lint、格式和
模块边界在冻结前执行。浏览器页面旅程和真实邮件服务送达属于整体升级验收。
