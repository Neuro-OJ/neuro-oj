# Agent Note: 作业发布与实际学生名单

Status: implemented

## Problem

班级需要固定题目集合、达标要求和实际目标学生的作业。题库版本策略继续变化，
因此发布依据与当前作答版本必须分别保留。发布失败、重复请求、离班和重新入班
不能产生半发布任务、重复接收者或持续读取离班后的个人练习。

## Decision

追加 Drizzle 迁移建立作业、条目、实际名单、版本沿革、当前进度、持久事件、教学
停用区间和幂等结果表。复合外键保证班级、作业、绑定、接收者同域，以及条目和
沿革的版本属于正确源题；PGlite DDL 和连接模板指纹同步。

实现草稿创建与 revision 编辑、详情、按授权分页列表、定时预约、事务发布、
截止延期、提前结束和只读归档。发布再次检查题库授权与名单，保存固定集合和
版本依据，再共同提交学生名单、事件和审计。重复发布按域、操作者、操作和键
返回原结果，读取幂等记录前重新验证权限。定时执行的业务校验失败回到草稿并
保留原因；数据库故障保留预约等待重试。

全班任务在学生加入时补入未截止作业，部分学生任务不会自动扩大名单。离班、
改变学生身份、域退出或账号注销结束计入区间，保留历史接收者；重新入班只为
未截止任务开启新的区间，离班期间练习不会回填。

## Alternatives considered

- 发布时永久冻结题面版本：与批准的动态题库策略冲突，因此保存依据而不承诺
  版本永久固定。
- 每次读取现有班级名单作为作业目标：无法解释历史学生或补题范围，因此保存
  实际接收者与加入、退出区间。
- 用 Redis 通知替代持久事件：重启会遗漏教学进度，因此在业务事务中写 outbox。

## Consequences

本记录只交付作业数据基础、发布生命周期和名单同步。公开题单展开、任务复制、
成绩重算消费者、反馈通知及 Web 作业界面仍是后续任务，未标记教学阶段完成。
生产教学路由仍等待完整域隔离验收后挂载。

教学定向测试同时验证 PostgreSQL 和 PGlite；新增用例覆盖发布幂等、错误域与
角色、草稿不可见、动态 exact 发布依据、资源失效回滚、定时失败、截止延期、
归档和新生、离班、重入名单。迁移也在保留现有题目、账号的开发库及恢复库执行。

PostgreSQL 教学测试 17 项、PGlite 教学测试 17 项通过。core 全量 DB 分片 1650 项
通过；unit 分片首次因先前定向测试将 pg_trgm 安装在 test_db，test_unit 初始化
找不到扩展而失败。在新的独立库通过标准 `test:parallel -- --shards 1` 复跑， 374
项通过。两分片合计 2024 项通过、17 项忽略；初次全量命令本身仍为失败，
不把两次调用描述为一次成功退出。完整 core 类型检查、受影响格式与 lint、Schema
parity、迁移安全、快照链、域边界、CI 覆盖和 Agent Note 校验通过。
