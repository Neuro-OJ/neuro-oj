# Agent Note: 实例域治理目录与配额占用视图

Status: implemented

## Problem

普通发现列表按可见性与成员关系裁剪，平台管理员无法用它完整治理暂停或未加入的
私有域。创建审核目录固定截断为 100 条，没有分页或申请人展示，拒绝决定也缺乏
明确目标的事务审计。域配额页只提供配置值，不能展示已占用和预留容量。

## Decision

- 新增平台限定的 `GET /admin/instance/domains`，使用既有分页 helper，支持 status
  / keyword，返回治理必需的域配置、负责人展示、稳定 ID 与 revision。
  状态修改继续复用现有显式域路径与 If-Match，不增加按列表位置操作的写入口。
- 创建审核目录支持状态筛选与分页，展示申请人用户名，注销身份只显示匿名名称。
  批准与拒绝都在业务事务中记录 `domain_creation_request` 目标及请求 ID，批准
  另外保留实际新域 ID；重复审核仍冲突，不重复写审核记录。
- 现有域 limits GET 增加 usage。成员、题库读取当前持久计数，存储读取实际对象
  归属与有效上传预约，分别提供已用及预留量。明确缺失容量计数的不变量错误，
  不因缺失计数返回零。每分钟提交频率不伪装成存储式占用。
- 治理列表只授予当前平台管理权限；普通域负责人不能读取平台目录或创建申请。
  域配额继续检查路径域、当前成员和 `domain:limits` 权限。
- 审核事务内查询当前平台权限。审计复用已有合法 action，不修改共享 Schema。

## Alternatives considered

- 平台 UI 使用普通 `/domains`：遗漏私有或暂停域，拒绝。
- 在 UI 拉取全部审核行后分页：固定截断仍会丢记录，拒绝。
- 仅批准时以新域为审计目标：拒绝时尚无域，必须明确指向创建申请。
- 以存储累计历史计数替代当前物理占用：与内容复用、预约及释放规则不一致，拒绝。
- 扩展通用治理框架或新增审计 action 迁移：现有门面与目标字段足够，不采用。

## Consequences

前端可在不获得普通成员身份的情况下治理明确目标域，并展示实际容量。
分页读取不暴露 Provider、学生提交或教学内容。界面仍需独立浏览器验收。

新增真实 createApp HTTP 回归覆盖私有暂停域治理、状态筛选、分页、权限隔离、
恢复同一域、申请批准与拒绝审计、重复审核、注销申请人展示及配额预约读取。
