# Agent Note: 授权比赛成绩补题客户端

Status: implemented

## Problem

教师需要将本班学生的授权比赛成绩用于赛后补题，而不能修改原比赛排名或凭教学身份读取受限结果。
候选必须有明确来源、成绩规则和学生／题目范围。

## Decision

班级作业管理入口新增比赛补题页面，分页单选当前使用域可访问的比赛。
入口同时要求作业管理和学情读取能力；仅有作业管理的助教不能读取候选名单。
教师显式选择已发布正式快照或获授权实时成绩，以及正式通过或最低原始百分制成绩。
通过直接采用后端正式判定，分数阈值精确转换为 ×100 整数，不从加权分推断通过。

候选由班级 contest-remediation-preview 服务返回，共用全班补题选择表单。
展示正式快照版本、每名学生未达标题号、未参赛／历史学生及无效／待更新单元的排除数量。
修改比赛、榜单来源或达标要求即移除旧候选，重新预览后才能创建。
创建保留 source.revision、preview_token 和请求幂等键，生成独立草稿，再进行预览和发布。
页面明确新任务跟随当前使用域题库策略，原比赛快照、排名和提交仍是原来的记录。

## Alternatives considered

不在前端读取并拼接全榜来生成候选，不以班级教练身份推断比赛成绩读取权限。
不修改原正式结果，也不将比赛固定版本变成新作业永久固定版本。

## Consequences

组件和 API 契约测试覆盖正式快照版本、未参赛排除数量、创建独立草稿、
榜单来源切换失效旧候选、百分制阈值转换及比赛保密错误后不展示候选。
客户端使用后端确认的课堂批量 API；实际比赛授权、快照候选及完整浏览器旅程由整体验收验证。
