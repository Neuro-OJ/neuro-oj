# Agent Note: 原提交行批注与教学文本预览

Status: implemented

## Problem

教师已能按班级权限查看学生同域提交，但缺少绑定原代码的行反馈。产物提交仅有存储定位，不能直接用存储直链作为教学预览入口。

## Decision

新增批注表及准备路由，记录班级、域、学生、原提交、文件、UTF-8 原始字节
SHA-256、行范围、作者及
revision。创建需要同时具备源码读取和反馈能力；编辑只改正文，原作者可编辑，教练及域治理人员可撤回。新提交不继承旧批注。

文本接口每次重新验证域、班级和比赛权限。学生只读本人代码及批注。学生离班后已有批注成为该班保留的反馈依据，未批注的后续个人练习不会因此开放；教师撤职后失去读取能力。作者注销保留已注销身份显示。

产物仅从该提交的学生上传 ZIP 读取，不读取题目支持包。在线预览限压缩包 64
MiB、单文本 1 MiB，复用已有 ZIP 路径、1000 条目、64 MiB 单文件、512 MiB
总解压限制，解压前筛选文本。二进制及不可解码的 UTF-8
不开放批注，接口不返回存储地址或评测原始内容。

有批注的提交禁止物理删除，返回明确
`SUBMISSION_HAS_ANNOTATIONS`，避免丢失原代码与既有反馈依据；无批注提交继续沿用既有删除与进度重算。复合外键限制源提交的域和学生。

## Alternatives considered

- 自动把批注迁移到新代码：行号容易失真，且破坏原提交依据。
- 直接返回存储下载 URL：无法逐次验证教学关系和比赛窗口。
- 复制全量源代码到每条批注：重复数据且存在两个内容依据，采用保留原提交。

## Consequences

后端准备接口支持普通代码和学生产物文本，仍随教学模块保持生产入口关闭，等待完整域隔离。Web
批注界面、通知联动和授权原产物下载属于后续接入；本记录不把这些工作标记为完成。
