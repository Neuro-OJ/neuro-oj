# Agent Note: 邮箱验证与账户注销闭环

Status: implemented

## Problem

本地注册邮箱此前不验证，自动化账号可直接提交、发帖和私信；同时用户和管理员都缺少安全的账户注销入口，不能在保留公共内容与审计链的前提下撤销登录身份。

## Decision

新增哈希存储、30 分钟有效的一次性邮箱验证令牌和 mock、阿里云、腾讯云邮件发送链路。未验证用户可登录和浏览，但提交、社区写操作与私信写操作由认证中间件统一阻止。账户注销采用软删除：用户名改为「已注销用户」，邮箱改为不可投递的唯一占位地址，清除密码、OAuth、TFA、角色和活跃封禁，保留内容、提交和审计外键。管理员注销需要二次确认并记录审计，root、管理员自己和最后一个可登录管理员受到保护。

## Alternatives considered

- 注册后禁止登录：实现直接，但会阻断用户查看站点和重新发送邮件，恢复路径较差。
- 硬删除用户与关联数据：隐私清理更彻底，但会破坏题解、讨论、提交历史和审计可追溯性。
- 在每个业务路由分别检查邮箱：粒度更细，但容易遗漏新增写接口，维护成本高。

## Consequences

历史用户迁移后默认视为已验证，新注册用户显式为未验证。公共内容通过用户表联查自动显示统一匿名身份；多个注销账户依赖仅针对活跃用户的用户名部分唯一索引。邮件服务关闭时注册仍成功，前端明确提示稍后重发。注销不可恢复，相关接口和界面均要求显式确认。全链路测试在显式 E2E 且非生产环境中取得一次性验证令牌，并通过公开验证端点消费；生产响应不暴露令牌。
