# Agent Note: 管理员离线开号与临时密码交付

Status: implemented

## Problem

公开注册依赖邮件服务，学校内网与线下比赛无法提前开设考生账号。用户表的邮箱不可为空，管理后台缺少单建、批量导入和密码重置入口。

## Decision

管理员 identity 路由提供单建、最多 500 行的原子批量导入和密码重置。账号默认分配与公开注册一致的 user 角色，也接受已有角色名称或 ID；禁止分配 root。全部行先校验后计算密码哈希，数据库唯一约束的并发冲突使整批事务回滚；角色和搜索索引任务随账号在同一事务中创建。

缺省邮箱使用带随机短码的 users.noj.invalid 地址，账号标记为已验证并强制首次改密。所有邮件入口在加载 Provider 前跳过 invalid 域名及其子域；忘记密码对占位邮箱不创建重置令牌，保持统一防枚举响应。公开注册的邮件要求和开关保持原有行为。

管理员重置复用密码哈希、强度校验及密码重置的原子会话版本更新函数，拒绝 root 与已注销用户。响应设置 no-store；明文凭据仅在操作响应和当前界面组件中短暂存在，关闭结果弹窗即清空。CSV 上传、粘贴与本地下载共享编码解析工具，不通过服务端重取密码。

审计表的 action 存在数据库白名单，因此复用 auth.register 和 auth.password_reset，detail 使用 source=admin 与 operation 标记具体操作，仅缓存账号 ID、用户名、角色和数量，不缓存密码。

## Alternatives considered

- 放宽公开注册或取消邮件要求：改变站点既有安全与运营策略，管理员入口单独满足需求。
- 让 email 可空：扩大数据库与调用方改造范围，占位保留域名满足现有非空约束。
- 导入时逐行提交：部分成功难以重试和核对，使用单个事务及逐行错误响应。
- 新增独立审计 action：需要修改数据库白名单并新增迁移，复用已有事件及 detail 满足不迁移约束。
- 保存明文密码供管理员再次下载：增加凭据泄漏面，改用一次性展示和浏览器本地导出。

## Consequences

内网部署无需邮件服务即可建号并交付初始密码。遗失初始密码只能再次重置；占位邮箱不能自助邮件找回。导入需要执行最多 500 次密码哈希，界面提供处理中反馈及较长请求超时；部署代理仍需允许请求完成。没有新增数据库迁移，也不自动加入域或班级。接口测试覆盖权限、原子性、凭据失效、占位邮箱和审计脱敏，前端测试覆盖 CSV 及一次性凭据生命周期。
