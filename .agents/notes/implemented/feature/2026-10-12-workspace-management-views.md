# Agent Note: 工作空间管理视图与邀请注册入口

Status: implemented

## Problem

工作空间后端的原始成员记录缺少组合角色，邀请目录和匿名预览尚不能支持 Web
管理流程。受邀注册如果同时自动加入默认域，会占用不相关额度，并使私有实例
出现多余空间。旧邀请还可能在签发者撤权后继续增加成员。

## Decision

成员分页批量读取角色，返回当前 / 历史状态及负责人标记；注销身份不显示旧邮箱。
加入申请限定当前域，返回人类可读名称及可批准状态，注销账号匿名展示。
邀请目录使用允许字段列表，预览通过认证路径 POST 请求体消费令牌，只返回加入
所需信息，不枚举账号。预览和接受均实时检查签发者权限，接受沿用事务域锁及名额检查。

邀请注册在账号创建事务内仅加入目标域，失败完整回滚。普通开放注册继续按默认域
政策加入。概览返回实际查看者 ID，接口禁止缓存，JWT 不增加当前域字段。

## Alternatives considered

- 将邀请令牌放在 GET 查询参数：进入请求日志和链接摘要，采用 POST 请求体。
- 使用浏览器 Session Cookie
  判断权限：只能用于显示，返回实际身份并每次服务端授权。
- 撤权时删除全部邀请：保留治理记录，通过消费时检查立即生效。
- 邀请注册同时加入 main：会被默认域额度阻断且破坏单空间入口，按邀请目标加入。

## Consequences

工作空间标准测试 23 项通过，身份标准回归 312 项通过、26 项跳过；core 类型检查
通过。新增测试覆盖错误域、注销显示、邀请字段、签发者撤权、管理员开户政策及
默认域名额为零时的邀请注册事务。跳过项及 Web / 浏览器验收不计为通过。
其他业务的资源归属和教学 / 比赛隔离仍按升级清单后续实施。
