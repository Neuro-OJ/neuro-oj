# Agent Note: LLM 持久结算、测量基线与实时实例上限

Status: implemented

## Problem

旧链路先预占 Redis、再调用上游、结算 Redis，最后写审计。Redis 回复丢失或数据库
提交失败后缺少同一笔调用的重放依据，无法判断已经扣过的额度；服务重启也无法继续
待结算。实例降低对 Domain 的上限后，旧配额和已签发 token 仍能按旧限制执行。

## Decision

独立 Gateway 新增调用账本，迁移由 `db:generate` 使用时间戳前缀追加。调用 ID 对应
预占快照，已知实际用量与待结算快照同事务持久化，快照包含原计数键和绝对失效时刻。
Redis Lua 通过调用 ID 幂等标记保存结果，结算回复丢失或数据库回滚后重放同一笔，
不再次扣 delta。后台每五秒从数据库以 SKIP LOCKED
领取，多个消费者并行且重启继续。

受理使用数据库共享 advisory 锁覆盖预占计划、Redis 受理与状态确认；结算使用共享
事务锁，实例对账使用排他锁。对账按持久预占及实际差额重建活动计数和确认标记，
避免与新调用互相覆盖。新受理检查 Redis 进程身份及共享 ready 标记，整库丢失或
重启后的旧快照先重建。上游网络失败保留预估占用及 unknown 事实；退出进程留下的
预占三分钟后明确标记未知，治理核对，不假定未产生上游费用。

旧窗口没有预占快照时，对账先拒绝覆盖。实例治理可扫描实际存在的 Redis 计数及
TTL，扣除新账本部分，建立本月测量基线，旧平台域内键映射 main。基线 Lua 同步
登记测量标记；DB 提交失败后复用测量，不重复相加。没有旧计数或新调用尚未核实，
返回明确状态供治理处理；不从 usage 猜出已经丢失的 Redis 数值。

Domain 管理保存配额时按持久实例上限验证。普通域管理员的域日/月总额度只能降低，
比较该窗口全部有效约束而非请求 ID，每个维度取最严格有限值，保留历史记录。
平台管理员可在实例上限内提高总量，用户和题目配额仍服从总量且不受单调降低限制。
Gateway 每次调用前以服务凭据读取 core 的内部只读政策接口，日/月 Domain
配额与当前实例上限取较小值，不缓存。 默认上限全
null，没有引入新数字限额；政策无法读取时停止新调用，尚未扣预算或
触碰上游。Domain 用量返回明确 metadata 白名单，避免把 evaluator 正文和任意详情
经计费管理接口返回给没有源数据或比赛组织权限的使用域管理员。

## Alternatives considered

- 只把额度上限冻结在 token：平台降低后仍执行旧值，采用每次读取当前政策。
- 失败后再次计算并扣差额：无法识别已经执行的 Lua，采用持久调用 ID 和幂等标记。
- 从历史审计猜预占并重置计数：审计没有原估算依据，采用实际 Redis 测量基线。
- 重新调用网络失败的上游：无法证明上游未处理，保留未知事实供治理核对。

## Consequences

standalone 标准任务启用独立 PostgreSQL 和随机前缀真实 Redis 后 110 通过、0
失败、 1 个既有测试跳过；验证多消费者、回复丢失后事务回滚、重启补算、Redis
数据丢失 重建、未知预占、实时降低上限、缺失基线拒绝、基线提交失败重放不翻倍。
core gateway PostgreSQL/PGlite 各 29 通过，真实权限表验证上限约束和 Domain 用量
白名单；模块源码及全部测试类型检查、格式、lint、导出 JSDoc 门禁通过。

新 HTTP 请求拥有新调用 ID，内部结算的幂等性不承诺外部 Provider 对重复 POST
去重。 预算估算与已知实际用量如实保存，上游账单核对、未知调用治理及完整
Judge/浏览器 旅程仍需相应验收。独立 Gateway 写入与 core
操作审计仍不构成分布式事务。
