# Agent Note: noj-cli 人体工程学修复（退出码分层与只读 --help）

Status: implemented

## Problem

noj-cli 存在一批「能用但会伤到人」的缺陷，其中两条违背 CLI 最基本的约定：

- **`--help` 在子命令上失效**：`deploy --help` 报「未找到 noj-deploy.json」、
  `maintain --help` 报「需要子命令」，均以失败退出。
- **`--help` 触发写操作**：`deploy init --help` 直接进入交互向导，
  在读不到输入时无限循环「输入无效，请重新选择」——用户只想读帮助，却启动了写配置流程。

其余：异常直穿（`doctor --port abc` 打印完整栈帧与源码路径，既是体验问题也是信息泄露）、
缺值报错无意义（`非法端口: undefined`）、`--dir` 有 3 套解析且行为不一致
（一半支持 `--dir=` 且缺值报错，一半静默取 `undefined`）、退出码只有 0/1、
`--version` 不可用、拼写错误无建议、非 TTY 下空转。

根因有三条，且互相叠加：

1. 顶层 `run()` 只特判了顶层 `--help`，子命令走手写 `switch`、无 help 分支，
   且 `run()` 直接 `return await dispatchCommand(...)`，没有全局异常兜底；
2. help 文本与实现分离（手写字符串数组），必然漂移——它声称 `backup` 支持 `schedule`，
   而 `maintain backup` 并未实现；
3. `--dir` 解析在 4 处各自手写，行为不一致。

## Decision

### 1. 退出码分层，作为可脚本化的稳定契约

| 码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 运行失败（命令已执行但未成功） |
| `2` | 用法错误（参数非法、缺少必需参数、未知命令） |

新增 `UsageError` 类型承载「用法错误」。这解决了「调用方无法区分参数错与运行失败」——
参数错可以立即重试修正，运行失败需要看日志。既有断言中依赖 `=== 1` 的按新语义拆成 `1`/`2`。

### 2. `--help` 优先于一切副作用，且由 CLI 自己回答

每个子命令在进入任何副作用之前先判定 `--help`/`-h`，打印用法后返回 `0`。
转发生成脚本的命令（`install`/`check` 等）的 help **不转发给 bash**——
否则用户看到的是 `deploy.sh install` 的文案，而非 noj-cli 的用法。

### 3. help 文本成为唯一事实源

新增 `help.ts`，按**模式分区**声明命令清单与用法（生产模式 / JSON 编排模式 / 全局选项），
并集中声明退出码语义。命令清单可被测试逐项断言，避免再次漂移。

### 4. 全局异常兜底：单行可读 + 默认不暴露内部实现

`run()` 统一 `try/catch`：错误转为 `noj-cli <cmd>: <message>` 单行输出，
**不打印栈帧与源码路径**；`--debug`（或 `NOJ_CLI_DEBUG=1`）例外。
生产路径原先自己的 try/catch 被移除，改为抛出已分类错误——
消除「同一 CLI 内两套错误处理」这一根因。

### 5. `--dir` 统一解析

抽出 `parseDirArg()`：支持 `--dir X` 与 `--dir=X`，缺值/后跟选项时抛 `UsageError`。
四处处调用点（init/deploy/maintain/backup）统一。**关键改进是缺值不再静默取 `undefined`**。

### 6. 非 TTY 显式拒绝而非空转

判定抽成纯函数 `nonInteractiveAdvice(isTty, hasMode)`，可被单测断言。
非 TTY 时直接报错并给出显式传参示例，而不是进入必然失败的交互循环。

### 7. 可发现性

`--version`/`-v` 可用；未知命令用 Levenshtein 距离给建议（阈值按输入长度自适应，
避免短输入被误映射）。

## Alternatives considered

- **迁移到 Cliffy 框架**（自动 help/子命令/补全）：`parseProductionArgs` 刻意的
  「只消费 `--dir`、其余原样转发给生产脚本」透传语义与 Cliffy 的解析模型冲突——
  Cliffy 会尝试解析所有参数并在遇到未知选项时报错。保留手写解析，只补 help/错误/退出码。
- **保留 0/1 退出码**：调用方无法区分「我参数写错了」与「命令跑了但失败了」，
  这是脚本化场景的实际痛点。分层是轻度破坏性变更，用测试与文档吸收。
- **`--help` 转发给底层脚本**：用户看到的是另一套 CLI 的用法，失去一致性；
  且底层脚本的 help 未必与 noj-cli 的参数透传语义一致。
- **非 TTY 时自动取默认值继续**：会静默生成一份用户并未确认的配置，
  比报错更危险。选择显式拒绝 + 给出确切的补齐方式。
- **`--dir` 缺值退化为当前目录**：这正是要修的缺陷（静默失效）。改为显式报错。

## Consequences

- 退出码 `0`/`1`/`2` 成为有测试覆盖、写入文档的稳定契约。
- 所有命令的 `--help` 都是只读的，`deploy init --help` 不再有任何副作用。
- 错误输出默认为单行，不再泄露栈帧与源码路径；排查时用 `--debug`。
- help 文本与命令清单同处一处，新增命令时更不易漂移。
- 非 TTY 环境（CI、管道）下 `deploy init` 明确报错并给出显式传参方式，不再空转。
- 这份改动是 #514/#515/#516/#518 的基础：它们都要在稳定的 help/退出码/参数解析之上叠加新语法。

## 评审修正（2026-09-18，PR #526）

### Problem

评审 P2 指出：`--debug` 被 help 声明为**全局选项**，但 `run()` 直接取
`argv[0]` 当命令，`noj-cli --debug status` 因此落入未知命令分支返回 2，
命令名前使用无效；而命令后的 `--debug` 在被透传到底层脚本时同样不可用。

### Decision

在 `run()` 解析命令**之前**统一剥离全局旗标（新增 `extractGlobalFlags`），
`--debug` 两个位置都可用且不会进入子命令参数；兜底分支改用剥离后的布尔值
而非再扫描原始 argv。回归测试断言：前置 `--debug` 必须打印栈帧、不得被当作
未知命令，且命令语义（如 `doctor --port abc` 的用法错误 2）不受影响。

### Consequences

- 全局选项在命令前后均生效，help 的声明与行为一致。
- 后续新增全局选项时有唯一剥离点，不必在每个子命令里各自处理。
