# Agent Note: 教师学生提交读取与历史授权

Status: implemented

## Problem

教练和助教的源码能力需要落实到查询与详情，而不能借用平台管理员权限读取。
学生离班后，教师不能继续查看新练习；比赛保密和共享撤销还需要分别处理。

## Decision

增加班级学生提交准备 API，普通提交与客观题按同域归属统一分页。教练、域治理
人员及拥有固定 submissions:read 能力的助教可读；学情能力不能代替源码能力。
每次重新检查当前域与班级关系，撤职立即失权。

当前有效学生关系允许读取全部同域练习。离班后只读取已经发布作业的题目及
计入时间区间中的原提交，排除不计入的发布前练习和后续个人提交。班级归档
也限制后续提交读取。源题撤销不删除已授权的学生原代码或原答案。

进行中比赛仅向具有实际比赛管理能力的人员开放此教学读取；教练不能自动越过
比赛保密。赛后按教学授权恢复读取。列表和计数在分页前执行全部关系过滤，
避免隐藏记录出现在计数里。

DTO 只返回明确的提交摘要、原代码／答案及正式判定元数据，不返回题面、原始 评测
output/details、标准答案或存储地址。产物只返回已有产物标记，不自行 展开
ZIP。平台治理读取留下域目标与资源定位审计，不记录代码及成绩内容。

## Alternatives considered

- 将教练伪装成平台管理员：会扩大跨域及比赛权限，因此独立检查教学关系。
- 离班后删除全部读取关系：会丢失作业依据，因此按原接收区间保留历史。
- 返回整行数据库记录后再删除敏感键：容易漏字段，因此只选取所需字段。

## Consequences

不增加数据库字段，复用 Domain、班级能力、作业接收区间和比赛管理能力。 准备 API
随教学路由等待全入口隔离验收。产物下载、子任务详情、行批注和 教师 Web
另行实现；本记录不将这些工作标为完成。

验证：education 在 PostgreSQL 与 PGlite 各 52 项通过，包含真实 HTTP 父路由
认证、跨域拒绝、助教能力、教练交接与撤职、学生离班历史、比赛组织角色变化、
共享撤销后原代码读取，以及含隐藏数据的正式尝试不会返回原始评测内容。 完整 core
类型、受影响格式 / lint、模块边界、CI 路径及文件规模检查通过。 PGlite
首轮暴露查询结果封套差异，改用仓库现有 unwrapRows 后两种数据库均复跑通过。
