# Agent Note: 实例 LLM 上限政策读取

Status: implemented

## Problem

使用域独立管理 LLM 配额后，还需要实例上限约束，且平台降低上限应立即影响后续调用。
旧管理端直接请求配额列表没有携带使用域或实例治理上下文。

## Decision

在现有设置注册表增加日/月 LLM 配额上限完整对象，缺省各项 null，不凭空施加新数值限制。
采用 Gateway 现有调用、token、费用单位，写入时验证完整字段及非负安全整数。
新增服务凭据保护的内部只读 API，直接读取当前持久上限并禁止缓存。
内部凭据验证独立于用户会话，不允许域成员或域管理员替代服务凭据。
开发、生产及 E2E compose 为 Gateway 配置 core 内部地址。

旧平台管理端复用公开 Gateway 门面，分别查询实例级与默认域配额，不再自行构造无域请求。

## Alternatives considered

没有把上限冻结进评测 token，因为排队后降低上限仍应在后续调用生效。
没有让 Gateway 直接读取 core 拥有的系统设置表，两服务通过可信内部接口协作。

## Consequences

system 标准测试 157 项通过，0 失败、1 项环境专属测试跳过。
新增回归覆盖无凭据和错误凭据拒绝、最新 DB 政策即时读取、非法对象拒绝及 no-store。
Gateway 调用前检查、额度组合及持久对账由 Gateway 实现批次另行验证，不由本记录代替签收。
