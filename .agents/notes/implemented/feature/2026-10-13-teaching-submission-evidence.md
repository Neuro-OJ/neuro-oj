# Agent Note: 教学单元提交依据与正式评测沿革

Status: implemented

## Problem

矩阵单元只显示一份来源提交，教师无法沿此单元查看其他候选、重测变化或 适用的 OI
子任务。学生训练详情也只有当前汇总，不能解释旧高分如何变成
当前低分，或者平台重测失败为何没有覆盖已有正式成绩。

## Decision

新增公开教学读取门面和两个带域 API。学生×作业条目的提交按 25 条分页，
校验真实接收者、条目源题、发布时间、按时／补做范围、接收者计入区间、
归档和教学停用时间。沿用当前班级源码能力和比赛授权关系，学生或仅获学情
能力的助教不能借此读取同学提交。

候选标记直接读取 submission_version_results 指向的正式尝试与使用域当前
版本策略，不新增另一套成绩选择算法。进行中比赛即使组织者能查管理数据，
也不自动计入作业候选。列表只传元数据，不读取原源码、标准答案或原始输出。

原提交的评测尝试独立分页，展示尝试顺序、版本、重测来源、成绩、当前正式
指针和策略匹配。平台错误不冒充正式零分。OI 明细仅在真实 OI 版本中使用 submission
公开的 projectOiDetails 白名单，客观题与 AI 不伪造 OI 明细。
源授权撤销后仍保留历史分数，停止返回测试点和子任务数据。

矩阵教师侧栏显式加载此单元的提交列表，选择后展示正式沿革和原提交批注。
StudentTraining 复用沿革组件，客观题仅展示原答案和总分，无标准答案或逐题
正确性。账号、使用域、学生、条目、统计范围及分页均进入读取缓存键。

## Alternatives considered

- 使用全班学生训练列表替代单元详情：无法限定此任务的接收和计入时间窗。
- 用评测完成顺序或最高分推导正式沿革：会误解降分重测及平台失败。
- 直接把 evaluator details 送给前端：会泄露测试数据、原始输出和标准答案。
- 为每个矩阵单元自动请求历史：制造大量请求；只在打开单元并选择提交后读取。

## Consequences

标准 education PostgreSQL 124/0（1 既有忽略）、PGlite 123/0（2 既有忽略），
两轮迁移与种子 8/0；新增五项测试覆盖角色、错误路径／学生／条目、计入时间、
离班、exact 策略、停用、重测降分、平台失败、源撤销、客观题、分页和真实 Hono
比赛保密及赛后恢复。没有新增忽略。

UI deno task test 266/0；两相关组件文件 5/0，验证选择提交才加载沿革、原批注
定位、平台错误文案及 OI 子任务和测试点元数据。core 完整类型与边界检查、 UI
工具类型及 Nuxt/vue-tsc 类型检查、受影响文件格式和 lint 通过。

本批不新增 Schema、不构建或重启运行栈。浏览器与真实 Judge 链路验收仍由
协调端执行，不把组件测试或数据库夹具等同于浏览器旅程。
