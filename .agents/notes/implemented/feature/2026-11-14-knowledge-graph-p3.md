# Agent Note: 知识图谱 P3 掌握度、推荐与覆盖度

Status: implemented

## Problem

P2 给了每个知识点从易到难的阶梯，但学习者仍不知道「自己掌握到哪、下一步学哪个
知识点、卡住是因为缺了哪个前置」；管理员也看不出题库在哪些知识点上题量不足或
缺难题。P3 面向没有老师带、借助 AI 自学的学习者补上这一层。

## Decision

- 物化表 `user_knowledge_mastery`（主键 user × node），配置
  `knowledge_mastery_min_solved`（K，默认 3）。规则：任一题达标为学习中；达标数
  ≥ K 且至少一道达标题位于节点难度上三分之一为已掌握；题量 < K 时需全部达标。
  成绩口径复用 P2 的「达标」，进行中比赛不计。
- 增量：有效成绩物化写入点在同一事务经 `modules/runtime` 出口登记
  `knowledge.mastery`（按用户去重，重算该用户全部相关节点），旧模块不 import
  feature；比赛结束后由每小时周期任务（advisory 锁互斥）补算相关用户。
- 推荐只推前沿节点（前置均已掌握、自身未掌握、本域有题），带结构化理由
  `{ code, params }`，前端拼文案；多次未达标且有未掌握前置时给出根因提示。
  另有节点根因诊断 API 与管理员覆盖度面板（单条聚合 SQL）。
- 覆盖度的「难度断层」按校准难度绝对值判断（题量已足但没有困难档题），不用节点内
  相对上三分之一——相对口径下任何一组题都有「最难的几道」，断层永远判不出来。
- 前端：域内「我的学习」页（推荐 + 按领域掌握度列表）、节点页掌握状态与根因
  提示、管理后台覆盖度面板。不做图谱可视化（用户暂缓）。

## Alternatives considered

- 按 user × node 去重任务：一次提交可能影响多个节点，且重算单用户全部节点成本
  很低，按用户去重更简单。
- 实时在请求中计算掌握度：每次打开页面都要扫用户全部成绩，改为物化 + 增量。
- 前置作为硬锁：会让自学者被卡住，保持软约束，只在推荐与诊断中体现。

## Consequences

- 一次提交会重算该用户所有相关节点；用户成绩规模很大时需改为只重算受影响节点。
- 保护结束补算只看过去 24h 内结束的比赛；周期任务停摆超过 24h 时需手动重算。
- 讲解效果对比（4.5）与摸底诊断、间隔复习、知识点 AI 助教（4.7）留待后续。
