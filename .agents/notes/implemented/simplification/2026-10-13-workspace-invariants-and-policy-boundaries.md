# Agent Note: 工作空间不变量与政策验证边界简化

Status: implemented

## Problem

工作空间升级审查发现四处不必要的行为：缺失配额记录被解释为不限额；可信数据库角色
再次进行 HTTP 输入式验证；实例资源政策解析错误被重复包装；普通授权读取依赖完整
导航配置。这些分支会掩盖数据问题、丢失诊断依据，或让首页配置错误阻断正常题库使用。

本次实施审查清单的 Q1、Q3、Q4、Q5。班级授权复用 Q2 与比赛答案可见性 S1 由其他
独立批次处理，本记录不将它们标记为完成。

## Decision

- 每个正式创建或初始化的 Domain 都必须拥有配额记录。读取缺失记录返回
  `DOMAIN_LIMITS_MISSING`，不自动补行、不返回宽松额度。记录中的显式 null
  继续表示该维度不限额，仍与实例上限组合。
- `domainPermissions()` 只映射可信内置角色。生产调用来自具有角色 CHECK
  约束的数据库记录；`setMemberRoles()` 保留对外部输入的角色校验。
- 资源政策的数据库 JSON 解码和结构验证都在 `resourcePolicy()` 边界内完成，
  只转换一次 `ServiceUnavailableError`，保留原始 `cause`。日志仅记录异常类型，
  不输出配置原文或把原始解析信息放入 HTTP 响应。
- `loadWorkspace()` 只校验当前进入域所需的 access 政策；加入入口另校验
  join_policy；模块执行入口验证目标开关与必要依赖。普通读取不因 homepage
  或无关模块字段异常而失败。配置更新继续完整验证导航、模块与访问字段。
- 不增加跳过授权开关、恢复状态机、进程缓存或新的数据库 Schema。

## Alternatives considered

- 为缺失配额行新增自动恢复：会掩盖初始化或数据破坏，拒绝。
- 删除所有运行时验证：access、加入政策及模块开关是授权相关配置，仍须在使用边界
  拒绝无效值，拒绝此方案。
- 保持每次读取完整配置验证：让无关导航错误阻断题库与提交，继续扩大耦合，不采用。
- 将原配置或 JSON 解析错误原文写入日志：不需要这些内容即可关联故障类型，保留
  cause 供内部诊断即可。

## Consequences

内部可信角色映射变为纯函数，缺失配额成为明确故障，配置验证与实际操作的依赖范围
保持一致。完整配置写入、实时成员授权、实例额度与模块禁用政策不变。

新增回归覆盖显式 null、缺失配额不放宽、不自动补行、单次异常包装、导航错误下的
授权读取、无效访问及加入政策、目标模块依赖、外部非法角色和完整写入校验。

验证通过：标准 workspace PGlite 测试 39 passed / 0 failed / 8 ignored；独立
PostgreSQL schema `test_workspace_quality_recovery_final` 测试 47 passed / 0
failed。 workspace 门面及新回归类型检查通过，6 个修改源文件的格式及 lint 通过。
PGlite 忽略项为需要真实 PostgreSQL 的既有并发测试；它们在 PostgreSQL 本轮执行。
本批次没有浏览器验收，不代表整项产品升级已完成。
