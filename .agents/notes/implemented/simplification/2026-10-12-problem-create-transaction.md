# Agent Note: 题目初始内容原子创建

Status: implemented

## Problem

题目创建先插入题目，再单独保存初始草稿，失败时手动删除题目。标签也在独立事务
同步并重复校验。域编号和绑定需要跟随创建一起提交，这种分段写入会增加补救逻辑。

## Decision

题目、初始草稿和标签使用同一事务。初始草稿直接由插入返回的题目行派生，沿用
既有草稿服务的 executor；标签同步增加 executor，事务内只校验一次。任何失败
由数据库回滚，不再手动删除刚创建的题目。支持包登记与搜索事件沿用既有流程。

新增数据库错误测试：临时约束拒绝初始草稿写入，确认之前插入的题目行不存在，
随后移除测试约束。真实 PostgreSQL catalog 测试 343 项通过，另有 8 项静态测试
通过；格式及受影响文件 lint 通过。该测试只操作独立测试数据库。

## Alternatives considered

保留分段写入并增加更多补偿会扩大中间状态和失败分支。另建一套域题目创建逻辑
会重复运行配置校验及版本草稿流程。复用原服务的事务参数更直接。

## Consequences

后续域编号、配额及本域绑定可以加入这一个创建事务。当前仍保留旧题号分配与 P/U
分类，尚未完成域内唯一编号、资源全链路隔离及支持包存储原子登记。
