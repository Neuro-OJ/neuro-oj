# Agent Note: catalog 与 objective 执行归属非空约束夹具

Status: implemented

## Problem

执行记录的使用域和题库绑定已收紧为非空，部分 catalog 与 objective 测试仍直接
插入缺归属提交或自测。保留这些旧夹具会让统计、一次交卷、历史保留及标签门控
测试提前失败，无法验证其原本的业务条件。

## Decision

原始提交与自测夹具在插入前取得真实题库绑定，并显式写入使用域及绑定。默认域
源题复用既有绑定 helper，跨域统计场景单独建立学校域 shared 绑定并按使用域
查询，不将源域身份当作学校执行身份。题库绑定增加后，测试清理使用现有显式 删除
helper，先释放执行记录再清理题目，不放宽引用守卫。

公开统计与算法标签通过门控的源题夹具显式建立已发布基线，真实绑定读取路径
继续检查资源可用性，不沿用旧空归属绕过发布检查的行为。提交本身保留原历史
未知版本和正式判定投影，源题已发布不等于伪造历史提交版本。

未知旧版本提交继续保持原版本未知语义；域身份补齐不伪造提交时版本、评测版本
或答案。一次交卷唯一约束的正负两次插入共用合法归属，负向用例继续命中目标
唯一约束。本人跨域历史夹具保留两个账号及现有可见性断言。

本批只修改 catalog 和 objective 内九份测试及本记录，不修改生产、共享 helper、
Schema、DDL 或迁移，也不增加全局默认值或测试写入拦截器。

## Alternatives considered

- 给执行列默认 main 或自动补绑定：会掩盖错误使用域，尤其是学校引用公共题。
- 放宽非空和复合外键：普通业务测试不再代表当前数据库约束。
- 用最新版本替代历史未知版本：改变保留历史的测试含义。
- 给统计夹具使用源域 binding：使跨域排除测试不符合真实使用域关联。

## Consequences

普通夹具满足当前执行身份约束，原统计、权限、版本和历史保留断言继续有效。
验证分别使用独立 PostgreSQL schema 和 PGlite 的标准 catalog/objective 模块入口，
隔离 Redis 不影响开发数据及真实 E2E 运行栈。

首轮终态自测夹具揭示删除绑定早于清理自测的真实外键失败，协调 agent 先调整
通过活动评测和历史守卫后的清理顺序，再执行本批最终回归，没有修改测试预期。
最终标准 catalog 在 PostgreSQL/PGlite 均为 366 通过、0 失败；objective 两库均为
66 通过、0 失败，均无忽略。四轮迁移及种子各 8 通过、0 失败。两模块类型检查、
受影响文件格式及 lint、Agent Note 格式检查通过。
