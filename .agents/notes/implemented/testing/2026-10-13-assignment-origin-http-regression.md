# Agent Note: 作业入口来源的真实 HTTP 受理回归

Status: implemented

## Problem

教学授权门面的服务测试不能证明 JSON 路由、产物流式解析、受理事务和读取 DTO
都携带同一来源。客户端的可选作业来源还不能成为限制多作业自动计入或泄露比赛成绩的依据。

## Decision

`submission/tests/routes/assignment-origin.test.ts` 使用真实 `createApp` 和
`Request`，通过教学 HTTP API
建班、加入学生并发布作业。账号只有数据库中的实际域角色，JWT
不虚构平台治理权限。题库执行夹具建立真实来源域、共享授权和目标域题目绑定，队列使用既有
RESP 假服务，正式结果通过既有评测落库门面写入。

六项回归覆盖 AI 代码、OI、客观题、自测和流式产物的来源持久化与授权读取。JSON 从
body 提供配对 ID，产物从 query 提供配对 ID并经过真实 multipart
文件流和本地存储流程。错误域、另一份同题作业的真实条目、缺少配对字段和不在学生接收者名单的域负责人均不能留下提交记录。

自测即使获得满分也不计入正式教学进度。正式提交即使只记录第一份作业入口，仍计入两份同域作业；未带来源的普通练习也自动计入。客观题共享撤销后保留本人历史的来源
ID，同时题面访问被拒绝。

OI 比赛与作业来源可以同时保存在同一提交。真实域详情 API 仍返回 `hidden`
和中性受理状态，分数、判定、有效标记、评测尝试与详情均不返回；进行中比赛提交也不进入作业进度。

## Alternatives considered

- 只调用提交服务：不能证明客户端字段通过 HTTP
  边界解析，故调用根应用组合后的路由。
- 修改共享 helper
  或原有测试夹具：会覆盖其他并行整改范围，故只引用既有公开工具，在新增文件内建立教学部分。
- 对私有域负责人签发平台管理员
  JWT：会改变实际授权意义，故所有测试身份使用普通账号凭据和真实域关系。
- 禁止比赛与作业来源共存：不符合确认规则，也不能代替结果裁剪，故验证共存后的可见性。
- 把自测当成真实 Judge
  沙箱验收：此处验证受理与持久化，队列响应由既有假服务提供；真实沙箱仍由 Judge
  与跨模块 E2E 门禁验收。

## Consequences

测试使用标准
`deno task test:domain submission --filter='作业来源HTTP'`。标准入口先完整执行迁移与种子，再筛选业务测试；过滤仍加载其他模块的顶层初始化，因此旧夹具初始化错误必须如实记录并由其负责范围修复。

PostgreSQL 回归使用独立测试 schema，PGlite 使用内存数据库，Redis 测试编号与其他
agent 协调。测试不写开发或运行中的 E2E
服务库，不将授权读取的来源定位误称为作业内容授权。
