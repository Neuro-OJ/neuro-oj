# Agent Note: 班级 CSV、矩阵导出、交接撤职与补题跟进浏览器验收

Status: implemented

## Problem

已有教学旅程验证单人邀请、反馈、求助、补题发布和归档，但不能证明教师实际 使用
CSV 导入、下载矩阵、交接后结束旧任职，以及在学生完成新补题后继续跟进。
域负责人会拥有班级治理能力，用该角色验证教师撤职会掩盖权限边界。

## Decision

新增独立 `workspace-classroom-matrix.test.ts` 及 fixture helper，在新 MAIN
协调栈 core 0117、正式 UI 和独立数据库执行标准 Browser 门禁。API 只准备先已
注册且已入域的普通账号、教育域、原始班级与作业；CSV、身份调整、反馈、矩阵
筛选及下载、离班、补题、交接和结束任职使用实际 Web 控件。

六段旅程形成以下证据：

- 教师 CSV 操作前已有 40 个注册并验证的普通账号。教师与接任者仅持 Domain
  educator 角色，助教为基础成员，无平台或 Domain owner/admin 权限。
- 教师上传 42 行 CSV：40 个已有账号、一个重复行和一个无效邮箱行。实际逐行
  预览显示 40 可加入、2 错误、0 邀请；执行后 40 名学生及原教练共 41 份唯一
  班级关系。真实下载结果 CSV 包含全部账号和重复错误，没有账号注册或邀请链接。
- 实际任命接任教练；助教六能力全部勾选后，重新保存为“查看学情＋撰写反馈”。
  助教实际读取矩阵、写反馈，但原客观题答案详情请求为
  `403 CLASSROOM_PERMISSION_DENIED`，页面不提供补题管理入口。
- 学生通过 Web 在原作业交卷取得零分。教师按用户名和未达标筛选，实际下载
  一名学生的 CSV；切到补做范围下载文件名对应 current。移除另一名学生后，
  历史名单和历史 CSV 只包含该学生。390px 视口通过学生卡片打开历史单元详情。
- 教师在全班候选中只选择一名学生，实际创建、预览并发布新补题。学生通过新
  作业入口交卷获得 100 分；教师重新导航到新作业，看到一人达标，来源指针为
  这次新提交。原零分提交的成绩仍为零，不改写历史。客观题由真实 Core 正式判定，
  本场景不宣称新增 Judge 代码评测。
- 实际主教练交接后，旧教练仍保留 coach 任职，`manages_domain=false`。接任者
  通过成员页面移除旧教练与助教，双方重新请求矩阵均为 404，重新导航没有矩阵
  或反馈输入。接任者重新读取新补题达标进度和原作业既有助教反馈，历史保留。

同步修正四份文档：交接本身不移除旧教练；域模型别名、配置版本冲突与 Provider
RPM/TPM；预测／界面题和配套 Judge/SDK 升级；工程权限矩阵按接续 main 的 0116/0117
描述域别名复合主键及 pending 部分唯一索引。历史 0137–0139 编号只作
实施沿革解释，没有改动迁移或 Schema。

## Alternatives considered

- 使用 Domain owner 测试离职：负责人仍可治理班级，不能证明当前任职失效。
- API 执行 CSV 或直接生成导出文本：遗漏上传、预览、错误行、实际浏览器下载。
- 只确认补题已经发布：不证明学生完成后的新任务进度和教师重新读取。
- 给每个配置 PATCH 增加通用幂等框架：批准计划只要求发布、复制、批量邀请和
  批量任务的幂等；本批复用这些真实操作既有 revision 与幂等键。

review，四个浏览器会话已关闭。本项补充具体课堂 Web 证据，不代替完整
