# Agent Note: 组件测试使用线程池避免退出失败

Status: implemented

## Problem

在本地 Deno 2.9.7、Vitest 2.1.9 环境，标准组件测试的 110 项断言均通过，但 默认
fork 池在输出汇总后抛 BrokenPipe，命令退出码为 1。仅报告断言数量会误称
整个验证命令通过，阻断可重复的审查证据。

## Decision

Vitest 配置显式使用 threads 池，保留 `deno task test:components` 标准入口和
全部测试。对比运行同一套 22 个测试文件，线程池 110 项通过且退出码为 0，
原默认池断言全通过但退出码为 1。对比包含工作区正在实现的空间组件，后续新增
切换期间操作保护测试后，标准任务 112 项通过且退出码为 0。没有忽略错误、
过滤退出码或减少测试范围。

## Alternatives considered

- 将非零退出码当作成功：可能掩盖真正的运行器错误，拒绝采用。
- 改用 Node 启动 Vitest：当前线程池能解决本地失败，保留既有 Deno 测试入口。
- 只测试新增组件：不能验证既有组件回归，保留全部文件。

## Consequences

本地组件测试可正常完成，CI 仍使用同一任务。Vue 存量测试中的未注册组件和
生命周期警告保持可见，不被线程池隐藏。该对比是本地运行证据，PR CI 和
实际浏览器交互仍需分别验收。
