# Agent Note: 客观提交夹具显式建立本域题库绑定

Status: implemented

## Problem

默认域执行门面已要求合法的 owned 绑定，客观提交与客观版本提交两个测试文件仍
直接插入源题后只发布卷面版本。发布内容不能代替题库归属初始化。完整 core 回归
暴露 11 项提交用例因缺绑定返回 404；旧独立模块通过记录早于执行门面收紧，不能
证明当前夹具完整。

## Decision

两个文件的 makePaper 在源题创建后立即调用既有 bindPublishedProblemForTest，
同文件的编程题拒绝夹具也显式建立本域绑定。helper 使用源题实际 Domain、展示
范围和策略，测试不依赖其他文件先发布题库或回填数据。

提交模式、答案和分数预期、比赛保密及权限拒绝断言均不改变。本批不修改生产
服务、Schema 或共享 helper。

## Alternatives considered

- 在生产提交门面补建绑定：错误初始化会被静默掩盖，削弱使用域身份约束。
- 在提交前逐项补绑定：重复相同夹具步骤，后续新增用例容易遗漏。
- 依赖其他测试文件的回填：完整回归的导入次序和分片会改变结果。

## Consequences

客观题夹具在创建时已经具有源题与使用域的真实关联，后续卷面发布只处理版本。 独立
PostgreSQL 和 PGlite 使用标准 objective 模块入口复验；格式、lint 和类型
检查覆盖两个受影响文件。

最新复验结果：PostgreSQL 与 PGlite 均为 66 通过、0 失败、无忽略；每轮初始化
迁移和种子另有 8 通过、0 失败。完整 core 再验由协调 agent 使用冻结快照执行。
