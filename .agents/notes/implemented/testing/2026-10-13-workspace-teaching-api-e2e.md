# Agent Note: 多工作空间教学真实 API 验收

Status: implemented

## Problem

工作空间与教学模块的服务测试不能单独证明真实 HTTP
路由、身份凭据、资源引用和教学互动组成的用户旅程。尤其是平台管理员合法拥有治理权限，使用管理员身份测试学校之间的隔离容易产生错误结论。

## Decision

在 `noj-tests/e2e/cross-domain/workspace_teaching.test.ts` 增加真实 API
旅程。四个普通账号完成注册与邮箱验证，由平台管理员创建两个 Education
私有域，再通过邀请和转交产生普通平台账号的学校负责人。同一账号在学校 A
是学生，在学校 B 是教练，切换导航偏好不改变显式 URL 中的提交归属。

公共域的客观题通过共享草稿、显式发布和共享授权进入两个学校。旅程验证来源题号和独立绑定、学生不能读成绩矩阵、错误域路径不可访问、源域与另一学校提交不能计入学校
A 作业，以及学校 A
一次交卷同时计入两份作业。反馈和求助验证目标学生、同学、其他学校负责人之间的详情与目录隔离，并拒绝关联其他域提交。

撤销共享后立即检查题面、模板、版本目录、新交卷和题库列表；本人原答案、成绩、既有反馈与求助继续可读，作业单元标记资源不可用且保留成绩。所有准备数据通过
API 建立，不直接写数据库，不使用 Judge 探测结果跳过业务断言。

第二条旅程在隔离 E2E 栈通过管理 API
临时切换注册政策，验证邀请制下未获实例授权的学校邀请不能注册、没有邀请不能注册，以及获授权后同一邀请能创建统一账号并原子加入目标域与班级。邀请注册学生的成员空间仅包含所属学校，不自动加入默认公共域，也不获得教练权限。管理员开户政策下邀请预览与注册都拒绝新账号，已有账号仍能接受班级邀请且原密码继续有效。两项实例设置在
`finally` 分别恢复，并重新读取有效值验证恢复结果。

## Alternatives considered

- 直接操作数据库建立班级和作业：更快，但不能验证注册、邀请、发布与模块挂载，故不采用。
- 复用平台管理员完成所有操作：不能证明学校负责人的真实权限边界，故仅把平台管理员用于实例允许的建域和公共题维护。
- 使用异步代码题完成所有教学断言：会把教学访问与 Judge
  队列状态耦合；此旅程采用真实同步客观题判定，Judge
  评测旅程继续由现有独立用例覆盖。
- 为旧 P/U 题包和 Provider
  测试失败修改新旅程预期：这些是独立契约改造事项，保留原始失败并由对应负责范围处理。

## Consequences

新增测试可通过标准
`deno task test:domain cross-domain --filter=e2e/workspace-teaching` 运行。交卷
DTO 的百分制原分与教学、历史接口的 ×100
整数分别断言，不能把两种单位混用。测试保留隔离数据库中的唯一命名数据用于失败复查，不清除其他旅程资源。

注册政策旅程需要与其他账号注册旅程串行，防止临时政策影响其他测试；标准单进程跨域入口按测试顺序执行，分组并行执行时应按政策写入范围隔离数据库。

初次全域命令记录旧题包及 Provider
契约失败；这份新增旅程的过滤验证通过不代表全域验收已经完成。浏览器交互、LLM
实际调用、代码题沙箱以及性能验收仍由各自门禁提供证据。
