# Agent Note: 40人五题型教学真实跨模块验收

Status: implemented

## Problem

原教学跨域与浏览器旅程验证客观题和角色隔离，但没有以真实班级名单和矩阵同时验证
OI、AI 代码、LLM、产物、客观题。只插入评测成绩或重复调用进度算法，不能证明 实际
Judge、Gateway、受理时间、版本、作业候选与权限相互一致。

## Decision

新增独立教育域的六步骤 API 旅程。平台管理员建立域，并通过真实邀请与转交将
负责人交给普通账号；负责人邀请普通教师并授予 educator/editor 内置域角色。
普通教师无法访问平台治理，真实建班，40 个普通学生分别注册、接受班级邀请，
同时取得域成员与学生关系。账号与邀请操作采用八人有限批次。

小型题包工厂沿用已验证格式 2、fflate 与现有 SDK 镜像，导入并显式发布五题型 V1。
普通教师维护普通题目，平台仅代为导入需要实例网络权限的 LLM 题。
普通域负责人配置该域独立 Provider 与模型；新评测不继承其他域的 Provider。

教师发布两份相同五题作业，每份矩阵实际包含 40 人、5 题、200 个单元。
仅一名学生完成五种题型，其他 39 人保持未开始，不制造 200 个评测任务。
四种执行题使用真实 Judge，客观题通过实际正式交卷同步判定。

- OI 使用真实 Native C++ 的 60/40 分子任务。首提交仅完成 60 分，权威通过为
  false， 但达到最低 6000 的作业要求，达标与 AC 分别断言。
- AI 代码通过 SolutionRunner 调用 solve，实际返回 100 分。
- LLM 使用 SDK 调用本域 Gateway，再到 Mock；持久用量核对本域、Provider、 模型、8
  token、源题、版本、提交与评测尝试。
- 产物题实际上传含 submission.py 的 ZIP，由 Solution 容器执行并取得 100 分。
- 客观题通过一次实际交卷取得 100 原分，教学投影为 10000；受理时间和版本从
  本人历史读取，保留作业来源上下文。

所有普通提交携带作业 A 来源，但同一提交 ID 自动计入两份作业，逐单元核对
来源尝试与评测版本。两个矩阵都只出现一名达标学生。
学生不能读取矩阵、同学代码或域 Provider；伪造 progress 的 user_id
仍只能取得本人单元。普通教练可通过该班授权入口读取学生提交。

最后通过真实 end 操作结束作业 A，再实际提交 OI AC 代码。
服务器受理时间必须在结束之后：A 按时成绩保留 60 分和原提交， 当前补做进度变成
100 分、AC、late；B 仍进行中，按时成绩自动变成 100 分且非 late。 逐题核对发布时
V1、按时来源与作业版本历史，不直接修改数据库、成绩、投影或时间。

## Alternatives considered

- 插入成绩、投影或把比赛/作业时间改回过去：跳过实际链路，使用真实提交与 end
  操作。
- 评测全部 200 个单元：不能增加本场景的关键证据，四种真实执行题加一次客观交卷
  即可验证五链路，矩阵其余学生验证未开始。
- 将教师提升为平台管理员或直接写伪 owner
  角色：无法验证教学权限，使用真实域邀请、 负责人转交和内置教师角色。
- 用 AI 60 分伪造“未通过”：当前权威语义对非 OI 题沿用有效正分通过， SDK
  wrong_answer(60) 也实际得到 accepted=true。保留该规则，将最低分与 AC
  的区分放在真实 OI 部分分场景，不伪造 OI details 或扩大生产语义变更。

## Consequences

2026-10-13 在当前协调隔离 E2E 数据库，Worker 同时启用 ai、oi-native， 通过标准
`deno task test:domain cross-domain --filter=assignment-all-kinds` 取得 1
passed（6 steps）、0 failed、53 filtered out，耗时 13 秒。 五题型实际完成，域内
LLM 持久用量与任务成绩一致，无条件跳过或数据库伪造成绩。

标准入口完成当前整个 cross-domain 目录类型检查，测试格式和 lint 通过，
本记录通过 Agent Note 校验。正式 cross-domain CI 必须给该 job 的 Worker
与测试统一设置 ai,oi-native，并在同一 runner 构建 C++ 镜像；不能以 AI
专用池跳过。

此结果是六步骤实际 API 旅程，不冒称浏览器验收、100人×50题性能测量、V2
跟随或整个产品升级完成。V2
跟随由既有独立工作空间教学测试覆盖，未在本旅程重复扩展。
