# Agent Note: 域内浏览器契约与水合等待

Status: implemented

## Problem

原浏览器用例仍点击常驻空间切换器、全站搜索和固定反馈标题，与已确认的域内
导航不一致。部分客户端页面只等待 Vue 根节点存在便点击按钮，此时异步子组件
尚未水合，可能出现服务正常但首次点击没有处理的假失败。

## Decision

标准浏览器入口等待 Nuxt 的 `isHydrating` 完成，再执行交互。搜索测试验证域 URL、
查询类型、刷新与返回；切域通过头像二级菜单，教学入口通过实际导航菜单。
反馈测试使用学生与题号组成的标题，继续校验个人反馈和授权历史。

测试忽略报告由标准脚本生成。原搜索环境判断改为显式 `ignore`，PostgreSQL
单连接通知回归仅在真实 PG 环境启用；实际验收运行启用浏览器、API、Judge、 LLM
Mock 与对应数据库，不把缺少环境时跳过的测试算为执行成功。

## Alternatives considered

- 增加固定等待时间：不能证明异步页面已经可交互，也使每次测试变慢。
- 在产品 DOM 加测试专用就绪标记：Nuxt 已提供需要的水合状态，无需新状态。
- 删除已失效用例：会丢失搜索、角色切换、双标签页和教学闭环的实际覆盖。

## Consequences

测试跟随用户确认的交互契约，保留真实浏览器、网络与评测结果检查；失败仍保存
截图和 trace。测试数量、实际执行环境及最终结果在验收报告中分别记录。
