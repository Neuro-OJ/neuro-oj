# Agent Note: 系统、社区与管理门禁使用当前 Domain 契约

Status: implemented

## Problem

旧 system 自测重用 main 种子题，旧 community 全流程重用 main 社区。 其他 E2E
留下合法进行中的比赛后，自测因题目保密返回 404，社区普通发布因 CONTEST_SILENCE
返回 403。预审测试失败后不恢复全局审核窗口，又使后续帖子进入待审。

管理测试还允许找不到布尔设置时跳过写入，或只要提交详情不返回 401/403
就认为通过。
审计测试只统计整个实例的同类日志，缺少记录仍打印警告，旧记录可能掩盖本轮缺陷。

## Decision

自测复用共享 `createCodingProblemFixture()` 通过真实格式 2 题包导入、显式发布
独立公开加法题，读取其题号与版本后调用带 main 上下文的自测创建、查询接口。
保留真实 Judge 10 分、输出、队列类型验证，并确认当前用户正式提交与统计不变。
不删除已有比赛或放宽题目保密规则。

社区在独立 Community 域创建板块，作者和回复者通过真实邀请加入。
发布、评论、点赞、收藏、搜索、动态流、举报处置与预审治理使用显式域入口；
治理采用当前 `manage` 路径和 PATCH 状态协议。搜索等待正常持久事件索引生效，
不直接修改搜索表。回复与互动通知在使用域读取，关注关系和关注通知仍由账号入口读取，
分别断言两类通知，保持原互动与关注总量检查。

旅程明确准备无预审的发布配置，最后一项独立开启 24 小时预审并使用 finally
恢复此前设置，即使业务断言失败也执行恢复。恢复失败本身使测试失败。

管理测试明确选择 `allow_domain_registration_invites`，保存原政策值并按已有
updated_at 协议携带 If-Match、重读验证；普通用户越权使用真实设置路径。
管理员读取不存在提交精确要求 404，保留过期版本的 409 VERSION_CONFLICT。

审计夹具先读取 admin/user 内置角色，提权后明确恢复 user，不先写空角色再回退。
日志按本轮 target_id 检查提权、降权、封禁、解封、题目与标签删除及合并，
缺少记录直接失败。封禁之后重新登录必须成功，不回退到旧会话。
既有公告、轮播与签到用例保持行为，跟随标准 system 门禁共同运行。

## Alternatives considered

- 删除比赛或让社区忽略当前域赛中禁言：改变产品规则，使用独立资源和域。
- 将失败路径允许为 404/403：会丢失真实自测和社区主流程验证，按当前夹具执行。
- 用数据库写索引、评测成绩或成员权限：无法验证当前业务入口，使用实际 API 与
  Judge。
- 等日志数量大于零或找不到设置时只警告：可能被历史记录掩盖，选择本轮目标和明确设置。
- 把关注迁到 Domain：不符合统一账号关系规则，域内容与账号关系分别读取。

## Consequences

2026-10-13 在当前协调的隔离数据库和本地存储栈执行标准 Domain 测试：
`deno task test:domain system` 为 38 passed、0 failed（4 秒）；
`deno task test:domain community` 为 4 passed、0 failed（615 毫秒）；
`deno task test:domain admin` 为 11 passed、0 failed（191 毫秒）。 共 53
项真实运行，无新增跳过或删除业务断言。

四份修改的测试通过格式、lint 与标准入口类型检查，本记录通过 Agent Note 校验。
实际目录不存在独立 query/search E2E；本批不虚构额外目录或宣称覆盖整个升级。
修改只涉及测试与本记录，没有改变生产 core、UI、Schema 或重启测试栈。
