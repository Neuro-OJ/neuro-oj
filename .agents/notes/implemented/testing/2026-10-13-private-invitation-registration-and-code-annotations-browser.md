# Agent Note: 私有学校邀请注册与原代码批注真实浏览器验收

Status: implemented

## Problem

既有教学浏览器旅程使用已经注册的学生接受邀请，不能证明邀请注册新账号、
单可用域入口或代码行批注实际可用。客观题作答也不能验证教师查看原代码及批注
绑定不可变提交。已有组件测试和 HTTP 回归不能替代这些用户操作。

## Decision

新增独立 `workspace-private-registration-annotations.test.ts`，通过标准
`deno task test:browser --filter=private-registration-annotations`
执行六段旅程：

- 新学生从班级邀请注册页面创建账号，阅读并勾选法律同意，邮箱由邀请固定。
  使用真实注册响应的一次性 E2E
  验证令牌打开邮箱验证页面，实际完成验证并进入学校。
  核对唯一可用域、普通学生身份和班级关系，单域导航隐藏切换器；退出后不带
  redirect 重新登录，仍自动进入唯一学校。
- API 只准备普通教师、域、班级、共享题绑定及作业。教师通过真实负责人转交取得
  域权限，不授予平台权限。加法题复用已有独立题包夹具，发布后只授权目标学校引用。
  代码通过账号、使用域、源题、版本和语言对应的草稿恢复到编辑器，由学生在页面
  正式提交，经过实际 Judge 得到零分。
- 教师在成绩矩阵打开原提交代码，按文件与源码哈希保存 1–2 行批注；学生在自己
  作业的原提交详情读取。教师实际修改、撤回，学生重新读取后核对可见内容。
- 学生修改代码并再次通过编辑器提交，经 Judge 得到 10 分。新来源提交没有继承
  原批注；教师重新进入学生训练详情，重新读取第一份原提交并确认旧反馈仍在，
  不使用已经打开的旧侧栏作为持久化证据。
- 教师给第二份代码留下独立反馈，再通过班级设置的实际归档入口归档。双方重新
  打开作业，保留满分成绩、原代码及批注读取；归档后的教师侧栏不提供批注写操作。

测试临时设置邀请注册、允许域注册邀请及仅登录访问三项实例政策。写入使用既有 设置
API 和当前 updated_at 前置条件，finally 恢复原有效值并 GET 逐项核对。
政策窗口由主代理协调独占，未修改生产配置逻辑、邮箱实现、数据库成绩或进度。

## Alternatives considered

- 用 API 注册学生，再打开作业：遗漏本次要验收的邀请注册流程，学生账号只在
  浏览器表单创建。
- 将组件测试算作批注验收：无法证明原代码加载、侧栏、表单和学生读取，因此
  使用两个真实浏览器会话。
- 直接写数据库成绩或投影：跳过 Judge 和教学自动计入，采用真实零分、满分提交。
- 新提交后只检查教师已经打开的旧批注：可能看到旧缓存，改为重新导航并读取
  第一份提交。
- 对 Monaco 合成多行键入：自动缩进会改变 Python 代码。沿用既有浏览器门禁的
  草稿恢复输入方法，正式提交和评测操作仍在页面完成。

steps）、0 failed、15 filtered out，23 秒**。 日志为
`/tmp/noj-client-private-browser-archive-final.log`。
新增文件通过标准浏览器目录类型检查、格式及 lint，Agent Note 格式通过。

本地证明邀请新账号、单域入口、真实代码评测、教师批注与班级归档读取闭环；
邮箱服务采用现有 E2E mock，未验证外部邮件投递。此次过滤执行没有重新验收其余 15
项浏览器测试，也不代表 Public/Mixed 全旅程或 IDE 扩展宿主已经完成。
失败时沿用共享浏览器 helper 保存截图和 trace。
