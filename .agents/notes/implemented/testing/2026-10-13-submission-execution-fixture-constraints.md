# Agent Note: 提交夹具对齐执行归属与域版本策略

Status: implemented

## Problem

提交、客观提交、自测和批量任务的执行归属已收紧。旧提交测试需要显式填写真实
域和题库绑定；绑定存在后，直接修改源题的旧全局策略不再代表本域有效策略。
评测结果现在登记带实际用户归属的教学事件，旧临时用户清理缺少这一引用顺序。

## Decision

services、routes 与 mq 测试中的普通原始执行记录显式使用真实源题的 owned 绑定，
已有显式域和 shared 执行场景保持自己的目标域身份，不统一回填为 main。
初步夹具修改由协调 agent 完成，本记录的后续修复维护原测试行为。

提交版本读取、投影选择和结果落库的策略用例直接修改实际执行绑定的 any/exact 及
revision。源题最新版本仍在源题行更新，比赛策略仍只修改竞赛题关系，不恢复
从源题全局策略兜底读取的路径。未知版本桶、分数与通过指针分别选择等原断言
保持原含义。

三项评测结果用例的临时用户清理先移除该用户在本测试生成的 education_outbox
事件，再删除账号；不使用 catch 忽略外键失败，不改变产品软删除历史的规则。

公共队列的自测隐私用例显式建立公开且已发布的源题及 owned 绑定。队列普通
视角继续要求资源可公开读取，不沿用旧空归属绕过发布和展示范围检查的行为。
本人、他人、匿名与管理员四种自测可见性断言均保留。

执行归属数据库约束及 SQL 迁移测试由协调 agent 单独管理；versioning 子目录 由另一
agent 管理。本批后续修改涉及五份服务测试及本记录，完整模块验收在
这些范围冻结后执行，不把不同快照的结果拼成完成证据。

## Alternatives considered

- 在生产执行字段增加默认 main：会掩盖跨域提交归属错误。
- 恢复从源题全局字段选择策略：同一源题的多个使用域无法独立管理成绩。
- 忽略测试清理外键异常：会隐藏真实教学事件引用，并让失败诊断混入后续用例。
- 改低或删除既有断言：不再验证按当前域策略选择成绩的规则。

## Consequences

普通执行夹具符合当前非空和复合外键约束，版本读写按实际使用域策略运行。 继承的 NN
夹具与新增修复不修改生产、Schema、迁移或共享 helper。 聚焦标准 submission 入口在
PostgreSQL 与 PGlite 各 33 通过、0 失败，覆盖本批
修复的八项失败。完整模块另以独立 PostgreSQL schema 和隔离 Redis 验证，测试
通过不代替真实 E2E 或整个产品验收。

最终冻结快照的标准 submission 完整回归：PostgreSQL 为 381 通过、0 失败、 10
忽略，PGlite 为 350 通过、0 失败、41 忽略；真实 PostgreSQL 的公共队列
自测四视角用例实际执行通过。忽略项沿用标准环境门控，没有为修复新增忽略。
两轮迁移与种子各 8 通过、0 失败，全部进程退出码为 0。三个接管目录的完整
类型检查和新增修复文件格式、lint、Agent Note 门禁通过。
