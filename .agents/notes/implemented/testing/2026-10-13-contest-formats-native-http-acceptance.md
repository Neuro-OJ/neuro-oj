# Agent Note: 五赛制真实 HTTP 与 Native Judge 验收

Status: implemented

## Problem

原比赛 E2E 仍依赖 P/U、全局私有题权限和旧 Kaggle 配置，不能验证使用域、
不可变版本与多赛制规则。仅靠计分单元测试不能发现 HTTP 包装层重新加入受限制字段，
也不能确认真实 Native 判定被榜单正确采用。

## Decision

旧答疑和防作弊夹具改用当前赛制配置、显式 Domain 权限及草稿发布接口。
私有题归属独立成员域，通过实际邀请和负责人转交建立关系；跨域编辑者仍不能访问。
删除通过 SQL 修改私有属性的回退，普通交卷入口携带伪造比赛上下文必须明确拒绝。

新增九项五赛制回归，在隔离 E2E 数据库使用真实 HTTP 创建私有域、两名参赛者、 AI
支持包、C++ Native 支持包和客观题版本。提交由 core 入队，Judge 执行实际代码，
测试读取正式判定和排名；不直接写入数据库成绩，也不修改时间结束比赛。

- Kaggle 的先 100 后 20 分保留最高分；OI、IOI、IOI 严格选择最后 20 分提交， 后续
  CE 采用正式零分，不回退 AC。
- OI 本人列表和详情隐藏成绩、判定及评测字段，榜单与练习旁路拒绝；IOI
  测试点使用允许字段列表，严格模式和 ACM 只返回汇总，不包含原始输出或数据路径。
- 客观题并发正式交卷只能成功一次；Kaggle/OI 原百分分数不乘比赛题目满分。
- ACM 的 WA、CE、WA、AC、WA 序列仅计两次失败罚时，按 AC 受理时间计算耗时；
  封榜与本人反馈独立，比赛自然结束后检查结算和正式快照。
- 创建与赛前编辑校验允许题型，开赛后禁止修改计分规则，IOI 同分参与者并列。

Native 用例要求测试进程与 Worker 同时启用 `ai,oi-native`。 正式比赛 CI
的资源池和 C++ 镜像门禁由独立记录说明。

## Alternatives considered

- 插入评测成绩或直接调用计分函数：无法覆盖任务执行、版本结果和 HTTP 裁剪，
  采用真实 Judge 链路。
- 通过 SQL 回写结束时间：可能掩盖窗口与封榜缺陷，短比赛等待自然结束。
- 只删除旧权限案例：会失去私有资源隔离验证，改为显式域关系与跨域拒绝场景。
- 仅断言返回内容不包含测试数据字符串：不足以限制新增字段，同时检查允许字段和
  隐藏字段是否存在，包括值为 null 的原始输出字段。

## Consequences

该回归实际发现 OI 列表读取被裁剪题目信息导致 500，以及 Domain 详情二次投影加入
`output: null`、`output_truncated: null` 的契约问题；对应 core 修复后重新验收。

2026-10-13 在重建后的隔离栈执行标准 `deno task test:domain contest`，
`NOJ_RUN_E2E=1`、`E2E_JUDGE_RESOURCE_POOLS=ai,oi-native`，得到 36 passed、 0
failed，耗时 1 分 12 秒，九项 Native 用例均实际执行。 三份修改的测试通过格式和
lint 检查，Agent Note 格式校验通过。 结果代表本地协调栈比赛 HTTP
验收，不替代远端 CI、浏览器、性能或恢复验收。
