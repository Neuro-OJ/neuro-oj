# Agent Note: 完整浏览器回归的协议同意与教学提交依据前置

Status: implemented

## Problem

完整浏览器回归按顺序更新了隐私政策，治理夹具随后在未显示政策通知的管理布局寻找同意按钮。教学提交详情已提供按统计范围分页的提交依据列表，旧夹具打开成绩单元后没有选择具体提交，直接寻找原代码或已移到学生分支的提示。

## Decision

- 治理登录先进入普通 `/workspaces`
  布局，完成实际当前协议同意，再进入管理页；不通过 API
  伪造同意，不修改法律政策或管理布局。
- Private
  教师在单元详情中选择对应零分或满分提交，再检查原代码、创建与修改批注、学生可见性、新提交隔离以及归档后的历史读取。
- 教学窄屏场景实际选择客观题原提交，核对授权读取接口返回的当前正式尝试、策略匹配和原零分，并验证正式评测沿革的可见内容；保留
  390px 矩阵与跨域草稿断言。
- 不修改产品源码、权限、成绩、ignore 或已完成场景的断言。

## Alternatives considered

- 让管理员跳过协议同意会掩盖完整运行顺序的真实前置，拒绝。
- 只检查教师提交列表可见而删除原代码或尝试断言，会削弱验收，拒绝。
- 为夹具恢复旧详情页面结构会改变已实现产品行为，本次按实际流程更新夹具。

## Consequences

新隔离正式镜像运行栈先完成标准 cross-domain：55 项及 10
个步骤通过，无失败、无忽略。随后显式启用 `NOJ_RUN_BROWSER_E2E=1`
的完整浏览器回归为 17 项及 23 个步骤通过、3 项失败；已通过的新输入模式、LLM
模型治理与 Public/Mixed 旅程保留真实日志。

修复后只通过标准 browser 入口补验三项失败场景，不重复全套。治理 1 项、7
个步骤通过，无失败；Private 和教学 2 项、12 个步骤通过，无失败，18
项未受影响场景被过滤。完整入口已通过的 17 项与修复后补验的 3 项共同覆盖当前 20
项套件，不将其描述为一次全套全绿运行。

收尾 GET 实例政策与补验前快照逐项一致，注册开放、仅管理员创建
Domain、邀请注册默认关闭、模块与默认额度/上限均已恢复。没有 queued/judging
尝试，core
的数据库、Redis、消费者和队列健康。三份受影响夹具的格式、lint、类型检查与 Agent
Note 校验通过。

另一次未设置独立浏览器启用标志的入口调用仅返回或忽略，不能作为实际浏览器通过证据，不计入本记录。
