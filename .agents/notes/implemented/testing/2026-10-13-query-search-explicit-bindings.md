# Agent Note: 查询与搜索夹具复用明确归属

Status: implemented

## Problem

全 core 回归发现查询和搜索夹具在发布源题时建立本域绑定，随后又插入相同域的
另一绑定，违反每域每源题唯一约束。两项比赛索引夹具未保存比赛域，导致其题目
关联与父比赛不满足复合外键。

## Decision

共享源题场景先创建明确的三个域绑定，再发布版本；发布辅助复用已有本域绑定。
比赛索引夹具显式保存 main 域。测试继续保留三个域的数据隔离、共享撤销、
比赛保密及私有题标题不进入公共比赛索引的真实断言。

## Alternatives considered

- 插入冲突时忽略：会隐藏测试使用错误绑定 ID 的问题，不采用。
- 放宽数据库唯一键或复合外键：这些是产品不变量，修正夹具归属。

## Consequences

标准模块入口在独立 PostgreSQL schema 与 PGlite 分别验证：query PostgreSQL 37
项通过，PGlite 31 项通过、6 项专用场景忽略；search 各 35 项通过、1 项
性能测试忽略。三份修改的测试格式与 lint 通过。
这是首轮全量发现的九项夹具失败的针对性修复，完整全量仍需在最终冻结快照重跑。
