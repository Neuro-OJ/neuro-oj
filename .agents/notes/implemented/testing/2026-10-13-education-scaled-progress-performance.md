# Agent Note: 100×50 学情的真实后台更新性能

Status: implemented

## Problem

矩阵读取基线只验证分页查询，不能证明正式重测后持久事件消费者在五秒内更新
教学进度。原有自动消费者测试的数据量为单个学生和题目。

## Decision

在现有 100 学生、50 题、5,000 提交、10,000 进度单元性能夹具中新增正式重测
尝试，通过提交投影公共门面更新结果和事件，再启动真实教学后台消费者。
核对按时及当前进度采用新尝试、65 分、达标但未 AC 的独立状态。
计时包括正式判定写入和消费者处理，不包括 Judge 执行耗时。

## Alternatives considered

- 直接调用重算函数计时：没有验证持久事件领取与后台调度，使用实际 worker。
- 继续只测单个学生场景：已有功能验证，性能场景保持完整 100×50 数据量。

## Consequences

标准 education 性能过滤在独立 PostgreSQL schema 实际通过：矩阵 p95 100.36
ms，后台更新 1,623.94 ms；格式和 lint 通过。计时边界与环境详见
[性能记录](../../../../dev-docs/reviews/2026-10-13-education-matrix-performance.md)。
本次更新为单次固定环境记录，不承诺生产负载的延迟分布，也不代替浏览器渲染、
消费者重启恢复或整套发布验收。
