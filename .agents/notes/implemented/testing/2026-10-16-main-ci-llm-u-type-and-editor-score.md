# Agent Note: 修复 #651 合入后 main 的 LLM 与浏览器门禁失败

Status: implemented

## Problem

626ebf17（#651）合入后 main 的 CI 挂在三处：

1. `Core gateway` 的 `llm-bundle: U 型携带 llm 被拒` 与 cross-domain E2E 的
   「7.2 U 型题携带 llm 被拒」仍断言旧规则。#651
   有意放开了该规则：题包解析器只做结构校验，U 型 LLM
   由管理员在导入/CRUD/草稿/发布路径上准入，因此管理员导入 U 型 LLM 题返回 200。
2. Browser E2E 的「3/4 满分」读到 `0 分`、「4/4 非满分」读到
   `10 分`。后端日志显示两次评测分别为 1000 与 440，结果正确；问题出在测试读取
   UI。#648 把编辑器历史改为按题目内部 ID
   过滤后，「历史」列表才真正有数据：测试按文本匹配首个 `span.font-mono`
   时会命中历史卡片（未完成提交被渲染为 `0 分`），4/4
   又在历史异步加载前读取基线分数，于是把 3/4 的旧结论当作新结论。#648 的 main
   E2E 被取消、#650 的一次运行恰好时序通过，直到 #651 的运行才稳定暴露。

## Decision

- 单测改为断言 U 型 LLM manifest 能通过结构校验；E2E 7.2 改为「管理员可导入私有
  U 型 LLM 题」与「普通用户导入被拒 403」两条，与 #651 的权限边界一致。
- 编辑器「最近」卡片得分加
  `data-testid="recent-submission-score"`，浏览器测试只读该元素；4/4
  先等待「最近」卡片加载出上一条结论再提交。
- 历史卡片无终态结果时显示「—」而非误导性的 `0 分`。

## Alternatives considered

恢复 U 型 LLM 拒绝规则会撤销 #651 的需求，不采用。浏览器测试改用 CSS 类名区分
最近/历史卡片过于脆弱，因此使用 `data-testid`。

## Consequences

无 schema、协议或配置变更。E2E 对 U 型 LLM
的覆盖从「一律拒绝」改为「管理员允许、普通用户拒绝」；浏览器门禁不再受历史列表加载时序影响。
