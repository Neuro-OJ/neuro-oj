# Agent Note: 恢复 Domain 界面题的 SDK 反馈与运行参数历史

Status: implemented

## Problem

main 新增界面题的 SDK 支持 `NOJ.onResult`、历史参数对比和回滚。工作空间页面
最初仅复用了沙箱 iframe，未把运行结果传给 `UiFrame`，导致官方示例界面无法
接收到分数。旧 `UiWorkspace` 的历史与轮询使用全局 API，不能直接接到私有域。

## Decision

新增小组件 `DomainUiRuns`，复用本人 Domain 提交目录、授权详情、自测目录和现有
轮询工具。目录只提供运行元数据，用户请求对比或回滚时再读取授权详情中的原参数。
回滚不修改提交或作答版本，参数通过原域草稿链保存并回推 iframe；继续编辑后不再
用旧撤销动作覆盖新输入。

题库与比赛的 `UiFrame` 接收该组件输出的安全结果。正式提交只推送汇总字段，
`hidden` 固定输出“已受理”和空分数，不读取或推送嵌套判定、原始 output、details。
自测面板把已读取的 Domain DTO 共享给运行组件，避免当前自测重复轮询；重新进入
页面后仍可通过本人自测目录恢复运行历史与最近结果。源资源不可用时不推送自测输出。

比赛页面只查询本场正式提交目录，不查询题库自测目录。本人自测列表的后端实现由
独立 core 批负责；前端采用已确认的 `page/limit` 和标准 pagination 契约，原参数
继续通过已有详情端点读取。任何入口都不回退全局 API。

## Alternatives considered

- 接入旧全局工作区：会让私有域历史绕过显式使用域，因此继续复用 Domain 门面。
- 仅给 iframe 推送受理状态：无法兑现正常界面的 SDK 结果回调，故复用受裁剪的
  Domain 详情和现有轮询。
- 在客户端保存一份“历史成绩”：会与服务器权限、重测及比赛口径分离，因此客户端
  只保存草稿；运行参数和成绩都重新读取授权记录。

## Consequences

相关组件 4 文件、13 项通过；包括域目录与原参数回滚、撤销、SDK 分数接线、切域后
旧响应不恢复草稿，以及比赛 hidden 结果不泄漏。结果裁剪单元测试 3 项通过。 UI
Deno/Nuxt 类型检查和自有文件格式、lint 通过。本批不重复完整 UI 构建或全量
组件测试，不操作运行栈、Schema 或 jj。新增能力的真实 iframe、Judge 和浏览器
验收由根 Agent 在最终集成镜像中完成。
