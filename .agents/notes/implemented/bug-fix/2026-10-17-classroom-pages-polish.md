# Agent Note: 班级页面导航与教学操作打磨

Status: implemented

## Problem

班级子页面重复绘制面包屑，但没有稳定的班级内导航；概览页同时展示多个同级按钮，成员与作业列表使用重复阴影卡片。学生筛选缺少可见标签，设置保存没有确认反馈，主教练交接在没有接任者时仍提供空选框。部分内容经过 `AsyncContent` 的 `display: contents` 容器后，外层纵向间距不能分隔内部卡片。

## Decision

- 班级列表、概览、成员、学生训练、设置、加入申请、作业创建及比赛补题页面沿用原有 NOJ 内容页标题、颜色与表单控件。
- 使用共享 `ClassroomNavigation` 提供真实页面链接，按班级已有能力显示学生训练、成员和设置入口；学生不显示管理入口。学生详情保留学生训练导航的当前位置。
- 概览突出创建作业与按比赛补题。成员和作业使用单个分隔列表，保留角色、状态、权限与原操作。
- 学生搜索及范围筛选提供可见标签、结果数量和空结果重置入口；长用户名、题号与申请理由可换行。
- 设置保存提供成功状态，继续输入时清除旧提示。保存冲突保留输入；无接任者时禁用选择并说明前往成员页任命教练。
- 加载、失败和空数据使用现有 `AsyncContent`；需要多区块间距的位置使用明确的布局容器，不依赖透明容器继承间距。
- 调整作业编辑、CSV 预览、加入申请审核与学生提交抽屉的窄屏布局，不改变授权、版本、评分、邀请与批量导入契约。

## Alternatives considered

- 继续在每页复制返回链接与操作按钮：无法形成稳定导航，后续容易出现入口与能力判断不一致。
- 引入独立教学设计系统或重写教学业务：超过本次 polish 范围，且与用户要求保留原有 NOJ 风格不符。
- 仅修改卡片样式：不能解决保存反馈、空接任者、筛选标签和加载错误状态的问题。

## Consequences

班级页面使用相同的页面切换方式与操作层级，不新增后端接口或数据库迁移。导航和设置反馈增加组件回归，覆盖学生、助教、教练、加载中及保存冲突。

验证通过：UI 单元测试 287 项，组件测试 91 个文件、342 项，格式、Lint、工具类型检查、Nuxt 类型检查及生产构建。本地使用教练和学生身份完成 22 项检查：11 个 SSR 页面、10 个 API 权限与数据范围检查，以及比赛补题页面的客户端渲染入口可用性检查。比赛补题的能力分支另由组件测试覆盖，入口返回 200 不代表浏览器交互已验收。

当前会话浏览器工具未连接浏览器，桌面和手机的实际截图、触摸及键盘交互仍需可用浏览器进行最终视觉验收；构建和 SSR 结果不替代这部分证据。
