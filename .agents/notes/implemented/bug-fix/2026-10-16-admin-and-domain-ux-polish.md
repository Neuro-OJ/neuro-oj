# Agent Note: 实例与域管理界面 UX 优化与认知减负

Status: implemented

## Problem

在 NOJ 管理界面（包括实例访问政策、域设置、成员邀请、域额度配置以及提交与评测队列）的设计评审中（参考 `.impeccable/critique/2026-10-16T04-55-18Z__noj-ui-pages-admin-instance-access-vue.md`），发现以下影响管理员和用户体验的可用性与认知负担问题：
1. **策略重复编辑**：域基本信息（`WorkspaceSettingsForm.vue`）与域访问专页重复编辑相同的访问级别、加入策略和公开目录策略，导致职责混乱。
2. **移动端邀请适配不良**：邀请管理页在小屏下强制使用三列布局与横向挤压按钮，移动端表格横向滚动且重要状态及撤销操作被推挤至视口之外。
3. **额度层级重复冗长**：域额度设置中每项数值重复展示实例上限、已保存有效值和预计生效值三层文案，自定义存储仅支持原始字节数值输入，易错且不易读。
4. **长标识符挤占关键信息**：提交列表与队列首列展示完整 UUID/技术标识符，表头使用易混淆的“允许结果”，挤占了题目名称、用户与评测状态等核心业务内容。
5. **条件策略理解成本高**：实例访问设置中的“注册邀请政策”在开放注册或仅管理员创建模式下仍呈现为可编辑开关，管理员难以察觉其仅在“邀请注册”时生效；且默认工作空间下拉选单缺少局部加载、重试与空态表达。

## Decision

依据 Impeccable 方法论（Distill、Adapt、Clarify、Layout）与项目设计规范（浅蓝底、白色面板、天青蓝交互、2-6px 圆角），进行针对性收敛与修复：
1. **收紧职责边界（Distill）**：域基本信息表单仅负责编辑名称与简介；新增“访问与加入政策”只读卡片并提供直达专页的链接，避免双重真相源与保存冲突。
2. **响应式与无障碍增强（Adapt）**：
   - 邀请模式选择改为响应式网格（移动端垂直平铺，桌面端三列），主操作栏改为自适应纵向堆叠，生成按钮自适应全宽。
   - 4 个预设有效期按钮补充 `:aria-pressed` 状态。
   - 移动端新增自适应紧凑卡片流：首行保留受邀对象、状态徽章与撤销按钮，第二行展示到期时间与模式，次要字段支持展开与分页。
3. **层级提炼与单位换算（Distill / Clarify）**：
   - 额度展示突出“当前已保存有效值”，次级弱化展示“实例上限”，仅在发生变更时高亮提示“预计生效值”。
   - 自定义存储上限支持直接输入 GiB 并提供快捷预设（1 GiB、5 GiB、10 GiB、50 GiB），同时保留底层字节精确输入框。
4. **技术标识符收敛与表头语义优化（Layout / Clarify）**：
   - 提交 ID 超过 12 位（如 UUID）时自动截断为 `#前8位…`，完整 ID 保留在 `:title` 悬浮提示中；表头由“允许结果”明确更名为“评测结果”。
   - 队列中隐藏十六进制 UUID 题号，短业务题号与标题正常组合展示。
   - 队列范围切换按钮增加 `:aria-pressed` 语义，全局提示横幅降级为中性 subtle 风格。
5. **状态可见性与文案以人为本（Clarify）**：
   - 实例注册模式非邀请注册时，邀请政策以“预设提示框”形态呈现并附带原理解释，消除“立即生效”错觉。
   - 将“未认证请求均会被拦截或重定向至登录页”优化为“访客必须先登录才能访问站内内容”，消除接口化技术黑话。
   - 默认工作空间下拉选单增加局部 loading、重试按钮与空搜索结果提示。

## Alternatives considered

- **方案 A（整页重构与迁移）**：合并域基本信息与访问政策为单一大页面。放弃原因：违背了域导航分工与任务专注原则，会大幅增加单页复杂度和保存冲突几率。
- **方案 B（在手机端隐藏邀请表格）**：在小屏端彻底隐藏邀请历史列表，仅允许在桌面端查看。放弃原因：域管理员可能需要在手机端临时撤销外泄邀请或确认邀请状态，采用自适应卡片流展示更符合移动操作场景。
- **方案 C（完全移除底层字节输入）**：强制将存储额度输入限制为整数 GiB。放弃原因：破坏了后端已有的高精度字节契约，对于特定小额度测试与细粒度配额不灵活；保留字节模式与快速 GiB 换算双轨并存为最优解。

## Consequences

- **正面收益**：
  - 界面信息密度与视觉层级显著清晰，减少了管理员面对长 UUID 与冗余数值时的认知负荷。
  - 手机端域管理体验大幅提升，邀请流与操作按钮不再出现截断与横向滚动丢失重点问题。
  - 降低了非技术管理员对注册与访问政策生效机制的理解门槛。
- **维护成本**：
  - 需要同时维护桌面表格与移动端紧凑卡片两套模板（已通过统一的数据源和操作方法保证逻辑一致）。
- **回归与测试**：
  - 更新了相关组件单元测试（`WorkspaceSettingsForm.spec.ts`、`InvitationManager.spec.ts`、`WorkspaceLimitFields.spec.ts`、`InstanceAccess.spec.ts`、`DomainSubmissionsQueue.spec.ts`），前端所有 317 个组件测试与 284 个全局测试全部通过。
