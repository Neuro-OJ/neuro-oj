# Agent Note: 实例与域管理界面 UX 优化与认知减负

Status: implemented

## Problem

在 NOJ 管理界面（包括实例访问政策、域设置、系统设置、成员邀请、域额度配置以及提交与评测队列）的设计评审与使用反馈中，发现以下影响管理员和用户体验的可用性与认知负担问题：
1. **策略重复编辑与职责混乱**：域基本信息（`WorkspaceSettingsForm.vue`）与域访问专页重复编辑相同的访问级别、加入策略和公开目录策略，导致双重真相源；导航层级不清晰。
2. **移动端邀请与队列适配不良**：邀请管理页在小屏下强制使用三列布局与横向挤压按钮；评测队列（`QueueRow.vue`）在小屏下强制单行展示，多项固定宽度元素导致手机端横向撑宽溢出。
3. **额度层级重复冗长与编辑回归**：域额度设置中每项数值重复展示实例上限、已保存有效值和预计生效值三层文案；自定义存储仅支持原始字节数值输入易错；`WorkspaceLimitFields.vue` 因深层 watch 导致多字段编辑时未填完的自定义模式被误清空为继承，且父组件重新下发新对象时输入未及时同步更新。
4. **长标识符挤占关键信息且移动端难以获取**：提交列表与队列首列展示完整 UUID/技术标识符或短号后仅在 `:title` 提示中展示完整 ID，手机触屏无法获取完整编号；表头使用易混淆的“允许结果”。
5. **系统设置输入控件未规范化**：旧系统设置（`SettingFieldInput.vue`）使用了原生 `input` / `textarea`，不符合通用控件必须使用 Nuxt UI 的项目规范，且错误信息未通过 `aria-describedby` 关联。
6. **条件策略理解成本高**：实例访问设置中的“注册邀请政策”在开放注册或仅管理员创建模式下仍呈现为可编辑开关，管理员难以察觉其仅在“邀请注册”时生效；且默认工作空间下拉选单缺少局部加载、重试与空态表达。

## Decision

依据 Impeccable 方法论与项目设计规范（浅蓝底、白色面板、天青蓝交互、2–6px 圆角），进行针对性收敛与修复：
1. **收紧职责边界与导航治理（Distill）**：域基本信息表单仅负责编辑名称与简介；新增“访问与加入政策”只读卡片并提供直达专页的链接，避免双重真相源与保存冲突。统一管理页面导航、面包屑与次级操作位置。
2. **通用控件统一与无障碍关联（Clarify / Adapt）**：
   - 系统设置 `SettingFieldInput.vue` 全面替换原生输入控件为 Nuxt UI 组件（`UInput` / `UTextarea` / `USwitch`），保持 `setting-input-${key}-${templateId}` 唯一 ID 与敏感字段 secret 未编辑 null 语义。
   - 新增 `error` prop，通过 `aria-describedby` 动态关联帮助信息与保存错误（仅在错误存在时附加错误 ID），消除同页重复 ID。
3. **响应式与移动端结构优化（Adapt / Layout）**：
   - 邀请模式选择改为响应式网格（移动端垂直平铺，桌面端三列），主操作栏改为自适应纵向堆叠，生成按钮自适应全宽，预设有效期按钮补充 `:aria-pressed` 状态。
   - 移动端邀请列表新增自适应紧凑卡片流。
   - 评测队列行（`QueueRow.vue`）针对手机端重构为多行有主次结构：首行展示编号、复制按钮、域标签、自测标记与评测/等待状态或耗时/得分；第二行突出题目；第三行展示提交者、语言、资源池与提交时间，避免撑宽移动端视口。
4. **额度精度与单源状态修复（Distill / Fix）**：
   - 额度展示突出“当前已保存有效值”，次级弱化展示“实例上限”，仅在发生实际草稿变更时高亮提示“保存后预计生效”。
   - 自定义存储上限支持 GiB / MiB / 字节多单位安全无损转换，并提供快捷预设（1 GiB、5 GiB、20 GiB、100 GiB、256 GiB）。
   - 彻底修复 `WorkspaceLimitFields.vue` 状态机：仅在父组件替换 `modelValue` 整个对象引用时重建输入、错误与基线；组件内部修改同一对象属性，移除深度 watch 反向覆盖与 `props.effective` 重置基线，避免编辑一个字段时抹掉其他字段的未完成输入；域/实例设置父页面在保存和重读成功后均赋予新对象引用。
5. **技术标识符收敛与完整编号复制（Layout / Clarify）**：
   - 提交 ID 超过 12 位时自动截断为 `#前8位…`，链接保持完整原始 ID；表头明确更名为“评测结果”。
   - 在当前域提交列表（`pages/d/[slug]/submissions/index.vue`）和队列行（`components/feature/QueueRow.vue`）增加明确可访问的完整编号复制按钮（`UButton` 复制图标，`aria-label="复制完整编号"`），使用 `navigator.clipboard` 并通过 `useToast` 弹出轻量反馈。
6. **状态可见性与文案以人为本（Clarify）**：
   - 实例注册模式非邀请注册时，邀请政策以预设提示框呈现并附带原理解释。
   - 文案优化：消除技术黑话，清晰说明访客访问规则；默认工作空间下拉选单增加局部 loading、重试按钮与空态提示。

## Alternatives considered

- **方案 A（整页重构与迁移）**：合并域基本信息与访问政策为单一大页面。放弃原因：违背了域导航分工与任务专注原则，会大幅增加单页复杂度和保存冲突几率。
- **方案 B（在手机端隐藏邀请表格与队列次要字段）**：在小屏端彻底隐藏邀请历史列表，或队列行仅展示部分字段。放弃原因：管理员和用户可能需要在移动端核对提交状态或撤销邀请，采用有主次的多行卡片流既能保证信息完整，又不会横向撑破页面。
- **方案 C（为额度表单增加第二状态机）**：引入独立草稿与提交双重状态管理。放弃原因：过度设计且增加维护成本；简化为基于对象引用的单向同步和对象就地更新即可完全解决输入丢失与同步问题。

## Consequences

- **正面收益**：
  - 界面信息密度与视觉层级显著清晰，减少了管理员面对长 UUID 与冗余数值时的认知负荷。
  - 手机端管理与队列查看体验大幅提升，不撑宽视口且关键信息主次分明。
  - 统一了通用控件规范（Nuxt UI v4），无障碍关联更完善。
  - 彻底解决了额度编辑状态丢失与重载同步回归。
- **维护成本**：
  - `QueueRow.vue` 维护桌面单行与移动端多行两套响应式布局。
  - 需保证父组件更新额度配置时始终传递新对象引用以触发重置。
- **验收说明**：
  - 本轮集中修复针对 UX、响应式布局、控件规范及特定回归缺陷。最终的完整端到端测试与集成验证由 Codex 统一执行与提交。
