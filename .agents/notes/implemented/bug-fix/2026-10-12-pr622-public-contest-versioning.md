# Agent Note: 版本管理与客观题竞赛入口归一公开标识

Status: implemented

## Problem

独立复审发现：Web 竞赛 URL 和管理员页面使用 `ct-...`
公开标识，新增版本策略写路由却直接把它作为内部主键查询。管理员可以载入竞赛题目，但保存策略或固定版本返回
404。

客观题的竞赛小题读取、提交和历史查询也直接使用外部竞赛标识查询内部关联。真实参赛者因此读题
404、提交报“竞赛不存在”，历史查询为空；只使用 UUID
的已有回归没有覆盖正常浏览器路径。

## Decision

在管理员版本管理路由及客观题读写入口调用既有
`resolveContestId`，使后续权限、固定版本、提交唯一约束、投影和历史查询统一使用内部
UUID。管理员题目参数同样经既有题号/UUID
解析器归一。服务内的数据模型与锁序继续以内部主键工作。

回归覆盖公开竞赛 ID、题目 display_id、竞赛固定 V1 不被客户端 V2
覆盖、提交内部归属和公开 ID 历史查询。完整 objective E2E
改为使用浏览器实际的公开
ID，串联管理策略、固定版本、小题裁剪、提交、历史、重复提交限制与排名。

## Alternatives considered

- 前端要求管理员查找并输入竞赛 UUID：不采用，页面明确支持公开 ID，普通用户竞赛
  URL 也使用公开 ID。
- 仅修改管理员页面：不采用，客观题读题、提交和历史有相同标识边界，其他客户端仍会失败。
- 让底层数据查询同时匹配
  UUID/public_id：不采用，入口归一能使外键、锁和一次提交约束继续使用同一内部身份。

## Consequences

公开 ID 与 UUID
指向相同竞赛，已有权限和版本限制仍生效。修复不创建新的事实源或迁移。回归在修复前稳定失败，修复后通过，避免把
CI 的 UUID 夹具通过误认为浏览器竞赛流程可用。
