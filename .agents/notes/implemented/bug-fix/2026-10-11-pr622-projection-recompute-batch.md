# Agent Note: 题目版本投影批量重算

Status: implemented

## Problem

策略切换会重算题目下全部代码题与客观题提交。原实现逐条调用投影计算，重复读取题目策略、每条提交的当前版本判定和竞赛题目策略。提交数量增加后会形成 N+1 查询，并可能在大题目上把一次 `IN` 查询扩展到 PostgreSQL 参数上限。

## Decision

在 `projection.ts` 中把批量重算拆成「批量读取 + 纯计算 + 逐条写回」三步：题目策略只读取一次，当前版本判定按提交类型批量读取，竞赛策略按去重后的竞赛 ID 批量读取；每批最多 5,000 个 ID，超过后分批查询。单条重算继续使用原有查询路径，并复用同一个纯计算器，保证两条路径的选择口径一致。真实 PostgreSQL 验收覆盖题目策略与竞赛策略重算。

## Alternatives considered

- 保留逐条查询：实现简单，但策略切换在大题目上产生线性查询放大，不能接受。
- 把全部 ID 放进单个 `IN`：查询次数更少，但可能超过 PostgreSQL 参数限制；采用固定批大小保留可预测的上限。
- 只缓存策略而继续逐条读取判定：只能消除部分 N+1，仍无法满足批量重算的查询约束，因此同时批量读取两类来源的当前判定。

## Consequences

批量重算的读取次数按提交类型和 5,000 条批次增长，计算逻辑不访问数据库；写回仍逐条执行，因此不会改变已有锁顺序和投影写入语义。批量查询结果在当前事务快照内读取，策略切换与投影更新仍由调用方的宿主锁保护。真实 PostgreSQL `submission` 域 328 passed / 0 failed、`catalog` 域 328 passed / 0 failed，PGlite `submission` 域 298 passed / 0 failed / 40 ignored。
