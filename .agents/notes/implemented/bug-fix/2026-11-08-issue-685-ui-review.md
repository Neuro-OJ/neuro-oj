# Agent Note: issue #685 界面走查修复（首页刷新、底栏、题面页与题解入口）

Status: implemented

## Problem

issue #685 是对线上站点的界面走查（约 70 条）。对照 rc/v0.11 代码逐条核对后：
大量条目已在 rc 中解决或随功能下线（随机题目、关注动态）失效；剩余需要修的问题：

1. **首页“最新评测”与公告不刷新（真 bug）**：组件用
   `props.initialData ?? data.value`，服务端注入的首屏数据永远优先；实时事件 /
   轮询触发 `refresh()` 只更新 `data.value`，页面始终停在首屏。
2. 底栏：QQ 群把群号当 `qm.qq.com/q/`
   短链码（404）；“Issues”在两个分组重复；链接 `block`
   导致可点击区域占满整列；版权句号后直接接协议名。
3. 题面页：“题面”锚点紧邻题面无意义；抬头“开始编码”与题面工具条入口重复；工具条
   “展开”与正文底部“展开完整题面”重复。
4. 题解区：标题“题解与讨论”但只列题解；未通过本题也显示“发布题解”。

## Decision

- 首屏数据只做初值：`data.value ?? props.initialData`（`immediate: false` 时
  `data` 初始为空，自然先用首屏）。新增 vitest 用例覆盖“收到 `stats:updated`
  后显示刷新结果”。
- 底栏：QQ 群改为纯文本群号（不编造加群链接）；删除“开源 / 文档”中的
  Issues；链接加 `w-fit`；版权行加中点分隔。
- 题面页与比赛做题页：去掉“题面”锚点；编辑器入口只保留抬头按钮，
  `ProblemStatement` 删除无调用方的 `editorTo` / `editorLabel` / `editorIcon`；
  工具条只在展开后提供“收起”。
- 题解区：标题改为“题解”；发布入口按 `utils/solutionEligibility.ts` 判定（与后端
  `/solutions/eligibility` 的 `can_create` 同口径：题解模块开关、只读、
  赛时静默、发帖权限、通过门槛，审核员不受门槛与只读限制）。配置与通过状态仅在客户端
  读取，不阻塞首屏；仅因未通过而不可发布时提示一次“通过本题后可发布题解”。

## Alternatives considered

- “未翻译”类条目未逐条处理：283 个 Vue 文件仅 5 个使用
  `t()`，需先决定是去掉语言切换还是整体做英文版。
- 抬头中的难度等标签不移入“题目信息”：竞赛做题页不渲染右侧信息卡（#511
  回归修复）。
- 版本选择、最新评测的实时状态圆点、头像点击菜单、提交记录与队列分页等保留现状，
  它们是有意设计（版本策略、连接状态指示、触屏与键盘可达性、语义不同的两个页面），不属于缺陷。

## Consequences

- 首页最新评测与公告随实时事件 / 轮询更新。
- 未通过本题（且开启通过门槛）的用户不再看到“发布题解”，避免点击后才被 403
  拒绝。
- 题目页每次访问在客户端多 1～2 个轻量请求（社区配置；门槛开启时查询通过状态）。
