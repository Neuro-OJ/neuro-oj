# Agent Note: 初次评测任务显式发送尝试序列

Status: implemented

## Problem

协议 v2 的结果落库要求 `rejudge_seq`
是与尝试一致的整数。初次代码与产物提交通过统一任务入口构造封套时未传该字段，Judge
回传空序列，core 将真实结果当作过时消息忽略，提交停留在
`judging`。核心逻辑测试直接构造合法结果，未覆盖实际发送的 JSON。

## Decision

`prepareJudgeTask()` 对缺省序列显式发送 `0`，保留调用方传入的重测序列。增加任务
JSON 往返契约回归，覆盖代码、产物及非零重测序列，并通过真实 Judge
验证提交与结果闭环。

同步修正 E2E 请求以遵守已发布版本和草稿 revision 契约：提交携带
`version_id`，修改和重复导入携带 revision；SDK 评分使用百分制输入。

竞赛提交从竞赛题目响应读取固定版本。Judge
可用性探测使用管理员访问样例题，避免公开赛保密规则使在线 worker
被误报为离线。存储故障 E2E 按版本执行预检契约断言支持包缺失时返回 409
且不新增提交记录。

## Alternatives considered

- 结果入口把缺失序列视为零：拒绝，因为缺失封套应被拒绝，不能削弱消息归属校验。
- 只在代码和产物提交路径分别补字段：拒绝，统一入口可同时保证初次评测与自测封套的序列约定。
- 把序列放入执行快照：不采用；序列由尝试行提供，恢复时读取落库序列，快照负责冻结运行配置。

## Consequences

初次评测结果能按完整 v2
封套落入对应尝试；重测继续使用落库分配的序列。缺失或错误序列仍没有更新成绩的权限。真实跨模块
E2E 能检出仅靠合法结果夹具无法发现的生产者协议缺陷。
