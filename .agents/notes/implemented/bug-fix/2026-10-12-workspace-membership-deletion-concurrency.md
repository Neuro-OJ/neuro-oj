# Agent Note: 成员加入与账号注销串行化

Status: implemented

## Problem

成员加入、邀请接受及申请批准原先先锁域、再查询账号。并发注销可能在查询与新增
之间完成，留下已注销账号的有效成员关系，并占用成员额度。

## Decision

三个入口统一在事务内先锁目标有效账号，再锁域，沿用创建、交接和注销的锁顺序。
集中复用账号锁定函数；账号注销仍保留成员历史并释放名额。邀请注册的新账号由
原事务创建，不额外开启连接。审批先确认管理授权，再锁申请人的账号。

新增七个真实 PostgreSQL 测试，使用独立连接及数据库锁依赖屏障：三个入口各验证
注销先完成和加入先完成；另外验证两人竞争最后一个名额只有一人成功，失败邀请
不被消耗。锁依赖观测包含排队连接的间接阻塞，不用时间延迟推断执行顺序。

## Alternatives considered

仅在插入前再次查询账号仍存在查询后注销的窗口。新增事后清理任务会留下暂时
错误的授权与计数。沿用事务行锁即可满足要求，不增加第二套成员状态或重试框架。
