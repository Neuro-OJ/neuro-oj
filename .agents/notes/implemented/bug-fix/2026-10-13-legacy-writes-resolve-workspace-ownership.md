# Agent Note: 默认域旧入口与升级副本显式保存执行归属

Status: implemented

## Problem

默认域比赛服务在创建、编辑赛题时省略使用域和题库绑定，旧社区服务把新板块、帖子、评论、禁言及治理记录写成空域。比赛答疑通知也没有保存比赛域。代码和客观题升级副本使用可空字段拼接继承归属，可能把迁移期间的空字段带入新提交。

## Decision

比赛创建和编辑继续执行原题目添加权限检查，同时解析当前使用域真实题库绑定。旧入口固定
main，编辑保留已有比赛固定版本和有效策略，不允许通过旧服务把其他域比赛当成 main
修改。

旧社区 HTTP 内容与治理入口建立 main
的请求范围，并传递给板块、帖子、评论、互动、禁言及治理服务。写入与请求授权使用同一事务，Hono
已转换成响应的异常仍令事务回滚。旧平台社区权限仅在这个明确目标内生效；其他域资源
ID
不改变目标。板块角色授权也先校验板块所属域。新社区记录保存明确归属，私信举报和统一关注通知继续使用账号层面的空域。

题解始终解析使用域题库绑定。main 入口保留 P
数字题号转换，其他域使用来源题号。比赛保密和源授权检查使用同一资源解析；隐藏工单只保留举报依据，不返回不可访问的评论和父帖。答疑通知由持久比赛记录传入可信域
ID，不从通知 data 或用户输入推断。

升级尝试预检返回实际
DomainJobContext，新副本及额度直接使用该结果。升级解析原提交用户的当前资源资格，操作者的代操作权限单独检查；原比赛升级同时携带已验证的比赛上下文。既有尝试重派复用尝试和副本，不重新扣额度。代码、客观题副本保留源提交已有的作业入口依据，原历史空来源仍为空，来源字段不授予额外权限。

测试显式发布夹具同时建立源所属域 owned
binding，并保留已有独立策略。手写版本夹具明确调用相同绑定工具；比赛和社区夹具保存对应域，清理先释放绑定，模块级写入在实际
Schema 引导完成后执行。学校比赛由学校域入口创建，替代创建后搬域的无效状态。

## Alternatives considered

- 在缺绑定时由生产服务临时创建绑定：会把不完整归属变成隐式授权，拒绝采用。
- 新副本继续使用 item、source 和 null 多层
  fallback：不能证明新写入实际使用哪份题库策略，拒绝采用。
- 为升级放宽比赛保密或借用管理员的读题资格：违反原用户正常提交条件，改为明确使用原用户和可信比赛上下文。
- 仅在新显式域 API
  修正归属：旧入口仍会制造空数据并绕过治理范围，不能满足统一产品模型。

## Consequences

新写入具备后续 NOT NULL
与复合外键收缩需要的归属，当前数据库仍保持扩展阶段的类型；数据库收缩和历史回填由独立迁移批完成。本批不修改
Schema、DDL 或迁移，不删除存量业务数据。

模块标准回归覆盖两个数据库环境：比赛 PGlite 116 项、PostgreSQL 117
项通过；社区两套环境各 79 项通过；提交 PGlite 346 项、PostgreSQL 376
项通过，数据库专用、Redis
及性能场景按各自标准条件忽略。社区回归覆盖旧治理入口使用私域板块和帖子 ID 返回
404、新板块保存 main 归属。完整 core
回归仍需检查共享发布夹具新增绑定后的其他模块清理约定。
