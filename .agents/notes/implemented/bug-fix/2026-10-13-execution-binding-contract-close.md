# Agent Note: 默认执行绑定与批量历史终态闭环

Status: implemented

## Problem

默认域执行解析器在源题存在但 owned 绑定缺失时仍返回空绑定，旧提交与自测入口
会把这种未完成归属的记录受理入库。批量重试把失效来源的 failed/skipped 条目
重建为无绑定 pending，历史回填则以题目引用是否为空判断完整性，既会拒绝保留
非空失效题号的终态记录，又会放过题号为空的待执行条目。

## Decision

默认执行门面成功结果的绑定为非空字符串；缺少 owned 绑定或绑定停用时返回
404。四个旧执行入口继续复用这一门面，不自行重复检查或自动建立绑定。

重测任务重试只为可以解析题库上下文的条目建立 pending。没有合法源题的条目 记录
SOURCE_DELETED、skipped 和结束时间；全部条目均跳过时任务立即 completed。
混合任务中的合法条目照常执行，幂等身份与原目标版本依据保持原口径。

回填为所有条目保留父任务域归属，failed/skipped 可以保留空绑定及原始失效引用。
其他状态缺少绑定时完整性核对失败并回滚，不能以空题号绕过检查。提交原始内容、
受理时间与未知版本标记不改变。

旧提交、自测、版本评测和并发屏障测试显式建立真实 owned 绑定，复用已有测试
helper，不在生产解析器或共享测试拦截器中补历史数据。新负向用例保留缺绑定数据。

## Alternatives considered

- 每个旧写入入口分别检查绑定：重复实现同一门面约束，容易遗漏批量入口。
- 为缺绑定记录自动建立本域绑定：会让错误归属与未初始化数据被静默受理。
- 删除失效批量条目或伪造绑定：会丢失原始任务依据。
- 允许无绑定 pending 等 worker 再拒绝：队列中保存了不能执行的条目，违背后续
  数据约束收缩要求。

## Consequences

成功受理的默认域执行记录具有完整题库身份，批量失效终态仍可解释历史。 本批不修改
Schema、DDL 或迁移；NOT NULL 与条件 CHECK 由协调批次单独生成。

首轮全模块回归暴露旧测试夹具缺少 owned 绑定，已经逐项显式补齐。验证采用标准
catalog/submission 模块命令和独立数据库、schema、Redis，同时覆盖 PostgreSQL 与
PGlite。新增回归验证缺 owned 或仅 shared 绑定拒绝、绑定停用拒绝、终态回填幂等、
无绑定 pending 回填回滚，以及混合和全部失效重试任务的状态。

最终标准模块回归：catalog 在 PostgreSQL/PGlite 均为 366 通过、0 失败；
submission 在 PostgreSQL 为 379 通过、0 失败、10 忽略，在 PGlite 为 349 通过、 0
失败、40 忽略。忽略项为标准入口既有环境门控，没有新增忽略。四轮初始化
迁移与种子测试均为 8 通过、0 失败。受影响文件格式、lint、类型检查及 Agent Note
格式校验通过。
