# Agent Note: 作答版本与域 Provider 文档对齐

Status: implemented

## Problem

旧题目版本指南把 any 描述成允许任意已发布版本新提交，与当前 Domain 执行
入口检查当前作答版本的行为不一致。部署指南要求通过清空题目 LLM 配置处理 旧 BYOK
引用，会丢失题目能力与单次预算，也不符合域 Provider 的执行归属。

## Decision

版本指南明确题库、作业与自测新提交使用本域当前作答版本，版本变化要求
保留作答并重新确认；any 只决定历史成绩候选。旧版授权读取、重测已有提交及
不可变历史仍保留。用户升级说明与实际提交详情入口、当前作答版本选择对齐。

核对 Gateway 0002 历史迁移：它确实删除旧用户自建 Provider 及密钥，再删除
created_by；0005 则将平台 Provider 与用量归入默认域。部署指南保留旧迁移的
真实风险和只读盘点步骤，明确仅在尚未应用 0002 且旧列存在时适用。升级流程
改为备份、核对历史迁移、协调升级、重新配置使用域 Provider 与模型、实际调用
检查。删除清空 problems.llm_config 的指令，不再用题面旧 Provider ID 判断
当前配置是否可用。

历史版本的 Provider/模型字段保留但不选择当前执行服务，尝试冻结已解析配置。
新域没有公共域密钥回退；已有域设置也不会在重启时被旧平台默认值覆盖。
旧部署标题锚点显式保留，保证已有更新日志与外部链接继续定位到说明。

## Alternatives considered

- 删除全部 BYOK 说明：仍未跨越旧迁移的实例会遗漏真实密钥收缩风险。
- 保留直接清空题目配置操作：改错配置归属，且破坏题目 LLM 能力依据。
- 为描述旧行为而放宽产品规则：文档必须按当前实际使用域执行行为说明。

## Consequences

用户可以区分新作答版本选择与历史成绩有效性，运营者可以按使用域检查调用
配置。只修改两份文档和本记录，不修改生产服务、Schema 或迁移。

验证使用标准文档构建及仓库 Markdown 链接检查；格式和 Agent Note 门禁同时
执行。文档验证不声称实际升级、CI 或恢复演练已完成。
