# Agent Note: 工作空间账号封禁与真实预约人

Status: implemented

## Problem

后台预约发布和分页导出只持有账号 ID，没有重新通过 HTTP 认证入口。账号在
预约或首屏读取后被全站封禁时，需要直接检查当前数据库状态。预约动作由
其他获授权教师执行时，继续使用原创建者作为发布人也会导致权限判断错误。

## Decision

identity 增加公开的实时账号检查，验证账号存在、未注销及当前全站封禁。工作
空间先执行实例和账号政策再解析域，成员／邀请目标锁定后也检查封禁。社区
封禁和过期封禁不阻止正常教学；错误不额外暴露其他账号的封禁理由。

作业独立保存 scheduled_by，预约时记录实际操作者及审计，后台按此人当前
账号、域、班级和模块权限发布。创建者信息保留，合法的新预约人不会借用或
受限于旧创建者的权限；预约人被封禁则发布失败并保留具体失败原因。

## Alternatives considered

- 复用 HTTP 封禁缓存：不适合没有 HTTP 上下文的后台动作，因此读数据库。
- 将创建者视为预约人：会错误处理委托管理，因此独立保存真实操作者。
- 封禁后继续导出所有页：会扩大访问窗口，因此下一页读取立即重新授权。

## Consequences

追加迁移 0124，增加可空预约人，已有准备数据的 scheduled 状态按旧行为回填
创建者；约束保证未来预约状态具有发布时刻及预约人。PGlite DDL 同步更新，
开发库与恢复库保留原数据完成追加迁移。

教育专项在 PostgreSQL 和 PGlite 各 58 项通过，性能基准各明确跳过 1 项；
覆盖后台全站封禁、社区及过期封禁、创建人与预约人不同、预约后封禁、旧邀请
拒绝被封禁账号，以及两页 CSV 在全站封禁后停止。完整 core 类型、受影响 格式 /
lint、Schema parity（98 表 / 877 列）、快照、迁移安全及域边界通过。

workspace PostgreSQL 34 项通过；identity PGlite 312 项通过、26 项明确跳过。
这批账号修正之后未再次运行全量分片，最近全量记录仍对应前一批矩阵提交。
