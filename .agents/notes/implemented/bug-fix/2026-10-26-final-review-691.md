# Agent Note: 修复整栈复审的九项一致性与恢复问题

Status: implemented

## Problem

PR #691 的最终复审记录
FR-1～FR-9：后台派发覆盖已完成提交、临时重建错误破坏重试、 Domain
比赛受理逸出事务、任务执行失租、记账 readiness 假绿、排队后 token 未复核、Redis
恢复遗漏 done 吊销事实、搜索任务永久去重，以及发布集 WASM 标准漂移。

## Decision

- FR-1/FR-2：派发以 task 中的 attempt 为身份，条件更新只推进同一活动 attempt 的
  pending 提交。临时故障抛给 worker 退避；永久故障通过统一 attempt
  终态入口登记吊销。
- FR-3：比赛授权显式接收
  DbTx，使用同一事务读取域、比赛与报名，不占第二条根连接。
- FR-4：worker 执行期间续租，失租时取消 handler；串行处理逐条领取，过期 token
  不能续租、完成、重新调度或记失败。DB 的 clock_timestamp() 决定持有权，
  避免长事务中的 now() 冻结；本地时钟只保守触发取消。
- FR-5：超过 30 秒没有完整成功记账轮次，readiness 返回 worker_stalled。
- FR-6/FR-7：Core 从 PostgreSQL 吊销 outbox 的所有未过期行（包括 done）分页恢复
  Redis 标记，完成后写入当前 run_id
  屏障。启动及周期补偿均重建投影，保留原有效期。 Gateway
  在请求入口、等待预占锁后及原子 Lua 预占时复核身份、有效期与恢复屏障。 Lua 使用
  Redis TIME 和 INFO，检查先于额度递增与幂等标记返回。
- FR-8：搜索任务用不可变发布版本作为事件去重键，同事件重复登记合并，后续版本独立登记。
- FR-9：发布集 SDK 标准取 Core 实际协议 JSON，并与 Judge 的实际 JSON
  作一致性断言。

## Alternatives considered

仅在 HTTP 入口复核吊销无法覆盖 Provider 排队、政策锁等待或 Redis 切换。 只重放
pending outbox 无法恢复已完成行的丢失标记。把旧搜索任务直接重置 pending
会覆盖在途租约，故采用事件级任务。预先批量领取再串行执行会消耗尾部任务的租约，
因此保留单 worker 串行执行并逐条领取。

## Consequences

Core 与 Gateway 必须协调升级，共用 Redis，并允许服务身份执行 INFO server。 Redis
重启恢复后，Core 重建完成前 LLM 请求返回 503 revocations_unavailable； Gateway
容器健康不依赖该屏障，避免 Compose 中 Core 等待 Gateway 健康形成启动互等。
周期恢复会读取有效期内 outbox 全量事实，并逐批写 Redis；长期 token 较多时应观测
数据库扫描和 Redis 写入成本。过期行不延长标记存活时间。

回归覆盖真实 PostgreSQL/Redis 的派发交错、单连接池受理、续租与失租、done
吊销恢复、 搜索事件，以及 Lua 最终预占边界；路由测试验证拒绝后不调用上游。外部
Provider、 生产切换及完整备份恢复验收仍沿用原栈独立证据，不由本修复 PR 替代。
