# Agent Note: 评测完成后的教学矩阵实时刷新

Status: implemented

## Problem

前端已经监听教学 SSE，但服务端只发送反馈及求助通知。普通评测完成会物化成绩，
不会提示稳定矩阵重新读取，导致教师继续看到未开始状态。真实服务验收发现了这处
组件模拟事件无法覆盖的缺口。

## Decision

教学消费者在完成某作业一页学生的物化后，登记可重放的域内 `education:sync`
事件。事件只包含域与作业定位，不含学生、成绩或评测内容。SSE 入口订阅用户通知
和域教学提示，每次重新检查域及作业访问权限；无关作业过滤，离域后关闭连接。
前端事件回调重新读取作业、班级及允许的进度接口，不直接写入事件成绩。
比赛题目页也同时监听 revision 与开始、结束状态，时间导致的变化会重新读取题目。

真实验收使用独立恢复套件的 40 人、5 题型作业。学生 35 从未开始状态提交 C++，
Judge 返回 AC / 10000；教师已打开的当前补做矩阵约 786 ms 内更新为 “100 · 已达标
· 逾期”，无需刷新，浏览器无 JavaScript 错误。 提交 ID 为
`90b56b39-4235-4b04-b750-3c2d9b9cf177`。 education 124 项、community 85
项通过；类型及 lint 通过。SSE 测试覆盖持久提示、
重放、额外成绩字段裁剪、无关作业、错误域及撤权停止。事件目录由标准生成器更新。

## Alternatives considered

- 所有教师持续拉取整张矩阵：无变化也产生额外开销，采用轻量定位提示。
- 推送成绩及学生记录：造成第二套授权和裁剪逻辑，统一重新读取已有接口。
- 普通提交生成“未读通知”：评测频繁会污染教学通知，进度提示与待处理通知分开。

## Consequences

正常评测后稳定矩阵也能更新，断线可重放且重新校准。重复提示不会累计成绩。
实例模块治理的回归同步替代旧域模块开关，旧停用沿革仍保留。完整 CI 和比赛
开始结束真实计时旅程继续列在任务清单，不因本轮测试通过提前签收。
