# Agent Note: 为 LLM 自测补齐执行凭据和终态吊销

Status: implemented

## Problem

`v0.10.5` 的正式提交会签发 LLM 网关凭据，但自测构造任务时遗漏 `llm`。
数学助手的自测因此在 SDK 调用时报告网关地址缺失。自测恢复也跳过 LLM 配置。

部署节点另有旧的 2 GiB Judge 限制、缺失的专用 Docker 评测网络、停留在
`0.10.1-alpha.2` 的 SDK 运行时，以及未写入发布版本的模板；这些通过部署配置、
匹配 `v0.10.5` 的运行时镜像及发布新题目版本分别修复。

## Decision

- 自测在构造任务前生成唯一 `run_id`，按该运行标识签发 LLM token 和隔离预算。
- 保存不含短期 token 的 LLM 执行快照；pending 恢复使用冻结的 Provider、模型和预算。
- 正常终态、取消、永久派发失败与永久恢复失败均在终态事务内登记既有吊销 outbox，
  提交后执行吊销，Redis 不可用时由既有 sweeper 补偿。
- 修复在 `v0.10.5` 的独立副本中构建，部署为单独命名的本地后端热修复镜像，
  保留原 Release 镜像和配置备份；当前开发工作区不参与构建。

## Alternatives considered

- 只提高内存：不能解决缺失的自测凭据及 SDK 接口。
- 把 token 写入执行快照：短期凭据会过期，并造成不必要的持久化泄漏。
- 恢复时重新选择平台默认模型：会改变同一次自测的执行事实。
- 只在内存中重试吊销：重启后会丢失外部副作用，沿用持久化 outbox 更可靠。

## Consequences

无需数据库迁移；自测仍只写独立自测记录。LLM 题自测会真实消耗对应运行的调用预算。
新增回归覆盖首次派发、冻结配置恢复、结果幂等、取消和永久恢复失败的持久化吊销。
`deno install` 自动补齐了该 tag 锁文件遗漏的现有 `yaml` workspace 引用，未新增依赖声明。
部署验收记录与配置回退信息独立保存在节点维护目录中。
