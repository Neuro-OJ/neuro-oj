# Agent Note: 社区索引消息在授权事务提交后发布

Status: implemented

## Problem

最终社区 API E2E 中，讨论已出现在列表，域搜索等待 30 秒仍找不到。帖子、评论与
审核变更在域授权事务内直接发布 Redis 索引消息；消费者可能先读到未提交记录，
把它当成不存在。回滚事务也会留下无效索引消息。

## Decision

复用 `CommunityScope.afterCommit`，在域或默认域授权事务提交后才发送对应搜索
消息。无显式授权事务的原有调用继续在数据库写入后发布。帖子创建、修改、审核，
以及评论创建、修改、审核和删除共用该顺序。

## Alternatives considered

- 单纯重跑或延长 E2E 等待：消息已被提前消费，不会因为等待更久自动修复。
- 给消费者增加固定延时和重试次数：掩盖生产者违反提交顺序的问题。
- 新增另一套 outbox 表与后台任务：当前缺陷由已有事务提交回调即可修复。

## Consequences

消费者读取的是已提交事实，回滚不会发送本次索引消息。Redis 发布继续沿用现有
机制；本次不把它宣称为数据库 outbox 或新增可靠投递保证。
两项确定性回归分别验证事务完成前队列无消息、完成后有消息，以及回滚不发布；
修复前均失败，修复后通过，原无域调用的发布测试继续保留。
