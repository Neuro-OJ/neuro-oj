# Agent Note: 默认域策略绑定与比赛当前角色授权

Status: implemented

## Problem

旧有效版本策略入口仍修改源题全局字段，使不同使用域无法独立保存策略。旧比赛题访问把创建者身份直接当作组织权限，角色撤销后仍可获得组织者结果。真实
PostgreSQL
并发回归发现，源题先行的结果写入与域先行的策略更新会在教学事件的域外键检查处形成锁环。

## Decision

默认题库策略兼容入口仅定位 main 的本域题和 owned 绑定，调用 catalog
的公开策略门面，在同一事务完成当前权限、绑定
revision、历史、成绩投影和教学事件。源题全局策略不再修改，其他域引用不受影响；比赛策略继续独立。批任务含默认题库策略时先取得
main 域更新锁，再按已有顺序取得源题和比赛宿主锁。

比赛题访问默认固定 main，包括尚未回填的 NULL
历史归属。显式域调用必须匹配目标域。组织权限由当前平台管理权限或实际域角色计算；作者需要当前
contest:manage_own，退出域或角色撤销即时失效。

成绩写入共用的 lockProjectionHosts
先读取持久提交的域归属并取域共享锁，再取源题、比赛和提交锁。它服务于评测回调、活动尝试创建、批任务派发及失败结束、提交删除；新建提交的域锁由原受理入口先取得。比赛策略宿主锁也先按持久比赛归属取得全部域共享锁，再按
ID 锁定全部源题与比赛，最后重算提交和 revision。域归属不从 Judge 回调或
evaluator details 读取。

## Alternatives considered

继续同步写源题全局策略会破坏域间独立性；保留创建者授权会使撤权失效。只重试
PostgreSQL
死锁不能修复反向锁序，因此调整共同锁入口，并保留真实双连接屏障回归。测试夹具显式建立域成员、角色和题库绑定，不在生产授权中增加例外。

## Consequences

默认 API 的 expected_revision 指向 main 绑定 revision，不能继续使用旧源题 global
revision。跨域源题 ID 被拒绝，修改 main
策略不改变学校绑定及源题旧字段。重测日志使用 main:number，移除 P/U
展示分支。扩展期间 NULL 提交仍按 main 锁定，其原提交、版本与尝试 ID
保持不变。回归覆盖域策略隔离、权限撤销、默认及显式比赛路径、原子策略回滚与真实
PostgreSQL 锁竞争。
