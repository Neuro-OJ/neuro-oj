# Agent Note: 登录失败锁定按账号与客户端 IP 隔离并提供管理员解锁

Status: implemented

## Problem

用户名公开，单账号失败计数允许攻击者用错误密码锁住他人一小时。
既有改密与 TFA 命名空间同样缺少客户端 IP 隔离，管理员没有恢复入口。

## Decision

失败计数、Redis 锁定和既有内存退避统一使用小写账号标识与可信代理解析的客户端 IP，
命名空间保持隔离。账号标识进行 URI 编码并额外编码星号，避免 SCAN 通配符扩散。
登录保留用户名/邮箱解析为用户 ID 的规则；已认证的改密/TFA 直接用用户 ID，
避免把用户 ID 再当登录名解析为 unknown 标识，造成改密检查与记录使用不同失败桶。
独立的账号/IP 窗口仍调用原有逻辑，阈值、窗口、配置名保持不变。

管理员端点 POST /api/v1/admin/identity/users/:id/unlock-login 复用组级管理员鉴权，
分页扫描该用户全部命名空间与 IP 的失败/锁定键，覆盖 ID、用户名和旧 TFA 解析标识，
清理本进程退避，并以 users.unlock_login 写路由审计。
前端用户列表提供解锁按钮、加载状态、重复点击保护与成功/错误提示。

## Alternatives considered

保留单账号锁定无法消除针对公开用户名的拒绝服务。
删除账号窗口会削弱分布式撞库防护，因此账号窗口保持原状。
固定枚举命名空间会遗漏扩展命名空间，因此解锁按统一键格式扫描。
使用 Redis KEYS 或一次收集全部键会放大管理操作开销，因此逐页扫描并删除。
引入跨进程内存退避广播需要额外基础设施，超出本次范围。

## Consequences

攻击者只能锁住其客户端 IP 与目标账号组合；同 IP 的共享网络用户仍共享失败桶。
登录成功只清理本 IP 和当前命名空间，管理员可恢复全部 IP 的 Redis 锁定。
其他副本的内存退避和已经等待中的请求仍按原期限完成；没有新增进程内可变状态。
旧版无 IP 键不再读取，按原 TTL 过期，无数据库迁移。
测试覆盖 IP/命名空间隔离、成功局部清理、管理员扫描与审计、权限拒绝和前端操作反馈。
