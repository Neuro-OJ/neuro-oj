# Agent Note: 凭据变更原子撤销全部旧会话

Status: implemented

## Problem

修改密码仅撤销当前 JTI，邮件重置密码没有撤销会话，其他设备的旧 JWT 仍有效。
凭据校验与更新之间还可能发生并发重置，必须避免旧凭据覆盖新密码。

## Decision

users 新增默认 0 的 session_version，密码更新与版本递增在同一条 SQL 中完成。
登录和 OAuth 会话携带读取用户时的版本，改密路由使用 UPDATE 返回的版本签发。
强制认证与可选认证都读取数据库版本并比较，不使用缓存。
历史 JWT 缺省为版本 0，因此升级本身不踢出用户，首次凭据变更撤销全部旧会话。
补设密码同样递增版本；普通改密通过版本与密码哈希条件阻止并发覆盖。

迁移通过 deno task db:generate 生成，未手改 journal。
旧快照漏记 search_entries，生成器重复生成了 0074 已建的表和索引；
本次新增 SQL 仅保留生成的 users ALTER，新的生成快照包含实际已存在的搜索表。

## Alternatives considered

枚举所有 JTI 需要新增持久会话索引，且无法覆盖此前未登记的 JWT。
仅在 Redis 保存撤销时间有持久化和时钟精度问题；秒级 iat 无法区分同秒改密前后会话。
单独更新密码和撤销状态存在失败窗口，因此采用数据库原子版本递增。

## Consequences

部署前必须运行新增迁移；现有启动流程自动执行迁移。
所有服务实例需更新到支持会话版本校验的代码，混合版本部署不能保证旧实例拒绝旧会话。
密码重置后所有设备需重新登录，改密当前设备由代理替换新 JWT 后继续使用。
回滚应用代码会移除版本校验，恢复旧会话的风险必须在回滚时考虑。
回归覆盖历史 JWT、多设备、可选认证、正常改密、OAuth、无效重置、并发更新和迁移。
