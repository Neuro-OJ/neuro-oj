# Agent Note: 统一通知的真实控件与答疑访问修复

Status: implemented

## Problem

Issue #696 的统一收件箱在真实 Nuxt UI 控件下使用空字符串选项，导致通知页 SSR
返回 500。列表展示后源授权失效时，点击通知的异常也缺少页面反馈。
此外，竞赛答疑通知沿用了社区功能开关，教学域关闭社区后会隐藏仍有权查看的答疑。

## Decision

- “全部域”在选择器内部使用非空标识，仅在发出请求时转换为不带域筛选。
- 打开通知仍先核验源授权；请求失败时显示错误并留在收件箱。
- HTTP 组合根独立组合竞赛答疑授权：检查通知所属域、源竞赛、原提问及当前
  参赛身份，复用于分页、未读、详情、已读和 SSE；社区开关只限制社区通知。
- 构建后浏览器验收覆盖桌面与窄屏的通知筛选、详情、批量已读、撤权和作业跳转；
  竞赛域回归覆盖关闭社区及删除源竞赛后的读取和已读行为。

## Alternatives considered

只在组件 stub 中检查选项无法发现真实选择器的空值限制；直接放行全部答疑通知
会跳过源资源授权。因此保留真实浏览器回归，并由竞赛模块提供数据库授权条件。

## Consequences

无需新增表、迁移或业务数据搬运。验收使用任务独占的 PostgreSQL、Redis 和存储
目录；浏览器脚本使用真实构建与 Chromium，但 Core 响应为夹具，不能代表生产
联调验收。原工作区的后续比赛界面改动保持原样。

本次隔离验收结果：教学域 146 项通过、0 失败、1 项跳过；竞赛域 129 项通过、 0
失败；授权组合调整后教学通知的定向回归 2 项通过；仓库门禁 251 项通过。 前端
lint、Nuxt 类型检查、正式构建、Core 通知入口类型检查、模块边界严格检查 和构建后
Chromium 验收均通过。浏览器覆盖 1440px / 390px 通知页及既有
SSR、水合和身份分支回归。
