# Agent Note: 域负责人初始化及注销事务守卫

Status: implemented

## Problem

管理员列表包括不可登录的 root，按 ID 排序使默认域一直由 root 占位。
现有注销只将账号软删除，可能留下失效负责人，且注销前清除头像会让拒绝操作
产生副作用。交接和注销也需要统一锁顺序，避免交接给正在注销的账号。

## Decision

默认域选择未注销的真实管理员，排除 root；首次本机管理员初始化同事务建立
默认域关系，开发引导也接入默认域初始化。已由人担任负责人时启动不覆盖； 仅修复
root 占位，保存配置、资源 ID 和编号，并记录 bootstrap_owner 审计。

创建 / 交接先锁账号，再锁域；注销先锁账号并检查所有负责域，返回 409 和
DOMAIN_OWNER_TRANSFER_REQUIRED。拒绝时不改身份、成员、头像或文件。
允许注销时保留成员历史、原子移除当前关系及释放名额，每个域保存审计；头像
对象在账号事务提交后按引用守卫清理。密码确认后若哈希变化，重新要求确认。
平台治理可在归档或暂停域交接；普通负责人仍受只读 / 进入规则约束。

## Alternatives considered

- 每次启动选任意管理员覆盖负责人：会破坏人工交接，仅修复系统占位。
- 删除负责人时自动移交：没有明确治理目标和接受者，要求先显式交接。
- 只检查外键：软删除不触发外键，需要业务事务守卫及账号锁。
- 先删头像再检查关系：拒绝操作也会丢失资料，改为提交后清理对象。

## Consequences

workspace 27 项和 identity 312 项回归通过，identity 的 26 项跳过仍未计为通过。
覆盖真实管理员补入、不覆盖人工转交、自助 / 平台注销拒绝、资料保留、交接后
注销、成员名额释放和暂停域治理。core 类型检查通过；全量 PostgreSQL 结果
另行记录。没有连带删除 Domain、提交或版本，也不加入教师代建平台账号能力。
