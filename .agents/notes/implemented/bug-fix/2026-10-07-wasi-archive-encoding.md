# Agent Note: 固定 WASI 工具链来源归档封装兼容

Status: implemented

## Problem

固定 LLVM 提交的 codeload 下载归档摘要与旧构建配方不同，生产 runtime 镜像因此无法构建。直接替换已发布配方或忽略来源摘要都会破坏标准的可审查性。

## Decision

在临时目录用新归档重建，验证最终计量相关编译器、头文件、库和链接器逐文件摘要与冻结组件清单完全一致。另行记录同一提交的已验证归档封装摘要白名单，保留 v2/v3 配方、组件和计量清单原样。

下载只接受原摘要或精确白名单摘要；未知内容仍拒绝并删除临时下载。替代封装不能用于重新记录组件清单，重建产物必须匹配原冻结组件。CI 增加下载校验回归，缓存键纳入归档白名单。

## Alternatives considered

- 修改固定配方中的旧摘要：会使已经发布的标准来源记录改变。
- 忽略源码下载摘要：扩大构建信任边界。
- 只使用开发机现成 SDK：不能解决 CI 与生产构建入口。

## Consequences

归档封装兼容没有改变计量行为，最终组件一致性仍是交付硬门槛。将来新出现的归档摘要不能自动接受，必须再次重建验证；原生 Docker SDK 运行验收仍单独执行。
