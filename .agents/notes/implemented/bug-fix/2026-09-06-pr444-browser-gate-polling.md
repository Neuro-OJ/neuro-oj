# Agent Note: PR #444 浏览器门禁与竞赛轮询修复

Status: implemented

## Problem

浏览器提交用例在 judge 探测失败时成功返回，最新 CI 中错误答案用例实际跳过却
显示通过。探测代码可能快速进入错误终态，不能可靠代表真实提交链路的可用性。
竞赛管理页的轮询回调丢弃请求 Promise，使防重入锁提前释放；慢请求重叠时，
请求版本检查会持续丢弃旧响应。

## Decision

- 浏览器门禁直接提交正确与错误代码，依靠现有结果断言及 180 秒超时判定。 judge
  故障使测试失败，并通过既有 finally 路径保存 trace 和截图。
- 竞赛管理页的轮询回调使用 async/await，返回 Promise<void>，保留请求生命周期。
- 故障注入验证执行实际浏览器用例函数：结果等待抛错时，两条用例均拒绝并以
  failed=true 调用诊断清理；执行实际页面轮询回调及 usePolling，确认慢请求期间
  不重入，完成后恢复轮询。

## Alternatives considered

- 探测失败时直接抛错：仍依赖会误判的探测任务，可能阻止实际提交验证。
- 延长探测时间：不能解决错误终态被判不可用的问题，并增加额外评测任务。
- 放宽轮询回调类型但继续丢弃 Promise：无法恢复防重入语义。

## Consequences

浏览器门禁故障不会以跳过形式报绿；judge 无响应时最多等待现有结果超时。 既有 API
测试的 isJudgeAvailable 行为保持不变。竞赛管理页保持原有刷新间隔，
慢请求期间不叠加轮询请求。
