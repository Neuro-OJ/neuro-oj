# Agent Note: 正式判定反馈与登录前作答保留

Status: implemented

## Problem

OI 提交只显示生命周期，没有呈现正式判定、编译诊断和子任务成绩。
游客可输入代码，但登录会丢失输入；模板按钮会抛出未捕获的登录错误，空模板还会清空代码。
OI 编辑器补齐计分默认值后直接与原始 JSON 比较，导致打开草稿就误报修改。

## Decision

正式判定与评测完成状态分开呈现；仅展示服务端已裁剪的编译诊断和子任务。
隐藏模式不渲染结果，summary 不渲染子任务，资源撤销后不展示诊断和明细。
表单与修改基线使用同一份归一化载荷，文件保存沿用已经归一化的配置。
普通作答保存游客草稿；登录后只认领同域、同题、同版本、同语言的游客输入。
已有账号草稿优先，恢复游客草稿需要明确操作；不同账号不继承彼此内容。
游客模板按钮禁用，空模板保留输入并显示原因。语言选择展示可读名称。

## Alternatives considered

- 根据分数推断 AC：OI 达标分数与权威通过判定不是同一规则。
- 汇总模式也渲染原始 details：可能违反比赛明细裁剪要求。
- 登录后一律覆盖账号草稿：会丢失已有个人输入。
- 首次打开强制保存草稿以消除误报：会产生无意义修改和 revision。

## Consequences

使用现有评测和版本接口，不新增提交系统。草稿存储失败保留当前输入并提示复制。 UI
全组件测试 259 项和完整类型检查通过。
真实浏览器验证游客代码登录后保留、初次编辑无修改标记、直接预检通过，并通过实际
Judge 提交 `c50fdd9d-4d46-4bca-867c-99f3c2b9ca50` 验证 CE 判定和编译诊断，未出现
pageerror。
比赛隐藏、汇总与资源撤销的显示约束有组件回归测试；完整比赛旅程仍继续验收。
