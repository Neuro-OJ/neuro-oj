# Agent Note: 源题删除遵守版本与历史保留规则

Status: implemented

## Problem

旧题目删除服务会主动清除版本和终态提交，违反升级方案的历史保留规则。
新绑定和沿革外键虽然会阻止删除，但只依赖外键会返回 500，无法解释为何不能
删除源题，也不能确保所有旧历史情形在删除前得到明确保护。

## Decision

删除服务完成原有权限校验、锁住源题并检查在途评测后，使用同一事务检查已发布
版本、域绑定、正式代码 / 客观题提交及共享配置。存在任何保留引用时返回 409
及稳定错误码 SOURCE_HAS_RETAINED_REFERENCES，不清除草稿、版本、提交或对象。
未知提交时版本的旧记录同样受保护，不把缺少版本指针当作无历史。

没有版本、绑定或正式历史的未发布草稿仍可物理删除。
既有在途评测和比赛引用拒绝规则保持有效，权限不足在历史守卫之前拒绝。
受影响的版本删除测试改为验证拒绝及原内容保留，而非沿用旧清空行为。

## Alternatives considered

- 捕获外键错误再转为冲突：不能保护尚未建立绑定的旧版本和提交，也不解释业务依据。
- 忽略绑定强制级联删除：会丢失教学和本人历史，违背批准规则。
- 禁止全部删除：无历史草稿仍需要清理入口，按保留引用判断。

## Consequences

两个旧删除入口通过同一 catalog 服务遵守历史保护；管理员需使用受控停用流程
处理有历史源题，不能借旧入口物理清空。完整下架管理、旧读取入口切换和存储
生命周期仍在后续阶段实现。本次不删除数据库或对象存储中的任何历史记录。
