# Agent Note: 域业务页面统一与教学刷新状态保留

Status: implemented

## Problem

域提交列表和比赛列表偏离原版表格与卡片布局。教学请求刷新会将已有内容切换为
加载视图，卸载筛选、抽屉和反馈编辑区域；设置重新读取也可能覆盖未保存的配额。
旧学生 editor 链接尚未指向新的独立做题工作区。

## Decision

提交恢复紧凑表格，比赛和题单沿用原版容器、标题及卡片。提交摘要统一按服务器
结果可见性展示，隐藏结果只显示已受理，等待评测不伪造零分。管理标题操作允许
窄屏换行，题单共享导入收进独立展开区域。

教学页、我的学习和成绩矩阵刷新时优先保留已有数据。矩阵更新选中单元的最新
事实，保留侧栏及反馈草稿；账号或任务改变仍清除原选择。反馈、求助及回复使用
现有未保存保护。域设置统一保护基本配置及配额，后台刷新保留未保存配额，显式
重新读取时确认替换。移除已不存在的 Custom 类型文案。

旧学生 editor 入口固定跳转 main 的 solve；作者编辑仍使用域 editor。浏览器
旅程从阅读页点击开始编码或打开作答界面，随后操作实际工作区。

## Alternatives considered

- 每次刷新卸载内容：丢失正在处理的任务，改为保留数据并更新事实。
- 在所有组件重复增加状态缓存：会产生多套状态，使用现有组件本地状态和稳定挂载。
- 前端恢复隐藏分数：违反比赛规则，摘要始终服从服务器可见性。

## Consequences

刷新不再打断教师操作；显式切换账号、域或任务仍重新授权。基本设置与配额采用
统一离开确认，避免重复弹窗。未保存内容不在跨域间迁移。

验证：UI 283 项单元、291 项组件测试、完整 Nuxt/Vue 类型检查及 lint 通过。
组件用例覆盖刷新期间保留反馈输入、更新选中单元、账号切换清理和隐藏结果摘要。
core 全量标准并行测试通过；最终浏览器、构建与 CI 在完整实施清单继续记录。
