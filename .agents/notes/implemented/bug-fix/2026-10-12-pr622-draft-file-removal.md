# Agent Note: 草稿首次物化与主动删除文件的边界

Status: implemented

## Problem

复审复现：V1
绑定支持包，管理员删除草稿包后继续保存题面，旧包被重新绑定。`saveProblemDraft`
和 `saveProblemDraftWithObjects`
每次保存都会复制最新版文件引用，错误地把已有草稿的空引用当作尚未物化。新版本因此重新携带用户已删除的文件；OI
删除的逐文件引用也可能被补回，破坏逐文件快照与 ZIP 的一致性。

## Decision

在持有题目行锁的事务内先读取草稿并验证
revision。仅在草稿行不存在时继承最新版基线引用；已有草稿的引用集合以草稿本身为准，包括主动清空的集合。

扩展支持包回归，覆盖“发布 V1 → 删除草稿包 → 继续编辑题面 → 发布 V2”：V2 无包，V1
包仍可下载、物理字节仍保留。OI 回归覆盖把 V1 的 `1.in/1.out` 替换为 V2 的
`2.in/2.out` 后继续编辑题面，逐文件集合与实际 ZIP 一致，V1
数据仍可读取。既有首次物化继承回归继续保证迁移基线不会丢文件。

## Alternatives considered

- 引用表为空就继承基线：拒绝，空集合是用户删除全部文件后的合法草稿状态。
- 保存时总是合并基线引用：拒绝，会复活删除内容，也会使 OI 的逐文件集合与新 ZIP
  不一致。
- 删除旧版本对象来防止引用复活：拒绝，历史版本必须保持可重测和可下载。

## Consequences

首次物化继续继承基线，后续编辑保留用户的文件增删。历史版本引用和共享对象留存不变；不需要
schema 迁移。
