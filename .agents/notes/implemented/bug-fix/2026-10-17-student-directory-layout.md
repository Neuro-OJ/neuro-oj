# Agent Note: 学生训练目录改为连续名单布局

Status: implemented

## Problem

学生训练目录将同一份名单拆成两列独立卡片，反复展示首字母头像、状态徽章和边框按钮。教练需要左右跳读才能查找学生。手机端的班级导航换行、独立筛选面板和重复卡片进一步推迟名单的出现位置。

## Decision

本页属于教学操作界面，优先支持“筛选学生 → 扫描名单 → 进入训练详情”。保持 NOJ 的颜色、字体、页面标题及已有授权逻辑。

- 将筛选和名单放进同一个白色面板，以分隔线区分控件、列说明和学生行。
- 桌面按学生、成员状态、训练入口对齐。名单使用语义列表，每行一个真实详情链接，保留当前域和班级上下文。
- 手机将成员状态放在姓名下方，保留右侧训练入口；整行支持鼠标、触摸与键盘进入，并提供可见焦点。
- 去掉重复的首字母头像与逐行边框按钮。桌面实际行高 56px，手机实际行高约 76px。
- 手机将成员范围和结果数量放在同一行；名单加载失败时不显示误导性的零人数。
- 班级导航保持单行，窄屏允许横向滚动，不占用第二行。

## Alternatives considered

- 继续调整两列卡片的间距：无法改变左右跳读以及重复操作外框的问题。
- 增加学生训练指标：本页接口只提供成员信息，布局调整不引入未提供的统计或额外查询。
- 完整数据表：当前内容只有身份、成员状态和一个详情操作，使用响应式列表可以保持手机端的阅读顺序和可点击范围。

## Consequences

不修改后端、权限、搜索规则、成员范围或学生训练页面。共享班级导航仅调整窄屏排列方式，既有能力检查与链接保持不变。

布局检测前后均无未解释发现。342 项组件测试、格式、Lint 和生产构建通过。独立 Chromium 会话验证 1440px、768px、390px 的真实名单，覆盖搜索、空态重置、历史范围、键盘进入详情、失败重试及学生权限；窗口均无水平溢出、浏览器运行异常为 0。另通过浏览器响应夹具验证 40 名长用户名学生，夹具不写入数据库。

截图和测量记录保存在本地 `/tmp/noj-student-directory-layout/`，不提交开发验收产物。
