# Agent Note: 修复 PR #483 E2E CI 五处失败

Status: implemented

## Problem

测试增强路线图 PR #483 的 E2E CI 有四个 job 失败、一个 job 长时间卡住后失败，
且失败原因彼此独立：

- **E2E Rate Limit（13m48s 后失败）**：`docker-compose.e2e.yml` 只把
  `RATE_LIMIT_ENABLED` 注入 noj-core，未注入 `RATE_LIMIT_LOGIN_IP_MAX` /
  `RATE_LIMIT_LOGIN_ACC_MAX` / `RATE_LIMIT_LOGIN_BACKOFF_SEC`。`e2e-rate-limit`
  job 的放宽参数因此从未生效， 失败退避按注册表默认 15s 逐次累加，10
  次错误密码耗时约 13min；用例查 Redis 时又用 username 且未指定 DB（默认 DB
  0），而锁定 key 经 NOJ-092 归一化为 `loginlock:<users.id>` 且位于 DB
  1，断言必然 `EXISTS 0`。
- **Judge Sandbox E2E**：`support_package_missing_still_finished` 的 evaluator
  命令用 `sys.stdout.write('---RESULT---\n')` 输出换行，但 judge 的
  `parse_command` 会消费反斜杠转义（单引号内同样消费），`\n` 被吞成 `n`， RESULT
  标记与 JSON 粘连，结果被映射为 `error` 而非 `finished`。
- **E2E contest**：`anti_cheat_abnormal` 对整段 SSE 缓冲区断言不含
  `"user_id"`，但连接建立时先推送的 `contest:ranking:snapshot` 榜单快照合法 携带
  `user_id`，断言把非提交事件也算作泄漏。
- **E2E submission**：`mq_invalid_message` 向题 1001 提交 `print(1)`，该题
  evaluator 调用 `solve()`，未定义 `solve` 会被判运行期错误（`status=error`）；
  同时 `redisCli` 未指定 `-n 1`，毒消息被 LPUSH 到 DB 0，judge 消费 DB 1，
  用例对毒消息的断言退化为空断言。
- **E2E Cross Domain**：`storage_failure` 用普通用户 `ownerToken` 提交 admin 经
  `import-bundle` 创建的私有 U 型题，`resolveProblemAccess` 按 owner/admin
  判定返回 403。

## Decision

- `docker-compose.e2e.yml` 的 noj-core 显式转发登录限流四个参数 （`IP_MAX` /
  `ACC_MAX` / `BACKOFF_SEC` / `LOCK_THRESHOLD`），默认值与注册表 默认一致，其他
  E2E 域行为不变。
- `rate_limit_lockout` 先取 `/api/v1/auth/me` 的 `users.id`，再用
  `redis-cli -n 1 EXISTS loginlock:<userId>` 断言服务端锁定状态。
- judge 异常场景用例改用 `print('---RESULT---')` + `print(json.dumps(...))`
  输出，避免依赖反斜杠转义。
- 反作弊 SSE 用例新增 `extractSseEventData`，只对 `contest:submission:created`
  事件的 data 断言不含 `user_id`。
- `mq_invalid_message` 改用 `CODE_SAMPLES.accepted` 提交，并让 `redisCli` 固定
  `-n 1`，使毒消息真正进入 judge 消费的队列与 DB。
- `storage_failure` 改用 admin 身份向损坏题目提交（该题 owner 即 admin），
  并清理因此不再使用的 `ownerToken` / `PROBLEM_ID` 与相关 import。

## Alternatives considered

- **改 judge `parse_command` 支持单引号内反斜杠字面量**：这是更彻底的产品修复，
  但会改变既有 evaluator 命令的分词语义，影响面超出本次 CI 修复；本次让测试 使用
  parser-safe 命令。
- **改 SSE 实现去掉榜单快照的 `user_id`**：榜单快照的 `user_id` 属既有契约，
  泄漏面是提交事件；本次只收紧测试断言，不改读路径。
- **让普通用户可提交私有题 / 把导入题改为公开**：会改变题目可见性语义；
  用例目的只是验证“存储故障不阻塞提交创建”，用题目 owner（admin）提交即可。
- **接受 rate-limit 用例慢跑**：13min 占用 runner 且最终失败，必须让 job 设置的
  限流参数真正到达容器。

## Consequences

- 本地完整 E2E 栈复现全部通过：rate-limit 568ms、anti-cheat 211ms、
  storage-failure 147ms、mq-invalid 2s；judge sandbox 用例 1.68s 通过。
- 毒消息现在会真正进入 DB 1 并在 judge 处理后写入
  `noj:judge:queue:medium:dead`，MQ 容错用例不再是空断言。
- 其他 E2E 域的限流默认值与注册表默认一致，行为不变。
