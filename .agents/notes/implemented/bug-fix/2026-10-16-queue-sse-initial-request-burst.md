# Agent Note: 消除队列首次订阅的历史通知请求风暴

Status: implemented

## Problem

队列 SSE 在发送初始失效通知后，又从游标（首次连接默认为 0）重放最多 200 条历史
`queue:changed`。页面每收到一条便读取当前队列，打开页面和重连都会产生密集的
重复 REST 请求。回归测试预置每频道 200 条历史记录，旧代码返回 202 条通知，
其中只有初始校准与测试期间新增的实时通知有必要。

## Decision

队列 SSE 每次连接只发送一次初始失效通知，并继续订阅实时变化。初始通知会触发
完整当前状态读取，已覆盖断线期间的全部变化，因此不再逐条重放历史失效通知。
三个入口（默认域兼容、显式域、实例）共用修复，实时推送仍重新验证当前访问权。
提交详情和其他有独立重放语义的 SSE 不受影响，前端断线轮询保持现有行为。

## Alternatives considered

- 只在前端防抖或限制并发：不能消除服务端无意义的历史发送和逐条鉴权，掩盖根因。
- 只跳过没有游标的首次连接：重连仍会逐条重读相同当前状态，问题依旧存在。
- 删除共享 SSE 重放能力：其他订阅未必只有失效信号，不扩大改动范围。

## Consequences

无需迁移、清理历史数据或引入新的进程内状态。请求数量不再随保留的队列事件数增长。
页面初始加载和 SSE 初始通知可能各产生一次正常读取，后续只在实时变化、手动刷新或
断线降级时读取。

路由测试使用隔离数据库预置 400 条历史记录，覆盖三个入口及首次连接、请求头游标、
查询参数游标九种组合；每种组合都断言仅收到一次初始通知和一次真实的新通知。
浏览器回归在域与实例范围各观察超过现有 2 秒轮询周期，断言首次读取最多两次，
并验证手动刷新恰好增加一次请求。完整 submission 测试和标准 API 场景另作回归。

本地验证：core 完整格式、lint、类型检查通过；submission 域 384 项通过、41 项
按既有环境条件跳过，前置迁移和种子 8 项通过；新增九组合 SSE 测试实际执行通过。
设置 API 场景和完整设置浏览器场景均通过，浏览器记录当前域、实例初始请求各 2 次。
仓库门禁及其 217 项自测通过；静默跳过数量未增加，报告仅更新既有测试行号。
