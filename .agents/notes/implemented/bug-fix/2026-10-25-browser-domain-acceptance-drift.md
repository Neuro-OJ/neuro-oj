# Agent Note: Domain 浏览器验收契约漂移收敛

Status: implemented

## Problem

新 Domain UI 的响应式入口、题目页重复 CTA、设置表单脏状态、班级成员分页和
配额按钮文案已经变化，浏览器验收仍按旧 DOM 假设定位，导致 CI 在真正业务断言之前
因隐藏节点、严格模式多匹配或错误分页而失败。部分测试还把成功重载后的干净表单当成
应立即可保存，未验证真实写入前必须重新编辑的合同。

## Decision

- 搜索验收在桌面视口直接使用 `Control+K`，不等待仅在窄屏菜单可见的链接。
- 题目作答入口明确选取第一个同 href 的“开始编码” CTA，保留真实导航与提交断言。
- 设置成功重载后重新编辑简介，再断言保存按钮可用；失败重载仍断言保留草稿且写入禁用。
- 班级 CSV 验收先切换到“批量导入与邀请”标签，再检查文本框和真实上传链路。
- 配额验收使用 UI 当前的“保存配额配置”文案。
- 预测结果页按结果卡片中的数值定位（“得分”标签与数值是相邻节点，分数单位不在
  数值节点内）。
- LLM CAS 验收检查 Core 对 Gateway 冲突的稳定提示“LLM 资源已修改，请重新读取”，
  同时继续核对 `If-Match`、409 和数据库中的新映射。
- 公共题单验收按当前整卡链接和标题定位，不依赖已经移除的“查看题单”子链接。

## Alternatives considered

- 放宽为 `getByText`、删除可见性断言或用 `nth()` 绕过所有严格模式失败：放弃，
  这会降低对可见入口和业务状态的覆盖。
- 修改生产 UI 恢复旧文案/重复入口：放弃，验收应跟随已发布的 Domain 交互合同，
  不为旧测试保留不必要的兼容节点。

## Consequences

浏览器验收现在检查用户可见的 Domain 页面状态和真实写入前提，同时保留提交、导入、
并发冲突等负向断言。新 CI 仍需确认未处理的 input mode、LLM governance、公共题单
和教学流程失败是否为独立行为问题。
