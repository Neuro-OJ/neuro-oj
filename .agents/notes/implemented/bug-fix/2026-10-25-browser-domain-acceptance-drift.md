# Agent Note: Domain 浏览器验收契约漂移收敛

Status: implemented

## Problem

新 Domain UI 的响应式入口、题目页重复 CTA、设置表单脏状态、班级成员行结构、
配额按钮文案和题单/题目导航已经变化，浏览器验收仍按旧 DOM 假设定位，导致 CI 在
真正业务断言之前因隐藏节点、严格模式多匹配、旧文案或错误容器层级而失败。部分测试
还把成功重载后的干净表单当成应立即可保存，或在导航保护触发后直接等待 URL。

## Decision

- 搜索验收在桌面视口直接使用 `Control+K`，不等待仅在窄屏菜单可见的链接。
- 题目作答入口明确选取第一个同 href 的“开始编码” CTA，保留真实导航与提交断言。
- 设置成功重载后重新编辑简介，再断言保存按钮可用；失败重载仍断言保留草稿且写入禁用。
- 班级 CSV 验收先切换到“批量导入与邀请”标签，再检查文本框和真实上传链路。
- 配额验收使用 UI 当前的“保存配额配置”文案。
- 预测结果页按结果卡片中的数值定位（“得分”标签与数值是相邻节点，分数单位不在
  数值节点内）。
- LLM CAS 验收检查 Core 对 Gateway 冲突的稳定提示“LLM 资源已修改，请重新读取”，
  同时继续核对 `If-Match`、409 和数据库中的新映射。
- 公共题单验收按当前整卡链接和标题定位，不依赖已经移除的“查看题单”子链接。
- 设置页编辑后离开先确认“未保存的修改”，再等待邀请页导航，显式覆盖离开保护合同。
- 班级成员按带 `transition-colors`
  的成员行收敛用户名与右侧“调整身份”操作，不依赖 内部 div 层数。
- Domain 题目页使用当前“打开界面” CTA；提交结果按独立的分数胶囊定位，不再寻找
  已移除的“评测结果”标题。
- 教学矩阵的评测沿革请求与“客观题”面板点击用 `Promise.all` 绑定，失败时由当前
  step 消费响应等待，避免悬空 `waitForResponse` 拒绝污染整次测试。
- 其余真实写入辅助函数也统一用 `Promise.all` 绑定动作与响应，防止 UI 定位失败时
  留下未消费的响应等待器；当前配额、归档、班级研练和界面题入口均跟随实际可见
  文案与导航（“保存配额配置”“归档此班级并保留历史”“班级研练”及重复 CTA 的
  首个入口）。
- 配额页面先以当前配置为基线，再通过真实字节输入产生 dirty
  草稿后保存；班级成员、 教学班级创建和归档只使用当前 UI
  的“保存身份配置”“创建并进入班级”及完整只读 提示，跨域题号断言扩大到
  `ProblemHeader` 的可见区域而不依赖 h1 父层级。
- 配额输入按实际 `WorkspaceLimitFields` 可访问名称“存储上限”定位；助教反馈先
  切换“反馈与求助”标签并打开“写反馈”表单再填写正文；公共同源题号收敛到包含当前标题的
  `main header`；教师进入成员页只从 `班级导航` 中选择链接，消除页面动作按钮与
  导航链接的严格模式冲突，并先切换“批量导入与邀请”标签再选择指定邮箱。
- 班级矩阵的筛选控件默认收起，验收先打开“筛选”再选择完成状态；作业生命周期
  操作默认收进“发布与设置”抽屉，发布 helper 先打开该抽屉再确认“发布作业”。
- 矩阵学生搜索按实际 `aria-label="搜索学生用户名"` 定位；教学作业发布确认后
  重新进入作业详情再刷新成绩，避免把发布抽屉后方的隐藏矩阵按钮当成可见状态。
- 矩阵搜索使用当前输入框的 Enter 提交，统计范围使用“统计范围”按钮组，历史
  学生筛选重新打开收起的筛选面板；教学求助/反馈先进入“反馈与求助”标签并分别
  打开“向老师求助”“写反馈”表单，再点击“发送求助/发送反馈”。
- 矩阵导出按当前按钮的完整可访问名称“导出当前筛选结果为 CSV”触发，覆盖按时、
  当前补做和历史学生三种筛选结果；求助状态按“反馈与求助”区内同时包含正文与
  状态文本的可见卡片定位，避免将分散的内部节点拼成不稳定的严格角色名称。
- 窄屏矩阵按当前 `ul[aria-label="学生成绩摘要"]` 的学生行先展开，再点击带学生、
  题号和“未开始”状态的题目单元格；求助卡片则从正文按钮的父卡片读取旁邻状态，
  适配正文与“待处理/已处理”分属不同 DOM 节点的实现。
- 作业详情的“派生新作业”已收进“管理作业”抽屉；补题验收先打开可见的管理入口，
  再在该抽屉内点击“为全班未达标学生布置补题”，不再把抽屉内的隐藏节点当作页面入口。
- 教师刷新作业详情后，先等待真实“学生成绩矩阵”表格恢复，再切换“反馈与求助”标签，
  覆盖任务、班级和权限数据分开加载时的水合竞态。
- 补题草稿创建会导航到新的草稿详情页，验收在该页重新打开“发布与设置”抽屉后发布；
  学生刷新后按角色默认回到“题目与进度”，验收重新切换“反馈与求助”再读取反馈和已处理求助。
- 班级设置页当前交接按钮文案为“确认交接”，补题创建响应后的教学页验收绑定新草稿
  URL 并等待水合完成后再读取标题，避免把异步导航和旧页面误报为业务失败。
- 接任教练重新读取原作业反馈前切换到“反馈与求助”标签；学生从班级作业列表进入新建补题，
  不把列表页误当成作业详情页，保持“页面入口→详情状态”的真实用户路径。
- 教学窄屏矩阵和课堂矩阵共用 `ul[aria-label="学生成绩摘要"]` mobile contract；旧
  `div.sm:hidden` 不存在，按学生行先展开再选 cell。

## Alternatives considered

- 放宽为 `getByText`、删除可见性断言或用 `nth()` 绕过所有严格模式失败：放弃，
  这会降低对可见入口和业务状态的覆盖。
- 修改生产 UI 恢复旧文案/重复入口：放弃，验收应跟随已发布的 Domain 交互合同，
  不为旧测试保留不必要的兼容节点。

## Consequences

浏览器验收现在检查用户可见的 Domain 页面状态和真实写入前提，同时保留提交、导入、
并发冲突等负向断言。本轮继续只调整验收契约和等待器，需由下一轮 Browser CI 证明
窄屏矩阵、求助生命周期和补题导航均已收敛，且没有真实业务回归。
