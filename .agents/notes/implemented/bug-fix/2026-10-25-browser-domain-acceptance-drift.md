# Agent Note: Domain 浏览器验收契约漂移收敛

Status: implemented

## Problem

新 Domain UI 的响应式入口、题目页重复 CTA、设置表单脏状态、班级成员行结构、
配额按钮文案和题单/题目导航已经变化，浏览器验收仍按旧 DOM 假设定位，导致 CI 在
真正业务断言之前因隐藏节点、严格模式多匹配、旧文案或错误容器层级而失败。部分测试
还把成功重载后的干净表单当成应立即可保存，或在导航保护触发后直接等待 URL。

## Decision

- 搜索验收在桌面视口直接使用 `Control+K`，不等待仅在窄屏菜单可见的链接。
- 题目作答入口明确选取第一个同 href 的“开始编码” CTA，保留真实导航与提交断言。
- 设置成功重载后重新编辑简介，再断言保存按钮可用；失败重载仍断言保留草稿且写入禁用。
- 班级 CSV 验收先切换到“批量导入与邀请”标签，再检查文本框和真实上传链路。
- 配额验收使用 UI 当前的“保存配额配置”文案。
- 预测结果页按结果卡片中的数值定位（“得分”标签与数值是相邻节点，分数单位不在
  数值节点内）。
- LLM CAS 验收检查 Core 对 Gateway 冲突的稳定提示“LLM 资源已修改，请重新读取”，
  同时继续核对 `If-Match`、409 和数据库中的新映射。
- 公共题单验收按当前整卡链接和标题定位，不依赖已经移除的“查看题单”子链接。
- 设置页编辑后离开先确认“未保存的修改”，再等待邀请页导航，显式覆盖离开保护合同。
- 班级成员按带 `transition-colors`
  的成员行收敛用户名与右侧“调整身份”操作，不依赖 内部 div 层数。
- Domain 题目页使用当前“打开界面” CTA；提交结果按独立的分数胶囊定位，不再寻找
  已移除的“评测结果”标题。
- 教学矩阵的评测沿革请求与“客观题”面板点击用 `Promise.all` 绑定，失败时由当前
  step 消费响应等待，避免悬空 `waitForResponse` 拒绝污染整次测试。
- 其余真实写入辅助函数也统一用 `Promise.all` 绑定动作与响应，防止 UI 定位失败时
  留下未消费的响应等待器；当前配额、归档、班级研练和界面题入口均跟随实际可见
  文案与导航（“保存配额配置”“归档此班级并保留历史”“班级研练”及重复 CTA 的
  首个入口）。
- 配额页面先以当前配置为基线，再通过真实字节输入产生 dirty
  草稿后保存；班级成员、 教学班级创建和归档只使用当前 UI
  的“保存身份配置”“创建并进入班级”及完整只读 提示，跨域题号断言扩大到
  `ProblemHeader` 的可见区域而不依赖 h1 父层级。

## Alternatives considered

- 放宽为 `getByText`、删除可见性断言或用 `nth()` 绕过所有严格模式失败：放弃，
  这会降低对可见入口和业务状态的覆盖。
- 修改生产 UI 恢复旧文案/重复入口：放弃，验收应跟随已发布的 Domain 交互合同，
  不为旧测试保留不必要的兼容节点。

## Consequences

浏览器验收现在检查用户可见的 Domain 页面状态和真实写入前提，同时保留提交、导入、
并发冲突等负向断言。最新 CI 已确认 LLM governance 与其余跨域服务端链路通过；本轮
仅调整验收契约和等待器，仍需重跑
Browser，确认剩余时序/导航契约收敛且没有真实业务 回归。
