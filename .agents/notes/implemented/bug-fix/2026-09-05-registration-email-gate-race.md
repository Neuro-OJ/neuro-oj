# Agent Note: 首次注册邮件门槛的事务内校验

Status: implemented

## Problem

邮件关闭且没有真实用户时，并发注册请求会同时通过路由层预检。原有事务锁只保证首个用户获得管理员角色，不能阻止其他请求创建无法验证邮箱的普通账号。

## Decision

保留路由层快速拒绝，在注册事务内完成首次用户判定后、插入用户前再次检查邮件就绪状态。只有事务确认的首个真实用户可以使用引导例外。同步 main 时保留注册页的数据说明链接和注册受限提示。

## Alternatives considered

- 仅保留路由预检：实现简单，但检查与写入之间存在竞态。
- 对全部注册请求新增全局锁：可以串行化请求，但邮件已就绪时没有必要，增加争用。

## Consequences

复用现有首次注册事务锁，不修改数据库结构。并发回归测试关闭外层测试事务隔离，分别验证 disabled 时仅一个管理员注册成功、另一个返回 403，以及 mock 时两个用户均成功且只有一个管理员。测试切换 Provider 时同时重置发信缓存，避免实际发送与配置不一致。
