# Agent Note: 整体撤回 #776（UI 目录重组、设计系统收口、统一 4 格缩进）

Status: implemented

## Problem

#776 用 squash 合并了三组性质不同的改动：noj-ui 目录按领域重组、设计系统收口（圆角
token、色板、`check-ui-guards` 门禁），以及全仓从 2 格改为 4 格缩进。合计 2330 个文件，
其中约 2000 个只有缩进变化。

缩进改动没有功能收益，却带来了实际成本：

- 和并行 PR 大面积冲突（与 #778 合并时有 21 个冲突）；
- `.editorconfig` 被 LMCC 扩展的 Prettier 读到，LMCC 的 CI 因此失败；
- 4 格下多出的折行让静默跳过扫描器漏计；
- 因为是 squash 合并，格式化和真实改动混在同一个提交里，无法单独登记到
  `.git-blame-ignore-revs`，`git blame` 基本失效。

## Decision

对 #776 的 squash 提交 `db973c90` 执行 `git revert`，代码树与 #776 合并前的 `main`
（`a1509c80`）逐字一致。撤回时 `main` 在 #776 之后没有新提交，因此不存在冲突。

目录重组和设计系统收口由作者拆分后重新提交，每个 PR 只包含一类改动，不再夹带全仓格式化。
如果之后仍想统一缩进，应单独开 PR，用非 squash 方式合并，并登记到 `.git-blame-ignore-revs`。

## Alternatives considered

- 只撤回缩进、保留其余改动（#783，已关闭）：能保住目录重组和设计系统，但撤回提交与
  #776 交织，blame 只能部分恢复；与其在一个混合提交上做外科手术，不如整体撤回后拆分重做。
- 维持现状：缩进带来的冲突、工具链和 blame 成本会持续存在。

## Consequences

- 以下改动随撤回一起离开 `main`，需要作者在新 PR 中重新提交：noj-ui 目录重组、
  设计系统门禁与基线、领奖台名次对比度修复，以及两轮评审中的 8 个修复（seed 引导凭据
  先交付再落库、测试凭据隔离、题解关联题目搜索慢一拍、旧地址重定向保留查询参数和
  大小写规范化、设计门禁跨分支棘轮、静默跳过扫描器识别跨行调用、Tailwind 默认
  圆角与色板规则）。
- 在 #776 之后基于 `main` 开的分支，需要先 rebase 到撤回后的 `main`。
- 撤回提交和 #776 都可以登记到 `.git-blame-ignore-revs`：两者合起来净效果为零，
  blame 可以干净地穿透。
