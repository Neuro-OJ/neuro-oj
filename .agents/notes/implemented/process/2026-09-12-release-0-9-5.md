# Agent Note: 0.9.5 稳定版发布准备

Status: implemented

## Problem

SNG 当前运行 `v0.8.1`，需要一个可被生产安装器识别的稳定版本；直接使用尚未完成真实
预发布验收的 1.0 RC 会混淆版本承诺，且主分支存在 UI 类型检查阻断。

## Decision

基于最新 `main` 创建 `v0.9.5` 发布分支，统一各模块版本元数据，补齐 UI 类型导入，
并通过 Release workflow 的预发布触发机制构建镜像、CLI 资产、校验文件和安全证明，
由工作流在资产全部就绪后自动转正。

## Alternatives considered

- 直接把 `v0.9.5` 标记到现有 `main`：会保留版本不一致和 UI 检查失败，未采用。
- 直接发布正式 Release：会绕过工作流的构建与安全门禁，可能产生没有同版本镜像或 CLI
  资产的 Release，未采用。

## Consequences

`v0.9.5` 可作为 `v0.8.1` 到 1.0 之间的稳定过渡版本；SNG 升级前仍需确认备份口令、
执行备份并安排维护窗口，且当前 SNG 资源低于正式生产建议。
