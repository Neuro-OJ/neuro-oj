# Agent Note: noj-cli 重写的验收取证与一处退出码缺陷

Status: implemented

## Problem

26 个 Task 的实现全部完成后，需要一个**可复核的交付判据**。此前的证据散落在各
Task 的 Agent Note 与测试名里，无法回答两个问题：

1. "spec §8 的每条验收，**现在**到底过没过？"——需要可执行的复核命令，而不是叙述；
2. "有哪些事**没有**验证？"——未取证项如果不显式标注，会被读者默认当成已通过。

另外，取证必须**用交付物本身**（编译产物），而不只是测试。这一点立刻见效：用
`deno compile` 的二进制实测时发现了一个测试覆盖不到的缺陷（见下）。

## Decision

产出三份文档，**判据是"另一个工程师能否仅凭它复现结论"**：

1. **验收证据**（`2026-09-19-noj-cli-rewrite-evidence.md`）：逐条对照 spec §8 的
   L0/M/R1–R7，每条给**判定 + 可执行复核命令 + 实测输出关键行**。
2. **待人工 review 清单**（`2026-09-19-noj-cli-manual-review.md`）：每条给
   **判定动作 + 期望结果 + 不通过的后果**，而不是需要 reviewer 猜测的判断题。
   按"需判断裁决是否合理 / 需核对边界 / 文档"三档排序，并给出建议的 review 顺序。
3. **进度日志追加**（`progress-log.md`）：与既有 24 小时目标**分开一节**（它们
   是不同的目标），记录规模变化、发现的真实缺陷、spec 矛盾与未取证项。

同时修掉取证中发现的一个**真实缺陷**（单独提交，不混入证据文档）。

## Alternatives considered

- **只写"全部通过"的总结**：无法复核，且会掩盖未取证项。改为每条附命令与输出。
- **把发现的缺陷混进证据文档**：会让"证据"与"修复"耦合——reviewer 无法单独
  判断修复是否正确。按计划要求，发现缺陷**单独提交**。
- **沿用既有 `progress-log.md` 直接追加而不分区**：该文件明确声明是
  **2026-09-11 那个 24 小时目标的时点快照**，且"不是持续维护的看板"。把另一个
  目标的记录混进去会让两者都失真。故新增独立小节并标注"不同目标"。
- **信任测试全绿即宣称 R1 达成**：测试只覆盖被测试触及的路径。改用**编译产物**
  在独立目录实测（`/tmp`，无仓库脚本），这才发现下面的退出码缺陷。
- **把 `deno compile` 体积当作"已对照基线"**：基线没有该数值，无法比较。
  文档中如实标注"只有现状值，无基线可比"，而不是留一个看似完整的表格。

## Consequences

**取证的直接产出——一个真实缺陷（已修）**：

```text
status --dir /nonexistent                 → 2   ← 修复前
status --profile prod --dir /nonexistent  → 1
```

同一次失败、同一句文案、退出码不同。根因是 profile 探测先于生产分发抛
`UsageError`(2)，而显式 `--profile prod` 跳过探测后由 `findProductionDir` 抛
`ProductionDirError`(1)。这同时违反两处既有契约：T24 计划（`1371`/`1387` 行）
与 `production.ts` 的文档都写明"目录定位失败 → 1"；bash 侧对同类错误也用
`exit 1`。修法：生产命令跳过 profile 探测（探测的用途在单模态下已与
`findProductionDir` 重合），目录判定完全交给生产分发。

**其余交付**：

- 验收证据覆盖 spec §8 全部条目；**7 项未取证**逐条列出前置条件与补做方式
  （真实 Release 端到端、最小环境、真实 Docker 演练、rootless daemon、
  parity 映射表、真实 `pg_dump`、窄终端）。
- review 清单把三处**需要人判断**的事项前置（两处 spec 自相矛盾 + 备份门禁
  是否达到设计意图），而不是埋在文档末尾。
- 诚实标注一处设计裁决的代价：`.nojbackup` 的整包摘要因自指不可能而落在
  sidecar，因此**只能检测意外损坏、不能检测篡改**——reviewer 需要知道这一点。

**规模计量修正**：文档初稿里我凭印象写了脚本行数（`deploy.sh` 1187、
`backup.sh` 约 900）与二进制体积（106 MB），实测分别为 1216 / 443 / 101.9 MB。
已按实测改正——**取证文档里的估算数字与编造证据等价**。
