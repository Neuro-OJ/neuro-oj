# Agent Note: Domain 资源隔离与比赛保密

Status: implemented

## Problem

引入 Domain 后，比赛种类、资源可见性、跨域共享许可和使用域版本策略叠加，导致同一题在题库、作业与比赛入口的读取和提交规则不一致。旧共享引用还让来源撤销影响目标域日常教学。

## Decision

- Domain 作为资源访问边界，域角色管理编辑与发布；题目和题单不再按用户库、公开库或资源可见性隔离。私信、反馈、他人代码与答案、测试数据和 Provider 凭据保留业务权限。
- 完整继承 `nwulqqszwvpmkwrwkytxxsnsqrtxozmn` 的提交及祖先，包括竞赛作答工作区、公共作答面板、同伴学习与教学比赛发现入口。
- 比赛统一报名，不再依赖公开赛、邀请赛或比赛密码。`secrecy_enabled` 默认开启，开赛前可修改，开赛后锁定。
- 保密从题目加入比赛起到比赛结束，覆盖全部历史版本。列表保留元信息和斜纹标记；普通正文请求返回含比赛入口的 403，域不可见仍为 404。管理者可预览编辑，但不能走普通入口提交或自测。
- 正在进行的合法比赛上下文只读取本场固定版本；已结束比赛不能绕过其他未结束比赛的保护。成绩、封榜与正式快照策略保持独立。
- 跨域复用复制所选发布版本为目标域独立已发布 V1，分配本地题号，复制文件但不复制来源历史、学生记录及 Provider 身份。来源编辑/导出与目标创建/发布权限同时检查，目标 LLM 别名必须存在。题单递归复制去重并原子创建。
- 有效版本策略归题目所有，删除绑定表重复的实时策略字段。题库、作业及成绩投影使用统一策略，比赛保留自身固定版本。
- RC 尚未部署，不建立旧共享业务数据迁移；Schema 变更由工具追加生成，使用新建隔离数据库验证。

## Alternatives considered

继续保留邀请赛、资源公开范围与实时跨域引用会形成多套叠加授权，难以解释同题在不同入口的行为。只在前端隐藏提交按钮无法保护文件、历史版本、搜索与直接 HTTP 请求。按赛期调度翻转题目状态会增加多副本一致性负担，因此使用请求时的数据库事实判定。

## Consequences

目标域负责独立副本的维护和后续发布，不会自动同步来源更新。比赛元信息可见，但受保护正文及普通作答必须统一经过服务端门控。本人原提交与成绩通过私人历史权限保留，不能借此恢复题面或他人评测输出。测试设施使用任务专属 PostgreSQL、Redis 和临时存储，不改动现有测试站或生产服务。

题目编辑授权和提交删除抽为独立服务文件，保留原有导出接口，并移除已降到阈值以下的题目 CRUD 行数基线。

隔离数据库完整回归：题库 412、评测 491、访问控制 403、教学 146、比赛 126、搜索 87 项通过，教学与搜索各保留 1 项原有跳过项。文件拆分后的题目 CRUD、草稿与授权回归另有 65 项通过。前端单元测试 320、组件测试 388、工程门禁 251 项通过；Core/UI 类型检查、前端生产构建、严格模块边界、格式与 lint、迁移安全及快照链通过。这些是本地隔离验证，不代表生产部署或真实 Provider 调用验收。
