# Agent Note: 主线题包上传与显式使用域契约整合

Status: implemented

## Problem

最终验收期间 main 合入 #641，新增网页题包直接建题和 `noj-cli problem push`。
主线接口和文案仍使用全局题库、P/U 分类及单次上传中的 publish 标记，与已确认的
域内编号、权限和草稿发布契约不一致。

## Decision

保留 #641 提交作为合并父提交，接入共用 ZIP 选择组件、题包导入页面和 CLI push。
新功能明确请求 `/api/v1/domains/:slug/problems/import-bundle`；返回草稿后，发布
另行使用域内题号和 `If-Match: draft_revision`，不假定上传表单标记会自动发布。
失败仍返回实际错误，已经导入的草稿保留。

域内新建页提供直接导入入口并跳转同域编辑器。旧新建页面和平台管理快捷入口
明确进入 main；CLI `--domain` 默认 main，不读取浏览器偏好。移除新主线工具中的
P/U 分支，文档采用 `(domain_id, number)` 定位与域角色授权。

原有 core 域导入已经支持未发布题目的草稿更新，保留该实现，接入 #641 新增的 真实
HTTP 回归并将夹具改为数字题号、无 type 分类。业务 core 源码与最终签名
版本逐字节相同，既有 core 正式构建仍适用。

## Alternatives considered

- 使用旧全局导入接口：只能进入默认域，不能实现指定域推送。
- 服务端增加第二套上传并发布机制：已有草稿／发布接口足够，客户端直接组合。
- 为新建入口自动获取已有题目的 revision 并覆盖：缺少编辑者确认，不采用。

## Consequences

CLI 标准测试 767 项通过、4 项环境专属忽略，格式／lint／类型检查及正式编译通过。
UI 标准单元 283 项、完整组件 250 项通过，Nuxt/vue-tsc 类型检查通过。 core 标准
catalog 题包范围 22 项通过，初始化 8 项通过；包含新建未发布题目 上传支持包、缺
revision 拒绝和保存后原 ID 不变。

最新正式 UI 构建实际成功，普通域负责人 Browser 题包用例实际 1 项通过：分别
导入未发布草稿和显式发布 V1，确认同域原题 ID、数字题号及编辑跳转。未发布题目
版本列表按现有授权返回 404；新夹具以该契约断言，没有放宽资源可见性。
新用例采用标准 Browser 门控并实际执行，报告脚本更新位置棘轮后本地仓库级
门禁通过。正式 CLI push 与最终 UI 在独立恢复栈实际使用，见恢复 Note。

首轮远端 submission E2E 37 项通过、1 项失败、8 项专属忽略，失败来自主线新增
prediction 夹具仍发送 `type: P`。移除退役分类、明确公开范围并允许选择协调 SDK
标签后，标准 submission 预测范围实际两项通过，仍验证上传、6666 分与三个隐藏
测试点，未放宽断言或改变产品代码。最终完整 API 与远端 CI 结果独立跟踪。
