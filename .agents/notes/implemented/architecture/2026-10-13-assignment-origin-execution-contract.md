# Agent Note: 统一执行记录保存作业入口来源

Status: implemented

## Problem

同域提交已经自动计入相关作业，但执行记录不能还原学生实际从哪份任务进入。增加入口记录必须复用现有版本、评测及受理事务，不能重复实现交卷，也不能改变多作业计入和比赛保密规则。

## Decision

普通提交、客观题提交、自测各增加可空的作业 ID 和条目
ID。两字段必须同时存在或同时为空，复合外键校验所属
Domain、任务和源题，不级联删除历史。存量记录保持空来源，不根据题号或成绩推测旧入口。

Schema 使用延迟配置中的 AnyPgColumn 类型引用解除教学和评测尝试的类型环；标准
db:generate 生成追加迁移 0136，PGlite DDL 同步六列和相同约束。新迁移引用遵从测试
search_path，不绑定 public Schema。

JSON 执行接口读取配对的来源字段，流式产物从 URL query 读取；不能等待文件后的可选
multipart
字段，否则会阻塞流式消费。执行模块在既有受理事务锁定使用域、源题和绑定后调用
Education
门面，并把其返回的可信字段写入。自测仍使用独立记录；新来源不参与教学候选筛选。

## Alternatives considered

- 另建作业交卷系统：重复五类题型和评测协议。
- 自动为每个匹配提交选择一份作业：不能证明真实入口，一次提交还可能符合多份作业。
- 来源进入评测输出或 Judge 提供归属：业务归属必须由服务器受理事实确定。
- 在客户端决定来源授权：只能用当前数据库关系确认。

## Consequences

服务端保存来源，同时仍按域、接收者、源题、受理时间和有效判定计算所有符合条件的作业。比赛与作业上下文可共存，来源字段不授予赛时结果权限。没有来源的普通练习不依赖教学模块配置。

两库教学门面回归 PostgreSQL 119／PGlite 118 项通过；来源 HTTP 专项两库各 6
项通过，覆盖代码、OI、客观题、自测、流式产物、错误归属零写入、多作业计入、自测排除、共享撤销和
OI 保密。完整 core 回归与新版客户端浏览器验收另行完成。
