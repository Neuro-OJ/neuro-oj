# Agent Note: 0.11 RC 发布身份、升级边界与比赛实时性收敛

Status: implemented

## Problem

`v0.10.6` 之后 412 个提交里，源码清单版本始终停在 `0.10.5`，而静态门禁只断言"7 个清单彼此
一致、不绑定 Release 标签"，因此"标签是 v0.11.0、清单还是 0.10.5"这种发布身份错位永远是绿
的；`CHANGELOG` 的 `[Unreleased]` 是空的；迁移 `0116` 对任何存量比赛行都会以 `55000` 中止，但
没有人知道自己的库会不会命中。

比赛侧还有一处结构性浪费：后端早已提供 `/domains/:slug/contests/:id/events`（含榜单快照、
提交定位、`Last-Event-ID` 重放与撤权停推），前端**零消费** —— 域榜单页同时跑 2 秒详情与 5 秒
榜单两条轮询，赛时每个观众都在周期性打全量榜单；而唯一在收 SSE 的组件挂在已被 301 掉的旧页
上。同时 `kind` / `is_public` / `has_password` 三件套仍留在 API 契约里（写入恒为中性值、授权
仍读 `is_public`），报名请求仍接受 `password` 并静默丢弃。

## Decision

**发布身份**：7 个清单统一升到 `0.11.0`，并新增发布阶段门禁
`scripts/check-release-version.ts`（标签去掉 `v` 与预发布后缀后必须等于清单基础版本）。
两者分工明确：静态门禁管"清单之间不许漂移"，发布门禁管"标签与清单不许错位"。后者接入
`release.yml` 的 `supply-chain-check`，在构建任何镜像之前失败。

**升级边界**：0.11 首个 RC **只支持新装**，不承诺 0.10.x 原地升级，也不提供删比赛/删题或绕过
`0116` 的 SQL。为了让运维在动手前知道命中了什么，新增只读预检
`noj-core/scripts/preflight-upgrade.ts`：整个流程在一个 `SET TRANSACTION READ ONLY` 事务里，
输出迁移位置、旧 `U` 型题与比赛的数量及标识、依赖计数，命中阻塞返回退出码 2。报告明确声明
"不是备份"，且不写任何业务数据。

**比赛实时性**：域 SSE 载荷补齐 `classrooms` / `classroom_rows` / `other_rows` 与
`classroom_id`（分区在赛制引擎完成授权之后执行，与 REST 同源）；前端新增
`useDomainContestStream`，榜单页在连通时完全由事件驱动、只在降级时回到一套 5 秒轮询；正式
成绩视图不接收实时事件。

**时间推进**：新增纯函数 `contestPhase(contest, now)`，四个比赛页面统一用它推导"赛前/赛中/
赛后"。服务端下发的 `ended` 是终态，客户端时钟落后不会把已结束的比赛重新算成进行中。详情
同步从 5 秒降到 30 秒，并保留"跨越边界 / revision 变化 / 页面重新可见"三个即时刷新点 ——
不能只靠 revision，因为当前没有独立的 revision 通知渠道。

**兼容清理**：删除 `kind` / `is_public` / `has_password` / `password` 与 `ContestKind` 类型；
创建、更新与报名请求携带这些字段时返回 `400 CONTEST_LEGACY_FIELD`（报名仍允许空 body，保持
既有调用方兼容）。删除旧无域比赛页面与其专用组件、`useContests()` 运行时代码，保留一个最小的
`pages/contests/[...slug].vue` 承接旧 URL 的 301；类型收敛到 `utils/contest-types.ts`，管理后台
仍需要的展示辅助拆到 `composables/useContestAdminLabels.ts`。

**限流门禁**：`check-write-rate-limits.ts` 的路径正则只认字符串字面量，导致
`domain-contests.ts` 的 8 条写路由**一条都没被解析**（`extracted: []`），文件因"没有写路由"
直接跳过判定。修正为接受局部常量、模板字符串与简单引用，写路由总数 171 → 237。新暴露的 5
个文件逐条处置：`education/annotations.ts`、`education/enrollment.ts` 补
`educationWriteRateLimit`（6 条路由）；域社区治理、域 LLM、域题库资源管理登记为管理豁免并
写明依据。

**赛后复盘**：新增 `useOfficialSolutions` 与 `OfficialSolutionEntry`，一次拉取本域题解再按题
分组。只认 `is_official`（普通题解不冒充官方），一篇直达、多篇可选、无题解显示"暂无"，不
制造死链。

## Alternatives considered

**给版本门禁加"必须等于最新标签"**：被否决。模块版本与发布标签是两套语义（`v0.10.6` 标签
对应的清单版本是 `0.10.5`），强行绑定会逼着每次发版改 7 个文件，反而制造新的漂移。发布门禁
只断言"基础版本相等"，预发布后缀不受限制。

**为 0.11 写 0.10.x → 0.11 的原地升级转换工具**：本轮明确不做。Domain 隔离、比赛统一报名与
通知合并都是数据形态迁移，缺的是可审计的转换方案而不是脚本；先交付一个可信的新装 RC。

**让域 SSE 共享榜单计算**：没有做。SSE 按连接即时计算，5 秒节流也是连接级；接线减少的是
"没有变化时的重复查询"，不是把计算变成全员共享。这一点写进了代码注释与验收口径，避免把
"接了 SSE"误述成"榜单计算已共享"。

**只把 `is_public` 从响应里删掉、保留授权判定**：被否决。该列恒为 `true`，写在授权条件里
只会让读代码的人以为存在第二道门；删掉不改变任何可见结果，但把"死条件"从授权链上移除。

**限流门禁改为逐 handler 解析**：仍保持文件级。逐 handler 需要解析 handler 边界，误判成本
高于收益；真正的问题在路径解析，不在粒度。

## Consequences

- 发布身份可核对：标签、清单、镜像 `org.opencontainers.image.version` 与 `/api/v1/site/meta`
  都指向同一基础版本；错误标签会在构建前失败。
- 0.11 RC 的可发布标准收敛为"新装可验证"，旧实例升级另行设计与验收；预检给出可执行的中止
  原因而不是一句"迁移失败"。
- 赛时静默期不再有周期性榜单查询；降级路径只有一套轮询。SSE 仍按连接计算榜单，这一点在
  验收报告里要分别记录静默期与高频变更期的查询量，不宣称消除按连接计算。
- 比赛页面在浏览器时钟与服务器有时差时仍能正确推进阶段；但本地阶段只决定展示，授权与受理
  仍以后端为准。
- API 契约不再有已废弃的比赛分类字段；旧客户端带这些字段会收到明确的 400，而不是"看起来
  成功但凭据被丢弃"。
- 旧无域比赛页面删除后，`/contests/**` 仍 301 到 `/d/main/contests/**`；无域读 API 保留默认域
  门控并登记为弃用（最早 0.12 评估下线）。
- 写路由门禁从 171 条升到 237 条；新暴露的 6 条教学写路由已补限流，3 个管理级文件登记豁免并
  写明依据。仍有两项 `pending` 欠债保持可见（每日签到、邮件投递回执）。
- 赛后复盘提供"官方题解入口"，按提交时间轴回放仍未实现（需新的时间轴端点）。
