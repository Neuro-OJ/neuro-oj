# Agent Note: 执行归属完成非空收缩

Status: implemented

## Problem

服务已经明确保存执行的使用域，但扩展阶段的可空列仍允许缺少归属的记录。
复合外键的 MATCH SIMPLE 会跳过空键，无法完整约束执行与题库绑定。

## Decision

通过标准 db:generate 追加 0137，先核对旧空域执行来自默认题库、旧批量任务
无冲突归属，再按实际使用域与源题绑定回填。原提交 ID、代码、时间、版本与
尝试不改写；幂等键冲突及回填不完整由数据库约束中止迁移，不删除或猜测归属。

普通提交、客观提交、自测的域与绑定，批量任务和条目的域均为 NOT NULL。 条目仅
failed/skipped 可保留空绑定；删除旧空域任务的部分唯一索引。
默认入口的源域检查移除不再存在的空域兼容，重试条目在构造时声明使用域。
无保留引用的源题删除先释放终态自测，再删除绑定，继续拒绝在途评测及历史引用。

PGlite DDL 与 Schema 一致。夹具显式取得真实域和绑定，不使用全局注入或写入
拦截；历史回填用例在回滚事务中恢复扩展列，再执行实际追加 SQL。

## Alternatives considered

- 给执行列默认 main：会掩盖新写入遗漏归属，无法表达共享题的使用域。
- 将所有任务条目绑定设非空：删除来源的失败／跳过历史不能获得真实绑定。
- 只验证空库：不能证明旧提交字节、版本未知状态及评测历史保留。

## Consequences

数据库拒绝缺域／缺绑定执行、错误域关联及无绑定的可执行任务条目。
新旧数据使用相同归属模型，不需要运行时空域退路。

真实 PostgreSQL 执行约束与回填组 15 项通过；PGlite 非空及状态约束验证通过，
共享组 293 项通过、16 项环境专用忽略。旧库恢复副本标准升级至 0137，实际八列
非空；独立完整旧 Schema 夹具还保留未知版本桶和成绩指针，重建后有效、通过及
本人历史 DTO 的 10000 成绩均保留。迁移安全、Schema parity、 域边界及完整 core
类型检查通过。各模块最终回归记录由任务清单保存，本文不
代替尚未完成的比赛／社区收缩或整个发布验收。
