# Agent Note: 客观题默认域契约与答案权限收口

Status: implemented

## Problem

客观题旧入口仍按 P/U
解析题号并决定作者管理权限。默认域升级后，旧测试中的分类输入、未建立的默认域和缺少编辑角色的作者与产品模型不符；作者身份本身仍会让角色撤销后的用户读取标准答案。比赛小题读取还可能在管理身份下忽略固定版本而返回当前草稿。

## Decision

- 客观题旧引用只解析默认域稳定 ID、数字题号和 P 数字兼容链接；拒绝 U 前缀。新
  Domain 提交继续复用已经解析的域执行上下文，保留其版本及提交隔离。
- 套卷管理和草稿答案读取复用 catalog
  的当前源域编辑授权，不按旧分类、裸作者身份或 `userRole`
  字符串放行。匿名调用不被隐式视为系统账号。
- 正在比赛的参赛作者按固定版本读取并裁剪标准答案、解析。组织者获授权查看答案时也读取比赛固定版本；显式版本读取不能被管理身份转换成草稿读取。
- 默认域夹具明确复用 `catalog/tests/default-fixture.ts`，建立实际 Domain
  和必要角色；普通作答者不自动成为题目作者。已有作者按需授予
  editor，纯判分测试继续保持无数据库依赖。
- 旧“作者删除并级联清理套卷”的测试改为验证编辑者无物理删除能力、管理员不能删除已发布历史；保留版本、正式答案、判卷、一次交卷与比赛结果裁剪的原有回归。
- 竞赛客观题固定版本夹具显式建立默认域，继续验证竞赛固定版本不受客户端版本或题库最新版覆盖。

## Alternatives considered

- 在生产访问函数中自动建域或恢复旧作者特权会掩盖初始化及成员角色缺失，因此只修正测试夹具和旧授权分支。
- 为默认入口保留独立 P/U
  权限路径会继续产生新旧模型差异，因此统一调用源域编辑门面。
- 管理者一律读取当前草稿会让比赛管理视图检查错误卷面，因此指定版本和比赛固定版本也约束管理视图。

## Consequences

新增回归证明编辑角色撤销后标准答案立即裁剪，匿名和伪造 admin
字符串不能获取答案；参赛作者与组织者均读取固定版本，只有获授权组织者取得答案。客观题标准任务在
PGlite 与隔离 PostgreSQL `test_objective_contract` 均 66 通过、0
失败；竞赛标准任务的 PostgreSQL `test_contest_objective` 115 通过、0
失败，PGlite 114 通过、0 失败、1 忽略（真实 PostgreSQL 专用用例）。完整
objective 与对应竞赛夹具类型检查、lint 和域边界检查通过。

本批不修改新域客观题路由、提交执行、已保存的 catalog、Schema、迁移、锁文件、app
或版本控制。新域历史、受理限流和提交 DTO 的实现及验收仍由相应工作批次负责。
