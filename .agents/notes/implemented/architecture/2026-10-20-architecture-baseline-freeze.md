# Agent Note: 冻结 2026-10-20 架构整治基线

Status: implemented

## Problem

架构整治方案批准后，P0–P8 各批次都需要一个可追溯的"改造前状态"，但仓库此前没有同时
回答三件事的文档：审的是哪个提交、它和 `main` 是什么关系；代码/表/后台任务当前归谁
所有；改造前的请求、事件、门禁规模是多少。另外本地 UI 链（`codex/learning-ui-restructure`，
父提交 `fbc40624`）与 `main`（`2f488599`）是并行链，若不先写清归属，后续批次容易在
提交范围上夹带或覆盖既有工作。

## Decision

冻结受审版本为 `fbc40624`（对照 `main` `2f488599`，分叉点 `e4de4dd0`），并新增
[架构基线冻结文档](../../../../dev-docs/engineering/architecture-baseline-2026-10-20.md)：

- 版本归属：本地链已提交 292 条（jj revset `main..@` 计 293，多 1 条工作副本快照），
  `main` 独有 28 条；本地链含 `ui` scope 88 条、仅 `core` 121 条，是混合链而非纯
  UI 分支。架构批次从 `fbc40624` 派生，只包含本批改动；与 `main` 的协调留在 P8。
- 所有权登记：17 个当前域（436 个非测试 `.ts`、64 个路由文件）→ 12 个目标
  `modules` 分区映射；21 个 schema 文件共 109 张表按"当前 schema 文件 → 当前持有域 →
  目标分区"登记；14 个后台消费者/worker/sweeper/保留任务登记启动点、停止方式、周期与
  配置。
- 代表性基线：路由 355 条（GET 183/POST 107/DELETE 28/PUT 22/PATCH 15，按域分解）、
  SSE 频道 9 个、门禁 33（REPO_GATES）+25（自测）+3（模块检查）、各模块测试入口命令、
  单副本部署事实。
- 口径限制：本轮未做线上压测、全量测试、跨模块/浏览器/Judge Docker E2E、恢复演练；
  所有数字附复现命令，引用代码附 `路径:行号`；基线以 `fbc40624` 已提交树为准，不纳
  入工作副本中其他批次的在途改动。

P0 只新增上述基线文档与本 Note，不修改生产代码与既有文档。

## Alternatives considered

- 等本地链合入 `main` 后再冻结：会阻塞 P1–P8，且无法证明改造前状态；合入协调本身属于
  P8，不能前置为 P0 的依赖。
- 在 `main` 上另起基线：会丢失本地链的 UI/BFF/工作空间改造事实，使 P8 失去对比对象。
- 仅依赖现有生成物门禁（route/event catalog、schema parity）当基线：门禁只覆盖可机检
  目录，不覆盖表/后台任务所有权与停止语义，也不回答版本归属问题。
- 先批量搬迁目录再冻结：方案 §3.1 要求目录搬迁随职责迁移完成，在冻结前搬目录会让基线
  失去可对比性。

## Consequences

- 后续批次（P1–P8）以 `fbc40624` 为对比基点，提交范围与归属可审计；基线文档是时点
  快照，结构变化时追加更新指针或新快照，不回溯改数字。
- 基线暴露了三类缺口并已分配给对应批次：后台任务仅 3/10 在关闭流程接线（P2 统一
  `ManagedTask`）、Gateway ready 探针只 ping Redis 且停止句柄被丢弃（P1/P5）、
  `0007_fk_cascade.sql` 不在 `_journal.json` 的存量例外（P2/P8）。
- 文档未加入工程规范 README 常青索引（P0 约束不修改既有文档），引用入口为方案 §7 跟踪
  清单与本 Note；文档链接遵循 [CONTRIBUTING](../../../../CONTRIBUTING.md) 相对链接约定。
