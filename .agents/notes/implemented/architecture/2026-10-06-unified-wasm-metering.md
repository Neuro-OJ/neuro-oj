# Agent Note: NOJ 内置统一 WASM 计量标准

Status: implemented

## Problem

各实例拟合本机成本表会改变选手的运行预算，成本表导入还需要可信采样与独立留出集。管理员配置不同、工具链变化、宿主时钟及随机序列会妨碍跨实例比较；墙钟超时不能充当固定算法成本的
TLE 判据。

## Decision

NOJ 内置不可修改的 noj-wasm-v1 标准。完整算子表冻结为 Wasmtime 49.0.1
默认表，工具链固定为 WASI SDK 34，1,000,000 fuel 为 1 NOJ
等效毫秒。标准清单覆盖编译参数、固定时钟/随机行为、运行特性和保护参数，所有构建副本必须通过摘要一致性检查。随机流使用每个
guest 独立的 SHA-256 计数器；禁用线程和 relaxed SIMD，规范化 NaN。

删除 CLI
校准和成本表导入功能，旧数据库/环境配置不再用于计量，后台只读展示统一标准。Worker
拒绝不匹配成本快照并提示重测。结果记录实际
fuel、预算、等效时间及标准、源码、题目评测、编译产物和可比摘要；公开投影只保留摘要，隐藏数据不下发。缺少标识的旧结果不参与比较，重测采用当前标准。

fuel 耗尽为 TLE，墙钟运行保护采用 max(30 秒, 题目时限乘 10)，触发为
SE。保留内存、输出、文件和外层任务限制。普通计算与内存操作继续计费，不计宿主 IO
等待时间。

## Alternatives considered

不再要求部署者拟合本机参数；不把单一整数循环拟合结果作为通用算法成本；不把跨站可比标识视为来源可信证明，不引入跨站成绩导入或签名体系。不依赖运行时升级后的隐式默认算子成本。

## Consequences

等效时间不等于 CPU 时间，导入其他 OJ 的题目可能需要调整时限。原生
Docker/go-judge
计量方式保持原样。固定基准覆盖排序、图算法、DP、字符串、数值计算、批量内存操作、错解和
fuel 超限；两个独立 Worker
进程必须与固定报告一致。新增随机向量、批量内存计费、宿主等待、旧标准拒绝、摘要变化和隐藏数据投影回归。真实网页与
HTTP 验收覆盖 P3 原生评测和 P4 统一 WASM 评测。

标准清单是唯一来源；Rust/TypeScript 的构建副本被 CI 校验，已发布 v1
的摘要不得原地变更。计量行为修改必须发布新标准版本。部署升级应同时更新 core 与
judge；旧排队任务会返回 SE，可使用正式重测接口重新入队。
