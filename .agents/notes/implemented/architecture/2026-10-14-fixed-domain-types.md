# Agent Note: 三种固定域类型与统一社区能力

Status: implemented

## Problem

原 Preset 只初始化可修改开关，允许自定义类型及重新应用配置，与用户确认的
“三种域类型、均有社区、创建后固定能力”规则不一致。域排行还错误依赖教学作业。

## Decision

新建与创建申请只接受社区、教学、团队。共享契约集中定义能力：三者均有社区与
域排行，仅教学域有班级和作业。读取旧域时按固定类型计算能力，旧 JSON 开关不能
额外授予教学写入。实例允许列表继续限制运行能力；域管理员仍可修改访问与加入政策。
移除 Preset 预览和重新应用路由及前端方法，设置页改为固定类型说明。修改类型或
能力返回稳定的 `DOMAIN_TYPE_FIXED`，不静默忽略。

存量 `custom` 和创建申请保留数据读取；批准旧自定义申请须先重新选择类型。
不猜测迁移、不删除历史区间。此次只调整 TypeScript 契约，Drizzle 确认无物理
Schema 变化，不生成空迁移。

验证：workspace 43 项、education 123 项通过；前端单元 285 项、组件 263 项
通过，前后端类型与 lint、仓库级门禁通过。生产 core/UI 镜像已构建，在独立恢复
验收套件通过真实 API
创建三个类型、检查共同社区和排行、拒绝类型修改及自定义创建。
完整并行回归继续执行，不把这批结果等同于远程 CI 已通过。

## Alternatives considered

- 只隐藏前端选项：旧客户端仍能任意组合模块；在服务端也收紧契约。
- 把旧 custom 全部转为社区：缺少逐域用途依据，保留 proposed 决策项。
- 完全删除实例模块限制：违背实例治理规则，固定能力仍与实例允许列表组合。

## Consequences

域创建和管理更直接，三种类型均能使用社区。普通模块关闭改由实例治理处理，
历史停用区间仍用于解释成绩。教学能力变化的回归改用实例政策验证，继续覆盖
关闭期间练习不回填及授权历史可读。已核实的开发与恢复库没有待转换域，其他库须另查。
