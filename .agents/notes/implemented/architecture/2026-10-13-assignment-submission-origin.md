# Agent Note: 作业提交入口来源与教学成绩分离

Status: implemented

## Problem

统一提交系统需要保存学生从哪份作业进入作答，但这个来源不能把一次同域练习限制为只计入一份作业，也不能越过比赛保密或源题共享授权。普通题库练习及独立自测还需要在教学模块关闭时继续使用。

## Decision

Education 的公开门面 `resolveAssignmentSubmissionOrigin` 接收受理事务的
Executor，以及执行模块已经授权的
Domain、用户、源题和题库绑定。没有来源时立即返回两个
NULL，不加载教学配置；有来源时在同一事务按班级、作业顺序加共享锁，并检查当前有效域成员、班级学生、实际接收者、已发布作业及匹配题目与绑定的条目，返回可信作业
ID 和条目 ID。

截止和提前结束不禁止补做来源；班级或作业归档、教学模块停用停止带来源的新执行。校验不赋予教师、其他接收者或历史学生额外作答身份。权限和匹配失败统一不可访问，已可访问任务的归档或停用使用现有稳定错误语义。

普通、客观题和自测的执行模块在其既有受理事务调用此门面。共享、作答版本和比赛限制仍由原执行解析负责，来源字段不授予结果读取权限。教学候选计算继续按域、学生、题目、受理时间和正式结果，不按来源作业筛选；自测仍不产生正式成绩。

## Alternatives considered

- 新增一套作业提交系统：重复题型、版本和评测逻辑，故继续复用已有提交链。
- 直接调用管理写入版
  `loadAssignment`：该入口要求教师管理能力，不适用于学生作答，故提供专门的学生受理门面。
- 根连接再次读取授权或跨请求缓存：不能看见受理事务中的关系变更，故所有教学事实仅通过传入
  Executor 查询。
- 限定比赛与作业来源不能共存：用户计划允许两种可选上下文，来源本身不改变比赛保密，故不引入额外互斥规则。
- 将来源作业作为成绩唯一归属：违背同一次提交计入多份同域作业的规则，故保持入口记录和候选计算独立。

## Consequences

门面服务回归覆盖正确来源、错误域／源题／绑定／条目、教练伪造学生来源、草稿、当前关系撤销、同事务变更接收者、教学停用和归档。无来源练习不依赖教学开关，历史记录不需要因为作业配置变化而改写。

Schema、HTTP 解析、三个执行表的受理写入及 UI
入口由对应实施范围接入；这份记录描述教学授权门面，不把门面测试当成全客户端集成验收。
