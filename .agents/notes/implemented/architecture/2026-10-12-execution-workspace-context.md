# Agent Note: 执行记录的域归属与回填

Status: implemented

## Problem

提交、自测和批量任务缺少使用域，无法区分两个学校引用同一源题后的历史、策略
和幂等请求。旧入口也不能用源题 ID 执行其他域的题目。

## Decision

为普通提交、客观题、自测、批量任务和条目增加域归属与绑定关联，使用复合外键
约束绑定的域、源题和父任务。任务幂等键包含域。旧入口在准备资源前拒绝其他域
源题，在写入事务中读取默认域进入政策与绑定，不采用客户端提供的归属。

升级副本保留可信任务或原提交的域与绑定。提供幂等回填命令，保留历史 ID、代码、
答案、时间、版本和尝试；不能完整解析的记录使事务回滚，避免猜测归属。

## Alternatives considered

只给 HTTP 请求增加当前域不能保存历史依据。依靠前端传入域或仅用独立外键不能
防止同源题的跨域绑定混用。扩展迁移保留可空字段，完成全链路转换后再收缩。

## Consequences

迁移 0117 和执行回填在原开发库及备份恢复库通过；两库保留的执行记录均为零，
人口历史回填由隔离测试数据验证。PostgreSQL submission 标准测试 333 项通过、
0 失败、10 项跳过；PGlite submission 303 项通过、objective 63 项通过。全源类型、
相关 lint、迁移安全和 Schema parity 通过。

全量并行曾暴露两个旧并发测试的账号清理外键错误，修正成员及角色清理后，标准
PostgreSQL submission 重跑通过。此批不声称全量并行最终通过。

显式非默认域提交入口、比赛与作业上下文校验、绑定策略成绩投影、查询和下载
隔离仍需后续实现；不把结构回填等同于完整域隔离。
