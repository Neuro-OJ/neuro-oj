# Agent Note: Nuxt 视图 BFF 与 SSR 边界

Status: implemented

## Problem

空间布局、身份守卫和业务组件分别取数，存在重复身份读取、串行等待和客户端补取。
页面元数据的 ssr 标记不控制 Nitro，空间错误态返回 200。

## Decision

Nuxt Nitro 为首页、班级概览和作业详情提供固定的只读聚合接口。Core 的业务授权与
数据契约保持原样。视图中间件先获取真实用户与空间，页面和公共布局消费同一结果；
水合复用 payload，交互仍使用细粒度 API。

请求内 GET 去重、四路并发和取消使用请求上下文。Redis 仅缓存匿名站点元信息
30 秒，隔离部署与上游，Redis 故障时绕过缓存。域内容遵守 Core 的 no-store
契约，辅助模块错误独立呈现，必要资源失败保留 HTTP 状态。

客户端页面统一通过 Nitro routeRules 关闭 SSR，内容页保留 SSR。测试覆盖请求
数量、取消、角色分支、缓存与锁，以及生产构建的 HTML、浏览器水合和局部刷新。

## Alternatives considered

- 只并行转发：不消除重复取数与水合请求。
- 修改 Core 或直连数据库：扩大授权与发布耦合。
- 缓存完整视图：引入权限撤销延迟，违反现有 no-store 约束。
- 每次刷新重新聚合整页：放大轮询、SSE 和筛选产生的请求。

## Consequences

UI 增加可选 Redis 连接与公共缓存命名空间，生产配置使用现有 Redis。Core 不发生
源码、数据库或 API 变更。聚合不提供事务快照，动态成绩继续依赖实时刷新。其他
页面使用既有代理，新聚合视图仍需明确模块、角色和错误边界。
