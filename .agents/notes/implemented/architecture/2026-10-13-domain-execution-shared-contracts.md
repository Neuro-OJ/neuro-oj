# Agent Note: 域模型配置与比赛绑定数据库契约

Status: implemented

## Problem

域内 LLM 模型选择和比赛作答缺少独立持久配置、修改 revision
和使用域绑定约束，无法统一客户端与执行链。

## Decision

增加 domain_llm_settings，Provider 与模型同时设置或清空，revision
为正整数。旧数据库默认模型配置仅归入
main，迁移幂等且不覆盖现有域设置。启动在系统设置重新加载之后执行默认域首次配置初始化。

比赛增加
revision，题目关联保存使用域和题库绑定，通过复合外键约束比赛、绑定和源题关系。旧关联的可空字段属于扩展阶段，新域写入必须明确填写归属。Drizzle
自动追加 0127–0129，运行时 PGlite DDL
及缓存输入同步；完整重置表清单移入独立模块，保持单文件规模限制。

域内 LLM 治理增加精确审计动作。公开共享层不依赖业务模块。

## Alternatives considered

- 把使用域放进 JWT：仍由 URL 和实时成员关系解析。
- 在题面版本保存域 Provider：执行模型属于使用域，内容版本保持不可变。
- 重建开发数据库：采用追加迁移，独立测试验证已有数据库可升级。

## Consequences

Schema parity 为 104 表／942 列；迁移安全、快照链、域边界、CI
覆盖及共享标准测试通过（291 项通过，16 项跳过）。专属 PostgreSQL 比赛与 Gateway
测试库已执行这些追加迁移，相关模块验证通过。完整收缩、原开发库协调升级和首次发布恢复验收仍按总计划推进，扩展契约不代表产品全链路已验收。
