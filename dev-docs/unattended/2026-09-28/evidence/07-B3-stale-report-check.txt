⚠️ 诚实记录（本文件中间有一段无效验证）：
第一轮"修复后"验证是**无效的**——上一轮（未修复版）的 `--check` 已经把篡改行覆盖掉，
所以修复版面对的是**本就新鲜的报告**，`exit=0` 属正确行为，而"篡改行不在"也不是本次改写造成的。
发现后**重新篡改**再跑修复版，才得到上面这组有效对照：
  exit=1 + "报告过期" 报错，且 md5 前后一致（未被改写）。
教训与 `04-F04a` 那处一致：**"撤销/篡改"类验证必须先确认前置状态真的生效**。

未附回归测试（诚实标注）：B3 的修复是**操作顺序**层面的（先读后比、仅在非 --check 时落盘），
而该脚本是顶层脚本（无导出函数），唯一可测方式是以子进程运行它并临时篡改报告文件——
那会在测试期间改写仓库内被 git 跟踪的报告，副作用不可接受。
建议后续为 `scripts/silent-skip-report.ts` 抽出可测函数（如 `shouldReportBeWritten(check)` /
`compareReport(onDisk, generated)`）后再补门禁自测。
