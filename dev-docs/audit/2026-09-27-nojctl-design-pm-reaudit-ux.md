## 1.2 缺口详述（只展开需要动手的）

### 1.2.1 B1 的三个缺口（每个都能让"HTTP 明文"故障重新溜过去）

1. **登录冒烟依赖"向导创建了管理员"，而第④问标注为"可选"**（L220 vs L336）。draft-2 自己写明："若向导未创建管理员，则跳过并记为 warning（不静默）"——恰好是**最可能出 Cookie 故障的那类用户**（选了跳过 → 站点"部署成功" → 之后再手工建管理员）拿不到这条保障。建议：把第④问从"可选"改成**默认必经**（见 §2.3 屏幕 1 文案），或在跳过时把 warning 升级为完成页的**红色区块**："本次未验证登录可用性；创建管理员后请运行 `nojctl doctor --verify-login`"。
2. **VERIFY 的探测目标未定义（回环 vs 外部域名）**。§6.6 #2/#3 只说"HTTP 经 nginx"/"登录往返"（L335-336），没说打哪个地址。但 draft-2 把 HTTPS 标为"推荐"（L220），并在屏幕 2 说明"TLS 不由本站点提供、需要外部反代"（L221）——**外部反代在首装时通常还不存在**。如果 VERIFY 打的是 `https://<域名>`，那么一次完全正确的部署会 VERIFY 失败 → 自动回退（或首装失败），教练拿到一个他自己无法理解、也无法修复的失败。必须写死：**VERIFY 只打本机回环 `http://127.0.0.1:<NGINX_PORT>`；域名解析、TLS 握手、剩余天数只做完成页的检查清单与非致命告警（§5.5 屏幕 7 / §6.6 之外）**。
3. **黄金文件未断言 `NOJ_ALLOW_INSECURE_HTTP` 同时进入 core 与 ui 两个容器**。仓库事实：`docker-compose.prod.yml:46` 把它给了 core（生产配置校验用），`:152` 映射成 ui 的 `NUXT_ALLOW_INSECURE_HTTP`（决定 Cookie 的 Secure 标志），`noj-ui/server/api/[...slug].ts:237` 读后者。§5.5 屏幕 2 只承诺"推导这个键"，§7.4 第 1 层门禁只保证"每个键有交付目标"——**不保证两个容器都拿到**。建议 §7.5 黄金文件与 §10.3 增加断言："`NOJ_ALLOW_INSECURE_HTTP=true` 时，core 与 ui 两个服务的 environment 都出现该键"。

### 1.2.2 B5 的四个缺口（决定"人工手册"是 30 分钟还是半天）

1. **数据搬运不依赖 v1 快照**：§1.1 L60 不读 `snapshot-*.nojbackup`，而 v1 快照里恰好有 `postgres.dump` / `redis.rdb` / `minio/` / 加密 `.env.prod`（`noj-docs/docs/operators/production-deploy.md:75-76`）。手册必须明确走**手工导出**：`pg_dump -Fc` / `redis-cli BGSAVE` 取 `dump.rdb` / `mc mirror` / 卷目录 `tar`，并且写清"在哪台机器上执行、用哪个容器名"（容器名依赖 v1 的 `noj-prod` 项目名，`judge-workers.md:305-307`）。spec 至少要把这段大纲写进 §12 批次 6.5，否则"手册"是不可估算的工作量。
2. **一致性窗口未定义**：迁移期间老站要不要停写？新站导入期间学生能不能提交？建议手册固定顺序：老站 `stop` → 导出 → 新站 `deploy` → 导入 → 验收 → 切 DNS → 老站保留 7 天可回切。
3. **DNS / 证书切换窗口未定义**：域名从老机指向新机需要 TTL 等待（见 §2.2 的外部依赖），手册应含"提前把 TTL 降到 300 秒"这一步。
4. **回滚点**：老站必须保持可启动直到新站验收通过；手册要写"不要在新站验收前 `uninstall` 老站"（与 §9.5"永不自动删数据卷"一致，但用户很可能手动删）。

## 1.4 修订新引入的矛盾 / 漏洞（本次复审重点）

> 严重度：**高** = 必须在本稿定稿前收口（实现者会写出两种不同行为）；**中** = 会造成用户困惑或返工；**低** = 打磨。

### N1（高）`apply` 不改运行态 vs 事务本身必然改运行态——三方冲突

- **冲突面**：§4.2 不变量 5"`start`/`stop` 只管运行态；`apply` 只管部署描述，**不会启动已停止的栈**"（L136）；§5.6 规则⑤"栈为 `stopped` 时只切换部署描述并提示'运行 `nojctl start` 启动'"（L241）；§11 验收"`apply` 不改变运行态"（L566）。**对面**：§6.3 COMMIT"**一次** `up -d`"（L305）+ FINALIZE"`state=running`"（L307）；§6.6 VERIFY #1 要求"期望容器集合齐全且 **healthy**"（L334）。`docker compose up -d` 会启动已停止的服务；要验证 healthy 就必须让容器跑起来。
- **用户后果**：教练"应急先停站"（B3 新增的能力）→ 之后升级 → `apply` 把站**静默开起来**，`state.json` 被写成 `running`，而屏幕上他刚被告知"运行 `nojctl start` 启动"。若他随后敲 `stop` 或再 `apply`，状态判定与实际不一致。更糟的是**没人知道到底哪个是对的**——不变量与流程各说一套。
- **建议（推荐方案 a，并写进 §6.3 / §4.2 / §5.6）**：
  - **a（推荐）**：`stopped` 栈上的 `apply` = "临时启动 → 完成 VERIFY → **自动回到 `stopped`**"，并在摘要第一行写明：`当前站点是停止状态：升级过程中会短暂启动以完成验证，验证后自动恢复为停止。` 回退路径同样以"回到 `stopped`"收尾。
  - **b（次选）**：`apply` 在 `stopped` 栈上只做 PREPARE + 文件切换，**跳过 VERIFY**，并在摘要与 `--json` 里标注 `verification: "skipped_stack_stopped"`（风险：把未验证的世代留在盘上）。
  - **c（最省事但需改承诺）**：删掉不变量 5 的"不启动"半句，明确"`apply` 会把栈启动；要停站用 `stop`"（等于回到 draft-1，但至少自洽）。
  - 三选一必须落进 spec，并加一条契约测试（§10.4）：`stopped` 状态下 `apply` → 结束态断言。

### N2（中）`deploy` 在"无 state 但已有 `.env.prod`"时的分支未定义

- **出处**：§9.3 第 4 行"无 state，仅含保留物或本工具生成物 → `deploy` 允许（覆盖生成物、保留 `.env.prod` 与 `backups/`）"（L505）。
- **两条真实路径**：（a）上次 `uninstall` 后重装（应**复用** `.env.prod`、跳过向导，否则教练白答 4 个问题）；（b）教练把别的站的 `.env.prod` 拷进来（复用 = 带着别人的域名/密钥上线）。
- **建议**：`deploy` 检测到已有 `.env.prod` 时打印摘要 + 三选项：
  ```
  发现已有的配置文件 .env.prod（最后修改 2026-09-20 14:12，含 69 个键）
    1) 复用它（保留现有域名/密钥，跳过配置问题）   ← uninstall 后重装的默认
    2) 重新配置（覆盖它，问卷 4 个问题）
    3) 中止，我自己看看
  注意：域名/协议这几项如果和文件里的不一致，会以你这次的选择为准。
  ```
  `--yes` 时默认为 1（复用），并在 `--json` 里输出 `config_source: "reused"`。

### N3（中）项目名派生把安装目录绑进 `artifact_hash`：搬目录/改名会触发漂移与孤儿资源

- **出处**：§7.1 项目名进入渲染输入（L370-375）；§9.4 漂移守卫 fail-closed（L513）。
- **场景**：把 `/opt/neuro-oj` 拷成 `/srv/neuro-oj`（或改名）后运行 `apply` → 项目名变化 → 渲染产物变化 → `artifact_hash` 与 `current` 不一致 → **破坏性操作被拒**，提示"请先 `nojctl apply` 恢复受管状态"，而 apply 本身又因漂移被拦（逻辑上互为条件）。同时旧项目名的容器/命名卷变成孤儿，继续占磁盘（M9 的回收逻辑只清"本世代独占镜像"，不会碰孤儿卷）。
- **建议**：（1）§9.4 增加"漂移成因判定"：若 `state.project_name` 与当前派生值不同 → 提示"安装目录已改名/移动"并给两条出路（`NOJCTL_PROJECT_NAME=<旧值>` 恢复，或走"迁目录手册"）；（2）`doctor` 增加孤儿检测：列出同宿主上 `noj-*` 前缀但不在任何 `state.json` 里的 compose 项目与卷，并给 `docker compose -p <name> down --volumes` 的删除命令（默认只报告不删）。

### N4（高）回退文案要求陈述"迁移未推进 / 已推进 N 条"，而 §6.7 自己承认该事实多数情况下不可知

- **冲突面**：§6.3 回退输出示例 `数据库：本次迁移未推进（或：已推进 1 条，不会回滚）`（L313）→ 这是**事实陈述**；§6.7"精确增量……镜像不支持时降级为'目标版本声明总数 + 增量未知'，并在摘要中如实标注"（L359）。也就是说：只有目标镜像实现了 `noj db status --json`（批次 2.5，**可选能力**）时才知道精确状态。
- **用户后果**：这正是首轮 M2"回退文案不诚实"的回归——把"未知"写成"未推进"，教练会据此判断"数据没事"。而首轮修好的那部分（"数据库可能已推进，届时退出码为 7"，L251）又与它并存，同一个屏幕里两种说法。
- **建议（二选一）**：（1）文案改为不可知版：`数据库：本工具不查库，无法确认本次迁移是否已写入；如果退出码是 7，请务必先看 nojctl backup list`；（2）**把 `noj db status --json` 从"可选能力"提升为 v1 必选**（进批次 2.5 的验收门槛），这样才能兑现现在的文案。推荐 (1) 立即改、(2) 作为目标——因为 (2) 同时解决 N6 与 M3 的残留。

### N5（高）VERIFY 的语义冒烟需要管理员密码，而非交互等价里没有密码来源

- **冲突面**：§6.6 #3 登录冒烟（L336）；§5.5 非交互等价只列了 `--admin-email` / `--admin-username`（L230）；而容器内 CLI 的首次初始化**强制交互终端**且**不接受密码参数**——`noj-core/scripts/noj.ts:231-241`：`first-admin` 要求 `--username` / `--email`，并且 `if (!Deno.stdin.isTerminal()) throw new Error("请在交互终端执行首次初始化，以隐藏输入管理员密码")`，随后 `Secret.prompt` 两次；`noj-docs/docs/operators/cli.md:94` 亦载明"不接受密码命令行参数……首次登录必须修改密码"。
- **三处后果**：（a）`deploy --yes`（非交互）**无法自动创建管理员** → VERIFY 走 L336 的 warning 分支 → **B1 的核心保障在最需要自动化的场景失效**；（b）nojctl 若要代收密码，必须给 `compose run` 分配 TTY 并透传交互（spec 未提），否则容器内的 `Secret.prompt` 直接抛错；（c）密码会在 nojctl 进程内存在，而 §6.2 的世代目录含**配置快照（0600）**、`state.json` 也在磁盘上——必须明确"管理员密码绝不进入 state.json / 世代快照 / 日志 / `--json`"。
- **好消息（可直接写进 spec 作为可行性依据）**：`must_change_password` 的强制改密白名单包含 `/api/v1/auth/me`（`noj-core/src/domains/identity/middleware/auth.ts:39-43`），所以"登录 + 调 `/me` 期望 200"这条冒烟对刚创建的管理员**是可通过的**，不需要先改密。
- **建议**：（1）第④问改为默认必经（见 §2.3），执行阶段用 TTY 透传 `compose run`（不加 `-T`），并在屏幕上预告"接下来容器里会让你输入两次管理员密码"；（2）非交互模式新增 `--admin-password-file <path>`，并明确规定该文件不复制、不落 state；（3）非交互且未提供密码时，`--json` 必须输出 `warnings: ["login_smoke_skipped"]`，人类输出在完成页红色区块给出补验命令 `nojctl doctor --verify-login`。

### N6（中）退出码 6 的措辞与 §6.7 冲突，实现者与测试无法唯一确定取值

- **冲突面**：§5.2 6 号 = "已回退到上一世代并验证通过，**且本次未成功推进数据库迁移**"（L186）；§6.7 "`migrate` 退出 ≠ 0 → 迁移未完成 → 切回上一世代，退出 **7**"（L356）。"`migrate` 非零"字面就是"未成功推进"，按 §5.2 应给 6，按 §6.7 给 7。
- **建议**：把 §5.2 的 6 号条件改写为**可判定**的表述：`migrate` 服务**未运行或未执行**（例如 PREPARE 阶段就失败、镜像未拉起）→ 6；只要 `migrate` 服务**运行过**（无论退出码）→ 数据面可能已前进 → 7。并同步 §10.4 的契约用例（两侧）。

### N7（低）`start` / `stop` 在 `uninitialized` / `partial` 下的行为未定义

- **出处**：§5.1 L154、§6.1 四状态（L277）。
- **建议**：`start` 在 `uninitialized`（无 `current` 世代）→ 退出 3 + "还没有安装，先运行 `nojctl deploy`"；在 `partial` → 允许启动（应急恢复的第一动作）并在输出顶部标注 `⚠ 上次操作未完成（<原因>），本次启动的是 <世代>；建议随后运行 nojctl apply 或 nojctl doctor`；`stop` 在 `partial`/`uninitialized` → 幂等成功（退出 0）。

### N8（低）门禁豁免把 `stop` 当成"非破坏性命令"

- **出处**：§5.3 规则⑤"豁免……`start` / `stop`、所有非破坏性命令"（L199）。
- **说明**：`stop` 对**正在考试**的学校站点是破坏性的（中断提交）。不必加口令，但建议：`stop` 输出一行确认句 + 提示：`停止后学生无法提交；如果正在进行竞赛，请先确认没有正在进行的考试。[Y/n]`；`stop --yes` 跳过。这是 v1 成本极低的一条。

### N9（中）三类键的边界在面对"键存在但值不自洽"时没有出路

- **出处**：§5.7 表格（L259-263）+ 校验只承诺"指向具体键名 + 文件行号"（L265）。
- **用户后果**：教练拿到 `APP_URL 必须使用 HTTPS；临时 HTTP 需要明确开启 NOJ_ALLOW_INSECURE_HTTP（.env.prod:32）` 这类信息，仍然不知道该改哪一行（有两个合法改法，各改不同行，且改动后果不同）。
- **建议（两条，都可直接写进 spec）**：
  1. 校验失败输出**二选一的精确修复建议**：`把 .env.prod:32 的 APP_URL 改成 https://oj.school.edu，或把 .env.prod:40 的 NOJ_ALLOW_INSECURE_HTTP 改成 true（选了 HTTP 明文）`。
  2. **向导写出的 `.env.prod` 必须与 `.env.prod.example` 同构**（同样的分组注释、同样的"最常改的键"顶部区块，并在邮件区块上方内联一行指令：`# 开放学生自助注册：把上一行改成 aliyun 或 tencent，并填写下面 3 个凭据，然后运行 nojctl apply`）。这一条把"手改 250 行"降到"改 4 行、旁边就写着怎么改"，是 M4/B2 最便宜的补偿（**建议 v1**）。

### N10（低）VERIFY 的 judge 执行面探测用"最小镜像"，在受限网络下会误判

- **出处**：§6.6 #4"通过 rootless socket 跑一个一次性容器（`--rm --network none` 的**最小镜像**）"（L337）。
- **问题**：`busybox` / `hello-world` 之类的镜像来自 Docker Hub，而 §3 第 8 条（L105）明确"目标服务器常处于受限网络（Docker Hub 直连超时）"。拉不到 → 探测失败 → VERIFY 失败 → 正确部署被回退。
- **建议**：改用屏幕 3 已在该 rootless daemon 中**预拉过**的评测镜像（例如 `noj-evaluator-python`，L222 已承诺预拉），并指定 `--entrypoint /bin/sh -c true`；若镜像也不在本地，退化为 warning 而非失败。

### N11（低）屏幕 0 的镜像源可达性检查只提 GHCR，未考虑 `NOJ_IMAGE_REGISTRY` 覆盖

- **出处**：§5.5 L219（"GHCR + manifest"）；仓库事实：镜像地址由 `NOJ_IMAGE_REGISTRY` 决定（`docker-compose.prod.yml:148`，默认 `ghcr.io/neuro-oj`）。
- **建议**：检查应在渲染后**针对实际 registry** 发起（或同时检查 `NOJ_IMAGE_REGISTRY` / 用户配的镜像源），否则"配了国内镜像源"的用户仍会在屏幕 0 被判定不可达，或在屏幕 6 才失败。

### N12（低）`--help` 的信息量与首轮 m7 未采纳

- **出处**：§5.1 L163 仍把三个 `--acknowledge-*` 列在全局参数；§5.1 标题写"11 条命令"（L148），实际是 11 条命令 + `backup` 的 5 个子命令 = **16 个动词**。
- **建议**：见 §2.5 的 `--help` 版式（首屏 5 个高频命令 + "其他"折叠，`--acknowledge-*` 只在 `--help --all` 与对应命令的 `--help` 里出现）。

# 第二部分 易用性与 UI/UX 专项

## 2.1 核心问题的可执行答案

**问：一位没有过多接触过计算机科学的学校教练，能不能在短时间内把 Neuro OJ 部署起来？**

**答：能，但"30 分钟"只在一种组合下成立。** 判据如下（假设 A1：下载方式沿用 v1 的 `curl` + `sha256sum -c` + `chmod`，见 `noj-cli/README.md:18-30`）：

| 三个里程碑 | 乐观 | 现实 | 悲观 | 卡在哪 |
| --- | --- | --- | --- | --- |
| **M1 站点可用**（管理员能登录，学生能被手动建号） | **20–30 分钟** | 1–2 小时 | 3–4 小时 | 判题（rootless）；外网拉镜像 |
| **M2 学生能自助注册**（邮件配置完成） | +0（手动建号） | +20–60 分钟 | +60 分钟以上 | 邮件服务商（域名验证、凭据申请） |
| **M3 能判代码题**（judge 可用） | +10–15 分钟 | +20–45 分钟 | +1 小时以上 | rootless Docker（uidmap/linger/家目录空间/预拉镜像） |

**"30 分钟"成立的组合**（可直接写进文档的推荐路径）：

> 服务器已装好 Docker（或本身就是 root）＋ 用 **IP + HTTP** 先上线（不碰域名/证书）＋ **判题先不开**（完成页第 2 步再开）＋ 网络 ≥ 10 Mbps ＋ 会用 SSH 复制粘贴命令。

**任何一项不满足就进入 1–3 小时区间。** 因此最重要的产品建议是 **P1-1：把判题从首装流程移出去**——首装的成功判据应该是"学生能访问到站"，而不是"能判代码题"。把最脆弱的环节（rootless）塞进首装，等于把首装成功率绑在最低的那个环节上。

## 2.2 首 30 分钟时间预算表（逐阶段，含外部依赖标注）

> 计时起点：教练手上有一台 Linux 服务器（能 SSH）+ 一个域名（可选）。终点：学生能注册并做上第一道题。标 ⏳ 的是**必须等待外部依赖**的步骤。

| # | 阶段 | 乐观 | 现实 | 悲观 | 外部依赖 / 备注 |
| --- | --- | --- | --- | --- | --- |
| 1 | 找到服务器 IP/密码、SSH 登录 | 3 | 8 | 30 | 教练常把这一步算在"给我服务器"里；宝塔面板用户会更容易 |
| 2 | 下载 + 校验 + `chmod +x` nojctl（3 条命令） | 2 | 5 | 15 | ⏳ GitHub 可达性（受限网络下 `curl` 直接失败，见 §2.7） |
| 3 | 屏幕 0 前置探测（Docker 已装） | 1 | 3 | 8 | 静默检查，但如果要 30 s 以上，教练会以为卡死（见 §2.3 屏幕 0） |
| 3b | 若 Docker 未装：`apt install docker.io` 或官方源 + `usermod -aG docker` + **重新登录 SSH** | — | 8 | 25 | ⏳ apt 源速度；**"重新登录 SSH 才生效"是经典卡点**（draft-2 未写，见 B7 缺口） |
| 4 | 屏幕 1 配置向导（4 问） | 2 | 4 | 12 | 教练不懂"对外协议/邮件 Provider/首个管理员"的含义 → 靠选项文案（见 §2.3） |
| 5 | 屏幕 2 推导 + HTTPS 反代说明（仅 HTTPS 路径） | 0 | 1 | 15 | 反代要在宝塔/Caddy 里动手；HTTP 路径为 0 |
| 6 | 屏幕 3 rootless 引导（**选"现在开启判题"时**） | 8 | 18 | 45 | ⏳ 预拉评测镜像；需 root 执行脚本；uidmap/linger 常缺 |
| 6b | 选"稍后开启判题"（推荐路径） | 0 | 0 | 2 | 把 45 分钟的风险移出首装 |
| 7 | 屏幕 5 摘要 + 确认 | 1 | 2 | 5 | "迁移 95 条 / deploy_format 3"会让他犹豫（见 §2.3 屏幕 5） |
| 8 | 屏幕 6 拉 7 个镜像（示例 1.2 GB） | 6 (20 Mbps) | 15 (8 Mbps) | 45+ (3 Mbps 或重试) | ⏳ 外网带宽与镜像源；M14 的三条出路在这里生效 |
| 9 | 屏幕 6 `up -d` + 健康等待 + 建管理员 | 3 | 5 | 15 | 管理员创建需要容器内交互输密码（N5） |
| 10 | 屏幕 7 完成页 + 浏览器首访（成功登录） | 2 | 5 | 20 | 域名未解析 / 端口没开 / 防火墙 → 见 §2.7 |
| 11 | 邮件配置（要学生**自助注册**才需要） | 0（手动建号） | 20 | 60+ | ⏳ 邮件服务商审核 + 域名验证；教练最可能在这里放弃自助注册，改手动建号 |
| 12 | ⏳ DNS 生效（若用域名） | 0（提前配好） | 10 | 60 | TTL；建议迁移/切换前把 TTL 降到 300 s |
| 13 | ⏳ 证书签发 + 反代（若用 HTTPS） | 0 | 15 | 40 | Caddy 自动签发约 2–10 分钟，宝塔面板操作更久 |

**汇总**：

- **乐观 ≈ 20–30 分钟**（组合：Docker 已装 + IP/HTTP + 判题稍后开 + 域名证书都不碰 + 20 Mbps）→ M1；学生由管理员手动建号，5 分钟内可做题。
- **现实 ≈ 1 小时 50 分**（判题开启、域名 + 证书要配、8 Mbps）。
- **悲观 ≈ 3.5–5 小时**（Docker 从零装 + rootless 反复失败 + 受限网络 + 邮件服务商流程）。
- **瓶颈排序**：① rootless 判题（45 min 级）→ ② 外网拉镜像（45 min 级）→ ③ 域名/证书/邮件（外部流程，小时级）→ ④ nojctl 自身的交互（分钟级）。

### 2.5.4 口令门禁替代方案对比与推荐（进 v1）

| 方案 | 操作成本 | 抗"手滑" | 抗"无脑抄屏" | 对中文教练友好 | 可脚本化 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 现状：英文全大写长句（draft-2 L195） | 高（39 字符、非母语） | 中 | **低**（屏幕上就印着，L252） | 低 | 需 `--acknowledge-risk` | 只证明"会打字" |
| 按住回车 3 秒 | 低 | 低 | 低 | 高 | 需替代参数 | 容易误触/长按失败（终端差异） |
| **输入屏幕上随机 4 位码**（如 `7F2K`） | **低** | 中 | **中**（必须看当前屏幕） | **高**（中文提示 + ASCII 码） | 需替代参数 | **推荐**：强制"读一眼当前状态行"，成本比英文句子低一个数量级 |
| 输入目标版本号（如 `0.10.1`） | 低 | 中 | 中 | 中 | 需替代参数 | 对"我升到哪"有确认价值，但版本号长、易记错 |
| 只按一次 `y` | 最低 | 低 | 低 | 高 | 需替代参数 | 与"知情确认"的目标最远 |

**推荐组合（可直接写进 §5.3）**：

1. `apply`（版本变更）默认用**随机 4 位码**：门禁前先打印状态行（`最近备份：2 天前（已验证）` / `⚠ 没有可用备份`），然后 `请输入屏幕上的确认码（4 位，区分大小写）：____`；随机码每次刷新，屏幕上只显示一次。
2. 备份不新鲜（> 3 天或没有）时**不降级为"照抄"**，而是给动作：`[b] 现在创建备份并继续  [c] 我知道风险，继续  [n] 取消`；选 `b` 成功后自动继续（这条把 C2 的"形式主义"真正变成"保护"）。
3. `backup restore` / `uninstall --purge` 保留更强门禁，但改成"证明你知道自己在干什么"的形式：**输入要恢复的备份 id 后 6 位**（restore）/ **输入 `DELETE ALL`**（purge）——比随机码更重，因为不可逆。
4. 严格模式 `NOJCTL_REQUIRE_RECENT_BACKUP_DAYS` 保留给运维型用户，默认从 `0` 改为 **`3`**（或按第 2 条的"给动作"路线，让默认也有保护）。
5. 非 TTY 保持 `--acknowledge-*`（必须），但不进 `--help` 首屏。

### 2.5.5 `--json` 与人类输出的分工（补一条契约）

现状已定义（L205-213）。建议补两点（进 v1）：

- **同源**：人类输出的最后一行（`下一步：<命令>`）与 `--json` 的 `next_steps[0]` 必须来自同一个字段，避免两套文案漂移（首轮 m1 的落点）。
- **给教练的"报错截图"友好**：非 0 退出时人类输出末尾固定一段可复制块：

  ── 把下面这段发给维护者 ──────────────
  nojctl 0.1.0 · 命令 apply · 退出码 7 · 2026-09-27 07:12

## 2.6 最小上手材料（15 分钟版）章节清单

新页面 `noj-docs/docs/operators/quickstart.md`（建议由批次 7.5 交付）：

1. **你需要什么**（3 行）：一台 Linux 服务器（能 SSH）· 一个管理员密码（sudo/root）· 一个域名（可选）· 30 分钟。
2. **第 1 步：下载 nojctl**（3 条命令，含校验；如果不会命令行，给"宝塔面板 → 终端"的替代做法）。
3. **第 2 步：运行 `nojctl deploy`**：四个问题分别怎么答，配"不知道就选这个"的建议值（协议选 IP 试用 / 判题稍后开 / 邮件不确定就选手动建号 / 管理员务必创建）。**这一节要写成"照着选即可"，不要解释原理。**
4. **第 3 步：把地址发给学生**（含：怎么给学生建号——邮件未配置时的 3 步截图级说明；以及"首页能打开 ≠ 代码题能评测"的一行提醒）。
5. **第 4 步：现在就做一次备份**（`nojctl backup create` → 抄口令 → 把两个文件拷到别处；给一条可直接复制的 `scp`）。
6. **第 5 步（可选，各约 15 分钟）**：开启判题 / 开启 HTTPS / 配置邮件——各自一节，标题写成"我想让学生能提交代码评测"、"我想让网址是 https 开头"、"我想让学生自己注册"。
7. **出问题了怎么办**：三步法（`status` → `doctor` → `doctor --bundle` 发给谁）+ 常见 5 个症状对照表（打不开 / 登录不上 / 提交一直等待 / 磁盘满 / 证书到期）。
8. **一页速查卡**（可打印）：6 条常用命令 + 两个"绝对不要做"（不要手改 `docker-compose.prod.yml`；不要把备份和口令放在同一台机器）。

## 2.7 降级路径（缺域名 / 缺证书 / 2 GB 内存 / 网络受限）

| 情形 | 会失败在哪（draft-2 现状） | 应给的替代方案（v1） |
| --- | --- | --- |
| **没有域名** | 不会失败：屏幕 1 有"IP"路径（L220）。但完成页给 URL 时可能仍以域名为主（L226 只说"站点 URL"） | 完成页把"**现在就能用**"的 IP URL 放第一行，域名 URL 放"加域名之后"；文档写"IP 也可以，但 IP 变更后要运行 `nojctl apply`"；没有固定公网 IP（家用宽带）→ **明确不支持**并说明需要 DDNS + 手工反代（避免用户以为工具会处理） |
| **有域名但没证书** | 屏幕 2 打印"TLS 不由本站点提供"+ 两行反代示例（L221）；但教练不知道 Caddy/宝塔怎么弄 | 给**一条可复制的 Caddy 配置**（`oj.school.edu { reverse_proxy 127.0.0.1:8080 }`，自动签发证书）+ 宝塔面板的 3 步操作；若都做不到 → 回退 IP + HTTP，并在完成页固定一行风险披露：`当前是明文 HTTP：学生密码在网络上不加密，建议仅内网使用；配好 HTTPS 后运行 nojctl apply 收紧`（draft-2 L224 已有这句话，把它也放到完成页） |
| **只有 2 GB 内存** | spec 未做内存画像；屏幕 0 只查磁盘（L219）；仓库文档：仅启动/诊断需 2 vCPU/2 GiB（`production-deploy.md:21`），同机判题建议 4 vCPU/8 GiB（`:22`），判题单容器默认 1 核、并发默认 2（`judge-workers.md:81,90-99`） | 屏幕 0 增加**内存与 CPU**，并直接给出机器画像：`这台机器（2 核 / 2 GB）：✅ 可以跑网站  ⚠ 不建议在本机判题（判题建议 8 GB 以上）`；`judge=on` 时若内存 < 4 GB，向导明确劝阻并把"稍后开启判题"设为默认；文档给"2 GB 机器怎么跑"一节（关判题 + 限并发 + 加 swap） |
| **网络受限（拉不到镜像/curl 失败）** | 屏幕 0 三出路（镜像源 / 代理 / 别处 pull + `docker save` / `load`）（L219）+ 断点续传（L228） | ① 检查要针对**实际 registry**（N11）；② `docker save/load` 路径要求用户在别处有 Docker——给一条"在你自己的电脑上（装了 Docker Desktop）"的分支说明；③ 提供**离线包申请入口**（群/Release 附件的大 tar），并把 `nojctl images load <tar>` 列为 follow-up（首轮 M14 的建议）；④ 给出国内加速器的 `daemon.json` 片段（可直接抄） |
