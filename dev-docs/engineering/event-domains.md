# NOJ 事件域分离

## 原则

- **DB / 事件日志是事实源**：提交状态、评测结果、私信等持久化数据以 PostgreSQL 为准。
- **Redis Pub/Sub / SSE 是实时投影**：只负责把“事实已变化”的通知推送给在线客户端，不持有第二份状态。
- 客户端收到 SSE 通知后，应通过 REST 拉取最新事实；SSE 事件本身不携带完整状态（除非未来事件日志携带快照）。

## 事件域

| 域 | 职责 | 存储 |
|---|---|---|
| 持久事实 | 提交状态、评测结果、消息、审计 | PostgreSQL |
| 实时通知 | 状态变更触发推送 | Redis Pub/Sub → SSE |
| 客户端投影 | 页面展示 | 前端内存/缓存 |

## 规则

1. 状态变更必须先写 DB，再发布 Redis 通知。
2. SSE 端点只做“订阅 + 转发”，不修改状态。
3. 客户端必须能以 REST 作为最终校准源，SSE 只是加速。
4. 未来引入 `sse_events` 表后，SSE 可重放，但事实源仍然是 PostgreSQL。
