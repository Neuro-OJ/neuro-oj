# 竞赛风控与防作弊机制（Anti-Cheat）

在 AI 领域的能力竞技与学术认证中，维护考纪公正至关重要。Neuro OJ
秉承**人机协同与数据最小化**的安全理念：风控系统定位为**辅助裁判裁决的人工复核线索生成器**，绝不进行未经人工核验的自动化裁决封禁。

---

## 风控核心立场：线索机制，杜绝自动化误杀

::: info 平台伦理立场
所有的风控算法检测结果**仅作为仲裁委员介入调查的参考线索**。系统不会自动对选手执行取消成绩、封禁账号或扣减排名的动作。
在校园网络、实验室集群、企业 NAT
代理等场景下，大量无关选手共享同质环境属于物理常态，**高相似度或特征重合均不等于作弊定论**。
:::

---

## 历史架构演变：客户端 IP 采集机制全面下线

::: warning 机制下线声明（2026-09-28 安全审计 VULN-06）
自 2026-09-28 安全重构起，平台**全面停止采集并物理删除了全部提交来源 IP 数据**。原有的「同 IP 异常分析」与「IP 关联时间线」风控模块被整体移除，数据库 `submissions.client_ip` 列及相关索引已随迁移彻底清空。
:::

### 彻底下线的三大技术裁定

1. **极高的误报率（False Positive）**：
   高校机房、省队集训与线下正规赛场普遍由成百上千名考生通过校园网单一出口 NAT
   共享同一个公网 IPv4 地址。"多账号同 IP
   提交"在正规赛事中属于**必然常态**，依赖 IP
   溯源会产生海量无效误报并严重干扰考务工作；
2. **极易被专业作弊者规避**：
   在线远程考试中，作弊人员使用手机热点、商业代理（VPN）或虚拟网卡即可在数秒内切换出数百个干净
   IP，导致该机制对真正的黑产作弊形同虚设；
3. **数据合规与最小化采集准则**： 恪守《个人信息保护法》与 GDPR
   数据最小化原则，在技术手段证明无效后，系统坚决拒绝存储与评测无关的学员网络指纹。

## 核心算法：代码 Token 指纹查重引擎

平台管理后台的风控面板目前集成基于现代编译原理的**代码相似度分析引擎**。

```mermaid
flowchart LR
    Source[选手提交代码] --> Lexer[词法归一化<br/>剥离注释/字面量/空白，标识符改写为 v1..vN]
    Lexer --> Winnowing[Winnowing 滑动窗口算法<br/>提取抗扰动核心结构指纹]
    Winnowing --> Jaccard[Jaccard 集合交并比计算]
    Jaccard --> Threshold{相似度系数<br>>= 阈值 (默认 0.8)?}
    Threshold -- 是 --> Clue[列为候选对<br/>供风控面板人工复核]
    Threshold -- 否 --> Pass[不列出]
```

### 1. 算法处理流水线

- **按题目与语言分桶**：只在「同一题目 × 同一语言」内两两比较，同一用户自己的多次提交之间不互比；
- **词法规范化（Normalization）**：剥离注释、字符串字面量与所有空白差异，用户自定义标识符按首次出现顺序改写为 `v1..vN`（关键字与常见标准库符号保留，数字常量不归一化），瓦解简单的"洗稿重命名"篡改；
- **Winnowing 特征指纹提炼**：对 Token 序列取 k=5 的 k-gram 哈希，在宽度 w=4
  的窗口内保留最小值作为指纹，保证长度 ≥ 8 个 Token 的公共片段必定命中；
- **Jaccard 相似度匹配**：计算两位选手代码指纹集合的重合比例：
  $$\text{Similarity}(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

### 2. 仲裁面板参数与隐私保护

- **敏感信息隐藏**：风控 API
  返回相似对时**不包含双方源代码**，仅返回提交记录
  ID、所属选手、所用语言、相似度（0~1，4 位小数）与指纹统计指标；
- **可调阈值与容量控制**：默认阈值为 **`0.8`**，单次分析的候选提交上限为 200
  份——超过时接口直接报错并提示按题目逐题分析，**不会静默只算一部分**，避免把「没算到」误读成「没有相似」。

阈值语义、已知误报/漏报边界，以及主办方的复核、处置与申诉流程见
[竞赛代码相似度：判定口径、处置与申诉](../operators/contest-similarity.md)。
