# 竞赛风控数据说明

> Neuro OJ 的竞赛风控只提供**人工复核线索**，不做自动判罚。本页说明当前已落地的「代码相似度」线索，以及**已下线**的「提交来源 IP」机制及其原因。

::: info 设计立场
所有风控结果都不自动封禁账号、取消成绩或修改排名。共享网络、校园网、企业 NAT、代理和动态地址都可能让多个无关账号使用同一 IP，因此**同 IP / 高相似度都不等于作弊结论**。
:::

## 提交来源 IP（已下线）

::: warning 该机制已整体移除（2026-09-28 安全审计 VULN-06）
平台**不再采集、不再存储**提交来源 IP，也不再提供「同 IP 多账号」与「IP 提交时间线」风控视图。`submissions.client_ip` 列、相关索引、`anti_cheat_ip_retention_days` 配置与保留任务均已随迁移删除。
:::

**下线原因**：

1. **误报率极高**：学校机房、高校实验室、集训队与线下赛场普遍有数十至数百名学生经同一出口 NAT 共用一个公网 IP，"多账号同 IP" 在这些场景下是**常态而非异常**，以其作为作弊线索会产生大量误报并误导人工复核；
2. **可规避性**：远程比赛中用手机热点、VPN、多网卡即可轻易改变来源 IP，检测对真正的攻击者近乎无效（低检出、高误报）；
3. **数据最小化**：该字段是为这一机制专门采集的个人数据，机制下线后不再采集、不再存储，也不再需要设定保留期。

后续反作弊聚焦于**代码相似度检测、行为时序分析与作答过程审查**等强相关特征（见下节）。

## 代码相似度

代码相似度检测是风控面板中**唯一**的自动化线索视图（管理后台「相似提交」）。它按**题目 × 语言**分桶（跨题目/跨语言比较无意义），对提交代码做 token 规范化 → winnowing 指纹 → Jaccard 相似度，输出互相高度相似的提交对。

::: warning 已知局限（待重构，不属本轮修复）
分桶使用的是**未经别名规范化的原始语言字符串**，因此 `python` 与 `python3` 这类同义别名会被分进不同桶、永不互相比对，切换别名即可规避查重（2026-09-28 审计 VULN-12）。按审计裁定，本轮**不做局部热修复**，而是立项重新设计查重系统（语言归一化、分词/Token 化、跨语言比对与分桶策略需整体评估）。
:::



::: warning 相似度结果是线索，不是判罚
基于代码 token 指纹的相似度仅供人工复核：阈值过高会漏掉改名洗稿，过低会放大同思路独立实现的误报。接口不返回源代码本身，只返回提交标识、用户、题目、语言、相似度与指纹统计。
:::

- 默认阈值 `0.8`（可调，范围 `(0, 1]`）；默认返回前 50 对，单次上限 200 对。
- 单次分析的候选提交数默认上限 200，超限时建议用 `problem_id` 缩小到单题。
- 候选不会自动封禁账号、取消成绩或修改排名；证据留存与申诉流程另见运营规范。
