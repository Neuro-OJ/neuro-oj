# 竞赛

当前竞赛模块支持类 Kaggle 分数赛，并通过 SSE 推送实时排名。ICPC、IOI、OI 等其他赛制尚未开放。

## 当前规则

- 每道竞赛题配置一个满分，参赛者在规定时间内提交代码、作答客观题或上传 zip 产物。
- 每道题只取该参赛者的最高分，所有题目的最高分相加得到总分。
- 可按题目配置提交次数上限；未配置时不限制提交次数，失败提交也会计入次数。
- 排名按总分从高到低，同分时按达到最高分的时间排序。
- 排名页面通过 SSE 接收更新；**支持服务端封榜**（见下文「做题人」一节），当前不提供滚榜规则。

## 做题人

- 在「竞赛」页浏览公开竞赛并报名 / 参加。
- 竞赛期间在竞赛题目页提交代码、作答客观题套卷或上传 zip 产物。
- 排名页可实时查看排名；竞赛题目是否计入全局统计由竞赛配置决定。
- 支持服务端封榜：可配置公开榜、仅参赛者榜或完全隐藏榜，并设置结束前冻结分钟数。
  封榜期间 REST、SSE 与页面统一返回冻结视图；管理员会明确看到实时完整榜。
- 竞赛题目默认不计入全局榜单，除非运营者设置 `affect_global_ranking=true`。
- **赛期题解门控**：属于「进行中竞赛」的题目，其题解（含他人已发布的）对普通用户整体不可见，
  发布入口同时关闭；竞赛结束（到达结束时间）后**自动恢复**，无需人工干预。
  该判定按时间窗口实时计算，不依赖定时任务。审核员与管理员不受限。
- **赛后复盘**：竞赛结束后，竞赛页出现「赛后复盘」标签，可回看题目并进入题目页查阅官方题解。
  可读性沿用既有赛后放行规则（参赛者可见）。

## 运营者 / 管理员

后台「竞赛」页可以：

- 创建 / 编辑竞赛：标题、时间、题目列表、公开状态、是否计入全局统计和每题提交次数限制。
- 配置榜单可见性与结束前封榜时长。比赛结束后进入待结算状态，待评测清空且管理员发布
  #435 正式成绩快照后，普通用户才会看到正式榜；不会自动暴露未完成评测结果。
- 管理参赛者。
- 查看竞赛排名与提交记录。

竞赛相关 API 与排行逻辑见仓库 `noj-core` 的 `routes/contests.ts` 与 `services/contest/`。
