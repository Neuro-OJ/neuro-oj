# 通知收件箱

统一收件箱把**社区**、**教学**与**比赛答疑**三类通知合并进同一张 `notifications`
表与同一套 API，避免用户在多个入口之间来回切换时漏读或重复读。

## 入口

| 入口 | 路径 | 说明 |
| --- | --- | --- |
| 收件箱 | `/d/:slug/notifications` | 域内收件箱（按使用域过滤） |
| 账号级收件箱 | `/notifications` | 跨域聚合视图 |
| 导航未读红点 | 顶栏铃铛 | 30 秒轮询未读数，不比列表页更实时 |

## 通知来源与语义

| 类型 | 触发 | 深链落点 |
| --- | --- | --- |
| 社区 | 帖子/评论被回复、被 @、审核结果、举报处理 | 对应帖子或评论 |
| 教学 | 作业发布、批阅反馈、学生求助与回复、版本变化、教学通知已读同步 | 作业详情 / 求助线程 |
| 比赛答疑 | 你提出的答疑收到公开或私密回复 | 比赛详情（定位到答疑区） |

三类通知共用 `type` + 来源外键（`post_id` / `comment_id` / `assignment_id` /
`feedback_id` / `event_id` / 数据段 `data`），因此**一次列表请求即可拿到全部类型**。

## 授权模型

收件箱的可见性是**每次请求实时计算的 SQL 条件**，不是写入时固化的快照：

- **共同前提**：`recipient_id = 当前用户`，且账号未被停用；
- **社区通知**：帖子仍存在、未被隐藏、社区功能在该域仍开启；
- **教学通知**：作业与反馈仍存在，且你仍是该班级/该作业的当前参与者；
- **比赛答疑**：通知所属域可访问、源比赛存在且你仍是参赛者或提问者，社区功能开关
  **不影响**比赛答疑（这是本轮修复的一个缺陷：此前关闭社区会连答疑通知一起隐藏）。

因此**权限撤销 = 相应通知自动消失**，不需要额外的"撤销同步"任务；已读状态保留在
`notifications.read_at` 上，恢复权限后仍是已读。

## API

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/v1/notifications` | 分页列表；`domain_id` 可选过滤 |
| `GET /api/v1/notifications/:id` | 单条详情（复用同一授权条件，越权返回 404） |
| `POST /api/v1/notifications/read` | 批量已读（可按 `domain_id` 限定范围） |
| `POST /api/v1/notifications/:id/read` | 单条已读 |
| `GET /api/v1/notifications/events` | SSE：新通知推送 + `Last-Event-ID` 重放 |

SSE 与列表共用同一个 `visible()` 条件：推送前会重新取一次通知，取不到（权限已撤销）
就静默丢弃该事件，不会把标题泄露给已失去权限的客户端。

## 已知限制

- 早期 `community_notifications` 与 `education_notifications` 表已在 0.11 的迁移中
  删除，**历史通知不做数据搬迁**；升级前如有保留需求，请在备份快照中查阅。
- 未读数不做跨域实时合并：导航铃铛按 30 秒轮询刷新，收件箱打开时以列表响应为准。
- 邮件通知与站内通知是两条独立通道：邮件发送前会重新检查成员关系，失败会记入
  `education_notification_emails` 的投递状态，不影响站内收件箱。
