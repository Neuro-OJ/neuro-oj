# 班级与作业：学生和教师指南

班级属于一个[工作空间](./workspaces.md)，作业属于一个班级。学生在题库或作业
页面完成正式提交，满足条件的同域提交会自动计入作业。代码题和产物题不需要
再执行一次独立“上交”；客观题通过卷面交卷完成提交。

## 学生：从邀请到第一份作业

1. 打开老师提供的邀请链接，确认空间、班级和邀请邮箱。
2. 已有账号先登录。没有账号时，按页面允许的邀请注册流程自行创建账号。
3. 接受邀请，加入所属域的基础成员和目标班级学生。
4. 进入空间“我的学习”，打开分配给自己的作业。
5. 查看题目、达标要求、截止时间和当前版本，完成正式提交。
6. 回到作业查看本人进度、老师反馈和求助回复。

邀请不会重置已有账号密码，也不会授予其他班级或域管理权限。如果实例实行
“仅平台管理员开户”，先由平台管理员开户，再登录接受邀请。学校还可以审核
已有域成员的入班申请，是否能加入以该班管理者的处理结果为准。

在学校做引用题时，保持 `/d/学校标识/...` 地址中的学校上下文。同一道公共题在
公共域的练习不会自动计入学校作业。

## 教师：建班与授予助教能力

有教学权限的成员进入空间“班级”创建班级，填写名称、简介和阶段标签。班级
详情提供成员、作业、学生训练详情及设置入口；“教学工作台”汇总当前教学任务。

教练管理本班。助教按授予的能力执行操作，可以分别授权：

- 查看学情。
- 查看学生提交。
- 创建和管理作业。
- 撰写反馈。
- 处理求助。
- 管理学生成员。

仅能查看学情的助教不能因此读取代码。学生只能查看本人学情和相关反馈。教练
可以查看当前本班学生的全部同域提交，但进行中比赛的结果仍按比赛规则保密。

教练移除或交接后失去本班权限，原批注仍保留作者信息。学生离班后保留该班
已有作业与反馈依据，老师不继续读取其后续个人练习；重新入班不会补计离班
期间的提交。归档班级保留授权读取，停止新作业和成员修改。

## 邀请学生与批量导入

班级“成员”页可以填写学生邮箱生成邀请链接，也可以处理当前入班申请、调整
成员角色和助教能力。需要批量加入时，使用“批量入班与邀请”：

1. 下载空模板，或准备 UTF-8 CSV。表头使用 `email`、`username`，可仅填写其中
   一列；需要邀请新学生时必须提供邮箱。
2. 上传或粘贴 CSV。每批最多 500 条，文件不超过 512 KiB。
3. 点击“预览导入”，检查逐行匹配、加入、邀请、重复、跳过和错误说明。
4. 修正姓名或邮箱冲突、重复项后重新预览，再确认执行。
5. 下载执行结果，将首次生成的邀请链接妥善交给对应学生。

```csv
email,username
student-a@example.com,
,existing_student
student-c@example.com,student_c
```

已有本域账号可以直接入班；其他账号或新学生通过邮箱邀请确认加入。CSV 不
直接创建全站账号。用户名与邮箱同时填写时应指向同一账号。

勾选“重签已有有效邀请”会使旧链接失效。邀请令牌只在生成时显示；不要把含
邀请链接的执行结果发布到公共页面。需要再次发放时重新签发，而不是索取账号密码。

## 创建、预览和发布作业

在班级详情创建作业：

1. 填写标题、说明、截止时间。时间按浏览器当地时区填写，留空可不设截止。
2. 从本域题库选题，或粘贴本域已有题单链接并预览。
3. 为每题设置“正式通过”或“最低分”，调整题目顺序。
4. 选择目标学生；默认不接受发布前提交，需要时启用“允许符合条件的发布前
   提交计入”。
5. 保存草稿，预览题目与名单，再发布，或设置未来发布时间。

OI、AI 代码、LLM、产物和客观题都使用现有题目提交方式。最低分要求例如 60 分，
不要求 AC；“正式通过”则使用正式通过判定，不能从最高分反推。

发布固定题目集合、顺序、达标规则和初始目标名单。从题单创建时，在实际发布
时展开题目；源题单后来增删不会修改已发布作业。已发布题目与要求需要调整时，
复制为新任务。定时发布会再次核对资源、权限与名单，失败会保留具体原因并回到
草稿，不会只发布一部分。

未截止作业会自动补入新加入班级的学生，记录实际补入时间。已截止作业不会
自动补入新生，可为其另建补做任务。离班学生不再自动收到之后的新任务。

## 提交怎样计入作业

同一次提交可以计入多份作业，但必须同时满足使用域相同、源题匹配、学生是
实际目标、受理时间符合窗口，以及评测满足本域当前版本策略。入口来源只说明
学生从哪里打开题目，不把提交限制在某一份作业中。

| 视图         | 范围                     | 用途                 |
| ------------ | ------------------------ | -------------------- |
| 按时成绩     | 截止前受理的合格提交     | 查看截止内完成情况   |
| 当前补做进度 | 包含截止后受理的合格提交 | 跟进之后的练习与补做 |

截止前已受理、截止后才评测完成的提交仍会补算按时成绩。截止后新增提交只
更新补做进度。自测用于调试，不计作业成绩。正在进行且结果受保密限制的比赛
提交暂不向作业暴露成绩，不能借作业页面提前查看。

作业页区分未开始、评测中、未达标、已达标、资源不可用和更新中。看到更新中
时等待重新读取，不把旧口径当作当前成绩。正式最高分和是否通过分别计算，
允许最高分来源与正式通过来源不同。

## 版本与重测

**发布固定作业的题目和要求，题面版本与有效成绩跟随使用域题库。**

题库策略为 `any` 时，新发布版本会成为默认作答版本；策略为 `exact(X)` 时，
默认作答继续使用 X。教师切换版本策略后，作业保存版本、策略及操作时间的
变化沿革，重算按时与补做成绩，并提示受影响教师和学生。

已有提交的代码、答案、受理时间和提交时版本保持原值。重测可以改变其当前
正式判定，作业成绩会跟随变化，截止后的作业也会记录影响成绩的变化依据。
平台评测错误不伪造为正式零分，也不抹去已有正式判定。

学生遇到版本变化时先保留代码或答案，刷新确认新题面后再提交。共享资源失效
时，作业标记不可用；本人原提交、历史成绩和既有反馈保留，题面及评测数据不
因历史保留而重新开放。

## 教师：使用成绩矩阵

打开作业详情，切换“按时成绩”与“当前补做进度”。矩阵按学生分页，支持当前
学生、历史学生、题目、状态及可公开正式判定筛选。点击单元格查看授权提交、
得分依据、适用题型的子任务结果和反馈入口；窄屏可以从学生列表进入详情。

先筛选未达标学生，再检查具体提交和评测依据。AI 题没有标准测试点结构时，
不会展示虚构的 OI 子任务。CSV 导出使用当前授权和筛选口径，导出后按学校的
学生数据管理方式保存，不公开班级成绩与源码。

比赛组织权限与教学权限分开：教练不能仅凭班级身份解除 OI 隐藏成绩、ACM
封榜或其他比赛反馈限制。查看比赛管理数据需要该场比赛相应权限。

## 反馈、代码批注与求助

教师可以在作业或学生维度写反馈。提交详情的行批注绑定具体提交、文件与行
范围；适用产物题可以对安全预览的文本文件批注。学生新提交不会自动迁移旧
批注，阅读时确认所属提交和版本。

学生在作业“我的求助”填写问题，可以关联题目和本人提交。获授权的教学人员
回复并标记处理状态；求助只对目标学生和相应教学管理人员开放。教师反馈默认
对相关学生可见。

空间通知会提示发布、版本变化、反馈和回复等事项。邮件发送取决于实例邮件
配置和账号邮箱状态；收到提醒后回到站内读取当前授权内容。成员或教师权限
被撤销后，旧通知不会恢复其访问能力。

## 补题与训练前后比较

“复制／布置补题”可生成独立草稿。矩阵快捷按钮只选择当前页未达标学生；需要
覆盖全班时使用“为全班未达标学生布置补题”，先预览完整候选名单，再明确选
学生与题目。所选学生收到所选全部题目，发布前检查组合是否合适。

从比赛创建补题时，可以选择获授权的实时榜或已发布正式成绩依据。待评测、
资源不可用或未参赛记录会在预览中说明。新任务独立计算，不改原比赛提交、
排名或快照，也不改变原作业成绩。

作业矩阵的学生单元格详情提供前后比较，学生也可在本人作业详情中查看。填写
两段按顺序、不重叠的时间窗，范围包含开始、
不包含结束，再显式执行比较。比较展示正式通过题数、达标题数、有分数题数、
提交与候选数量，以及评测中和版本不匹配数量；逐题可追溯来源提交、评测版本
及当前策略。

没有成绩不当作零分。比较用于描述所选时间内、当前题库口径下的变化，不替代
原作业截止成绩，也不把分数变化解释为学生能力评价。
