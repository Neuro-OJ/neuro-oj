# 提交代码

本页说明提交代码的约定：语言选择、函数实现与提交后的流程。

## 选择语言

| 语言标识 | 说明 |
|----------|------|
| `python3` / `python` | Python 3（默认双容器运行时） |
| `cpp` / `c` / `javascript` | 标识已预留，暂无评测运行时 |

::: warning 运行时现状
当前评测运行时**仅完整支持 Python**（多语言评测为项目的决策性不做项）。`cpp` / `c` / `javascript` 是提交接口预留的语言标识，尚无评测运行时，请使用 Python 提交。
:::

题目可选的编程语言由出题人配置，以题目详情页显示为准。

## 实现题面要求的函数

优先实现题面声明的函数。例如：

```python
def solve(a: int, b: int) -> int:
    return a + b
```

不要依赖顶层 `print()` 作为答案输出——Neuro OJ 的 Python 双容器评测通过 Solution Host 加载你的模块，由 evaluator 调用函数评分。

## 调试输出

`print()` 可以用于辅助调试，但它不是答案通道。注意：当前 Solution 的 stdout 是评测协议通道，用户代码直接 `print()` 的普通文本不会作为评测输出展示，因此不要依赖它来查看调试信息。

## 代码限制

- 代码体积上限 **100KB**。
- 时间与内存限制由题目的运行时配置决定，超出会得到对应的资源限制状态。

## 产物提交

如果题目标记为「产物提交（artifact）」，请按题面要求上传一个 zip 文件，而不是填写代码。Judge Worker 会将 zip 解压到 Solution 容器，并从约定的 `submission.py` 入口加载；题目可能要求使用 `noj-solution-ai` 提供的 CPU PyTorch、CV/ML 依赖。

上传大小受题目配置和系统硬上限共同限制。产物提交不支持重测；如需修改产物，请重新提交。

## 预测提交

如果题目标记为「预测提交（prediction）」，请在**你自己的本地 GPU** 上完成训练 / 推理，然后上传**单个预测结果文件**，而不是代码或 zip。

- 公开数据集由题面**外链**提供，请自行下载；平台不托管数据集。
- 提交物必须是**单个数据文件**，允许的扩展名：

  ```text
  .csv .tsv .jsonl .json .txt .npy .npz .parquet
  ```

  禁止一切 pickle 类格式（`.pkl` / `.pickle` / `.pt` / `.pth` / `.bin` / `.joblib` / `.ckpt`）；即使改了扩展名，含 pickle 协议头或 NUL 字节的文件也会被拒绝。
- 请按题面约定准备好 ID 列 / 行顺序；服务端会校验预测与隐藏标签的 ID 对齐，错位会报错或影响得分。
- 评分在服务端**单个 Evaluator 容器**内对照隐藏标签完成，**不会运行你的代码**，也**不会把隐藏标签下发到你的机器**。
- 上传大小受题目配置和系统硬上限共同限制。**预测提交不支持重测**；如需修改预测，请重新提交。
- 结果详情会逐用例展示通过状态，但隐藏用例不会展示标签内容。

出题人视角的完整约定见[出预测提交题](../problemsetters/prediction-problems.md)。

## 自测

编辑器提供「自测」功能，会向评测队列提交一个 `self_test` 任务，使用你当前的代码运行一次评测（不进入正式提交记录）。适合在正式提交前快速验证语法、函数签名与基本行为。

自测同样受代码大小、语言与运行时配置限制；结果可在队列页查看，状态与正式评测一致。

## 提交后

1. 任务进入评测队列，编辑器侧栏实时显示排队位置与状态。
2. 在「提交记录」页查看全部历史，可按题目、语言、状态、时间段筛选。
3. 打开单条提交查看详细结果。

提交详情页展示状态徽章、得分、用时与内存、标准输出与代码。其中代码与用例级详情仅**你自己和管理员**可见。

## 常见错误

- 函数不存在（`NotFoundError`）：函数名与题面声明不一致，或模块无法导入。
- `finished` + 0 分（或部分分）：返回类型或结果不满足评分条件。
- `error`：评测环境或题目配置异常，通常不是改代码能解决的，请联系运营者。

完整状态说明见[理解结果](results.md)。
