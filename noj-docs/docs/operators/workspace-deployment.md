# 工作空间部署与平台治理

一套 NOJ 部署是一个 Instance。公共题库、学校和团队以 Domain 分隔，班级归属于
各自域；账号由实例统一管理。部署方式仍使用
[noj-cli 生产部署流程](./production-deploy.md)，不需要为每个学校部署一份数据库。

本文面向平台管理员。域管理员的操作见[工作空间指南](../features/workspaces.md)，
教师和学生的操作见[班级与作业指南](../features/classroom-assignments.md)。

## 选择公开、私有或混合模式

实例访问、账号注册和域访问是三项独立政策。需要开放公共题库时，实例本身必须
允许公开访问；私有学校域仍可以仅允许成员进入。

| 场景       | 实例访问     | 账号注册                       | 域的建议设置                           |
| ---------- | ------------ | ------------------------------ | -------------------------------------- |
| Public OJ  | 公开访问     | 开放注册，或按运营要求邀请注册 | `main` 公开，按需直接加入或审核        |
| Private OJ | 仅已登录账号 | 邀请注册或仅平台管理员开户     | 学校域仅成员进入、接受邀请、不公开发现 |
| Mixed OJ   | 公开访问     | 开放或邀请注册                 | 公共 `main` 加多个私有学校域           |

“公开访问”只决定匿名是否能进入实例，不授予私有域成员身份。开放注册也不
自动加入学校。Private OJ 可以把已有学校域设为默认导航空间；旧无域兼容题目
链接始终归 `main`，不会因默认设置而指向学校。

## 配置实例政策

平台管理后台进入“实例政策与空间治理”（`/admin/instance`）：

1. 分别保存实例访问、账号注册和工作空间创建政策。
2. 选择已有空间作为默认工作空间，设置每个用户可负责的空间数。
3. 如需学校邀请新生注册，启用“允许域管理员签发新账号注册邀请”。该开关
   适用于邀请注册，不允许绕过“仅平台管理员开户”。
4. 设置实例允许的模块、新域默认资源额度、资源上限及 LLM 日/月上限。
5. 使用普通账号分别验证公共入口、学校邀请、学校成员和外域访问结果。

班级依赖教学组织，作业依赖班级，学情依赖作业；表单会协助调整依赖。实例
模块上限限制域可启用的功能，不代表任何用户自动取得该模块资源权限。

工作空间创建可以仅限平台管理员、申请审核或用户直接创建，初始默认为仅
平台管理员。治理目录支持按状态或关键词筛选空间，创建申请在审核目录处理。
批准前确认负责人、空间用途、访问方式和额度。

Community、Education、Team、Custom 是初始化模板，域管理员后续可以调整
允许的配置。重新应用模板应先看差异；它不会清除成员、资源或历史。

## 域治理与账号治理

域负责人及管理员负责日常成员、题库、教学和 Provider。平台管理员通过明确
目标域的治理入口处理配置、额度和暂停；这些操作保留审计依据。

归档保留授权只读历史，停止新业务写入；暂停阻止普通用户进入，由平台治理
人员处理后恢复。空间没有连带物理删除入口，历史版本、引用与提交需要继续
保留。负责人交接必须确保有效负责人，不能通过直接移除留下无负责人空间。

全站封禁、账号状态和平台注册政策优先于域邀请。教师 CSV 只匹配已有账号或
生成邀请，不代替账号开户。仅管理员开户时，在平台账号管理中开户，然后让
学生登录接受班级邀请。

## 资源上限怎样生效

新域默认额度只在创建时复制，修改默认值不自动改变已有域。实例上限与各域
配置共同决定有效额度。空值表示相应层级不额外限制，`0` 禁止增加该项使用。
默认域迁移不凭空增加新的数值额度。

| 资源     | 占用与操作                                               |
| -------- | -------------------------------------------------------- |
| 成员     | 成功加入时占用名额；并发加入不能超出最后一个名额         |
| 题库条目 | 本地题和共享引用均占用条目额度                           |
| 存储     | 源题文件归源域，学生产物归提交域；共享不重复计来源字节   |
| 提交频率 | 新提交同时遵守实例、域及既有用户限流                     |
| LLM      | 使用域、用户、源题、用户与题目组合及单次评测预算共同限制 |

域管理员只能降低当前有效额度，提高需要平台治理权限。降低到已用量以下
不会自动清除成员或文件，只阻断进一步增加。查看配置值、有效值和实际占用
后再调整，不能把共享题目数量当作复制文件量。

产物上传先预留容量，再按实际对象结算；失败会释放预约。有限额度遇到未核实
的历史存储时，应先核实存储基线，不能把未知字节当零。Redis 故障时，无法可靠
执行的限额操作会拒绝，排查 Redis 和 Gateway 后重试。

## 学校的 Provider 与用量

每个域独立配置 Provider、默认模型和 LLM 配额。新学校不继承平台或 `main`
密钥；共享公共 LLM 题也使用学校的配置与预算。来源题的旧模型设置不会强制
学校使用来源模型，也不会回退到公共域密钥。

已有平台 Provider、默认模型和用量归入 `main`。升级后逐域检查启用状态、默认
模型及配额，再让学生使用 LLM 题。历史尝试保留当时解析的 Provider、模型和
预算；停用阻止新调用，保留历史依据。

同域模型别名在空间 LLM 页面单独管理，保存本域 Provider 与真实模型的映射。
旧平台别名迁入 `main`，新学校需要配置自己的同名能力；`default` 继续使用
学校默认配置。引用题不继承源域映射。Provider 和别名分别保存配置版本，遇到
并发修改先重新读取再确认，不把空间设置版本当作所有 LLM 配置的共同版本。

Provider 的 RPM/TPM 用于限制每分钟请求数和 Token 数，`0` 不额外限制。调用
同时受实例、域和用户预算约束；RPM/TPM 不取代日/月额度，也不承诺上游账单
绝对封顶。升级后检查这些限额及别名，再执行一次学校实际 LLM 评测。

日/月配额包含调用次数、Token 和整数费用，界面显示实例上限。调用前预估
预占、调用后结算实际用量，预估误差和上游账单可能不同。部署运营需要检查
持久用量与上游账单，不承诺估算费用是上游账单的绝对上限。

不同学校模型与预算可以不同，成绩不用于未经解释的跨校比较。当前 Judge
基础设施仍共享；学校额度不代表独占评测机。

## 协调升级与历史数据核实

工作空间契约是 core、UI、Gateway、CLI 和 IDE 的协调升级，评测协议与 Judge
也应按同一发布版本配套。使用包含该能力的同一 Release 和部署文件，不混用
旧客户端跨域提交。题包采用 `format_version: 2`，导入目标域由操作指定：

```bash
noj-cli problem import --domain school --dir /path/to/problem-bundles
```

导入写入草稿，检查题号、内容及权限后显式发布。题包不携带部署域 ID 或 Provider
密钥，重复更新已有题目也需要检查当前草稿状态。

预测题和界面题也使用格式 2 及不可变发布版本。预测题上传单个预测结果文件，
由评分器读文件计算成绩，不运行学生代码；界面题的 `ui.html` 与可信执行模板
一起属于题目版本，浏览器只提交参数。升级时应使用同时支持这些模式的
core、UI、Judge 和 SDK 镜像，确认镜像白名单，再分别执行一次实际预测评分与
界面自测／正式提交。仅更新页面或沿用旧 Judge 不足以验证执行链。

升级前安排维护窗口，记录账号、题目数字号、提交、版本、评测尝试、比赛、 Provider
和存储情况。特别核实旧 U 题和旧比赛；遇到不符合预定迁移假设的数据，
先制定具体处理方案，不直接清空数据库。现有题目、提交、版本和评测尝试的
稳定身份应保留，历史未知版本也不应伪造。

升级应先建立默认域及绑定、回填归属、核对完整性，再执行非空与旧分类收缩。 使用
Release 自带的迁移和初始化工具；不要手工修改迁移日志、直接删历史
引用或通过重建数据库掩盖错误。旧 P 题数字在 `main` 保留，题号唯一范围改为域内。

## 备份、校验和隔离恢复

迁移前保存完整快照，同时保存加密密钥和配置。备份文件与解密口令应异地
分别保存。以下命令在安装目录执行，完整参数见[CLI 手册](./cli.md)：

```bash
noj-cli backup create
noj-cli backup verify backups/snapshot-YYYYMMDD-HHMMSS.nojbackup --deep
noj-cli backup drill backups/snapshot-YYYYMMDD-HHMMSS.nojbackup \
  --passphrase-file /secure/noj-backup-passphrase \
  --docker-host unix:///run/user/1000/docker-noj-restore-drill.sock
```

恢复演练必须使用专门的隔离 Docker daemon；通过
`--docker-host` 或 `NOJ_DRILL_DOCKER_HOST` 显式指定 socket。不要把生产宿主机的
默认 Docker socket 传给演练命令。daemon 的独立 data root、网络和 Compose 项目
准备方式见 [P8 演练说明](../../../dev-docs/engineering/architecture-remediation-p8.md)。

创建快照、文件校验与业务恢复是三项不同证据。`verify` 校验文件，`drill` 在
独立环境恢复并检验业务；查看实际演练报告中的数据量、成功项、失败项和
RPO/RTO，不把一次构建或备份文件存在当作恢复成功。

升级后的实际检查包括：公共域普通做题、学校邀请与班级作业、两个私有域的
隔离、公共题引用与撤销、同域 LLM 调用归属，以及历史提交和反馈读取。保留
验收记录，发现迁移或客户端契约不一致时暂停开放新入口，修复并再次验证。
完成本实例的备份与恢复验收后再开放正式使用。

## 邮件与教学通知

部署邮件服务后，作业发布、反馈、回复、版本和资源变化可以提示相关成员。
站内通知与实时更新仍按当前成员和班级关系授权；邮件发送前也会重新检查
授权和邮箱状态。服务重启后从持久待发送记录恢复，失败按重试策略继续处理。

检查邮件送达时参阅[邮件送达与退信处理](./email-delivery.md)。通知不取代成绩
详情，邮件也不携带学生代码或私人反馈全文。查看最新业务结果仍需登录站内
并具有当前权限。
