## Context

题目详情页使用 Nuxt UI 的模态框承载“加入题单”操作。当前模态框关闭时，插槽内容仍会参与页面布局，导致题单操作文案和按钮出现在入口下方。

## Goals / Non-Goals

**Goals:**

- 未打开模态框时不渲染题单操作内容。
- 每次打开面板时加载当前用户的题单并初始化临时操作状态。

**Non-Goals:**

- 不调整题单 API、权限或题目加入逻辑。
- 不改动模态框的视觉样式与交互文案。

## Decisions

- 使用 Nuxt UI 的 `v-model:open` 受控状态和 `#body` 正文插槽。组件库会在关闭时卸载正文，确保操作区不参与题目页布局，并把内容渲染到弹窗中。
- 在关闭事件中统一重置选择项、新题单输入和创建态，保证重新打开时不会复用过期状态。相比仅依赖 `unmount-on-hide`，该方式在组件库保留插槽 DOM 时仍然可靠。
- `useApi` 显式导入项目的 Toast 封装，避免与 Nuxt UI 同名自动导入冲突；所有 API 失败均保留原始 HTTP 错误并展示后端错误信息。

## Risks / Trade-offs

- [关闭时组件内部状态尚未卸载] → 显式重置本地状态，保证下次打开一致。
- [加载个人题单请求失败] → 保持现有静默加载与后续操作错误处理，不改变 API 错误语义。

## Migration Plan

前端发布后立即生效；如需回滚，仅还原该组件的条件渲染与关闭状态处理。
