## Why

传统 OJ 的题库是「题号列表 +
扁平标签」，学习者面对上千道题时最大的困惑是「下一道该做什么」。 NOJ 面向 AI
竞赛（IOAI / NOAI / LMCC），知识点之间有清晰的前置关系（如「线性模型 → 正则化 →
过拟合与泛化」），且题目分数天然连续，非常适合用「知识图谱 +
同类题从易到难」组织练习。

现状：

- `tags` 为扁平结构（无层级、无前置关系），由人工维护，跨题一致性差；
- `problems.difficulty` 只有 `easy/medium/hard` 三档且由出题人主观填写；
- 题单靠人工编排题号，无法回答「我在某个知识点上掌握到什么程度」。

本变更把**平台维护的 AI 知识图谱**作为 NOJ 的核心差异化能力：每道题由 AI
自动挂载到图谱节点， 难度由 AI
冷启动并用提交数据持续校准，学习者可以按知识点从易到难系统掌握一类题目。

## What Changes

- 新增**平台级知识图谱**：节点（知识点）+ 前置边，以仓库内 YAML
  为唯一真相源，经代码评审后导入， CI 校验无环、无悬挂引用。各域不可扩展或修改。
- 新增**题目—知识点挂载**：每道题 1 个主知识点 + 0–3 个次要知识点，记录来源（AI
  / 人工）、 置信度与打标所依据的题目版本。
- 新增 **AI 自动打标**：题目发布新版本时投递后台任务，经 LLM
  网关调用模型，只允许从图谱已有节点中选择；
  低置信度结果进入平台审核队列；人工确认结果优先于 AI。提供存量题目批量回填。
- 新增 **LLM 网关平台用途调用通道**：core
  以服务凭据发起系统级调用，独立计入平台额度并审计 （现有通道只接受评测
  eval_token）。
- 新增**连续难度分**：AI
  给出知识点内难度先验，按提交数据贝叶斯式持续校准；现有三档 `difficulty`
  保留为展示派生值。
- 新增**掌握度模型与学习路径**：按用户×知识点物化掌握状态；图谱页点亮已掌握节点，节点页给出
  从易到难的题目阶梯与「下一题」，题目页给出「同类下一题」。
- 新增**覆盖度面板**：向平台与出题人暴露题量不足、难度断层的知识点。
- 比赛进行中与比赛保密保护中的题目不展示知识点，不进入阶梯。

## Capabilities

### New Capabilities

- `knowledge-graph`: 平台知识图谱、题目知识点挂载、AI
  打标与审核、难度校准、掌握度与学习路径。

## Impact

- `noj-core`：新表与迁移；`problems` 新增知识点挂载与难度分；`runtime/tasks`
  新增任务类型 `knowledge.tag` / `knowledge.calibrate` /
  `knowledge.mastery`；发布流程与有效成绩变更处投递任务； 新增公开读取 API
  与平台管理 API。
- `noj-llm-gateway`：新增平台用途内部调用端点与额度归属。
- `noj-ui`：新增图谱页、节点页、审核队列与覆盖度面板；题目页增加知识点与「同类下一题」。
- 仓库：新增 `noj-core/data/knowledge-graph/` 图谱源文件与校验脚本，纳入 CI。
- 成本：AI 打标按题目版本计费，单题一次调用；存量回填需一次性预算。
- 隐私：发送给模型的内容仅限题面、公开样例与评测器/参考解摘要，**不发送隐藏测试数据与用户提交**。
