## Why

传统 OJ 的题库是「题号列表 +
扁平标签」，学习者面对上千道题时最大的困惑是「下一道该做什么」，教练也很难
看清每个学生缺哪块。NOJ 面向 AI 竞赛（IOAI / NOAI /
LMCC），知识点之间有清晰的前置关系（如「线性模型 → 正则化 →
过拟合与泛化」），且题目分数天然连续，非常适合用「知识图谱 +
同类题从易到难」组织练习与教学。

现状：

- `tags` 为扁平结构（无层级、无前置关系），由人工维护，跨题一致性差；
- `problems.difficulty` 只有 `easy/medium/hard` 三档且由出题人主观填写；
- 题单靠人工编排题号，无法回答「我在某个知识点上掌握到什么程度」，教练也无法按知识点看班级。

本变更把 **AI 竞赛知识图谱** 作为 NOJ
的核心差异化能力：官方提供可评审、可版本化的图谱内容包，每道题挂到
知识点上（人工或
AI），难度由先验冷启动并用提交数据校准，学习者按知识点从易到难系统掌握一类题目，教练按
知识点看班级掌握分布并布置作业。

NOJ
是开源项目，既有公共实例，也有学校/集训队自部署的内部训练实例，因此设计同时满足：实例可替换或扩展
图谱、不依赖外部 LLM 也能完整使用、可整体关闭。

## What Changes

- 新增**图谱内容包**：官方包随仓库发布（`noj-core/data/knowledge-graph/`，CC
  BY-SA 4.0，与代码分开版本化）， 节点 + 前置边，CI
  校验无环、无悬挂。**实例管理员可整体替换或在官方包之上扩展**；单个域不可修改。
- 新增**题目—知识点挂载**：每道已发布题目「已归类」（1 个主知识点 + 0–3
  个次要）或「未归类」；出题人与实例 管理员可**人工挂载**；人工结果优先于 AI。
- 新增 **AI
  自动打标（默认关闭）**：实例管理员显式开启后，题目发布新版本时自动打标；只能从图谱已有节点中
  选择；低置信度进入审核队列；支持本地模型（内网 OpenAI
  兼容服务），题面可不出内网。
- 新增 **LLM 网关平台用途调用通道**：core
  以服务凭据发起系统级调用，独立计入平台额度并审计（现有通道只接受 评测
  eval_token）。
- 新增**连续难度分**：AI 或出题人先验冷启动，按提交数据贝叶斯式校准；现有三档
  `difficulty` 改为派生展示。
- 新增**掌握度与学习路径**：图谱页点亮已掌握节点，节点页给出从易到难的题目阶梯与「下一题」，题目页给出
  「同类下一题」。
- 新增**讲解文档位置**：节点可关联一篇讲解（内容包 `docs/`），先预留并试点 10–20
  个基础节点。
- 新增**教练视角**：班级 × 知识点掌握热力图；按知识点从阶梯中挑题生成作业。
- 新增**覆盖度面板**：暴露题量不足、难度断层、未归类与待确认的知识点/题目。
- 新增**总开关**：实例可整体关闭知识图谱功能。
- 比赛进行中与比赛保密保护中的题目不展示知识点，不进入阶梯与统计。

- `knowledge-graph`:

  教练视角、覆盖度与总开关。

## Impact

- `noj-core`：新功能目录
  `src/features/knowledge/`（按功能切片结构，`defineFeature` 声明路由与
  `knowledge.tag` / `knowledge.calibrate` / `knowledge.mastery` 任务）；表定义
  `src/shared/db/schema/knowledge.ts`
  与迁移；运行时配置项；发布流程与有效成绩变更处经任务队列投递任务（不 import
  功能代码）； `scripts/noj.ts knowledge import` 与 `noj-cli` 对应命令。
- `noj-llm-gateway`：新增平台用途内部调用端点与额度主体。
- `noj-ui`：图谱页、节点页、题目页知识点与「同类下一题」、人工挂载与审核队列、覆盖度面板、班级热力图与按知识点
  布置作业。
- 内容：`noj-core/data/knowledge-graph/`（官方内容包 + LICENSE +
  讲解文档），图谱校验纳入 CI。
- 成本：AI
  打标默认关闭；开启后每题每版本一次调用，内容不变跳过；存量回填需一次性预算。
- 隐私：发送给模型的内容仅限题面、公开样例与评测器/参考解摘要，**不发送隐藏测试数据与用户提交**；可使用本地模型。
