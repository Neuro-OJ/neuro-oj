## Purpose

让重复部署时的配置复用行为明确可见，避免用户在不了解后果的情况下覆盖已有生产配置，同时保持非交互部署的自动化兼容性。

## ADDED Requirements

### Requirement: 交互式部署先确认是否复用已有配置

生产配置向导在检测到已有配置文件且处于交互模式时 MUST 在逐项配置前询问用户是否使用先前配置；配置不完整时选择复用 MUST 保留已有值并继续进入补齐流程。

#### Scenario: 用户确认复用

- **WHEN** 已存在生产配置且用户选择使用先前配置
- **THEN** 脚本 MUST 保留已有配置内容
- **AND** 如果配置完整，脚本 MUST 跳过逐项配置提问并继续执行后续校验或部署
- **AND** 如果配置不完整，脚本 MUST 使用已有值作为默认值并进入补齐流程

#### Scenario: 用户拒绝复用

- **WHEN** 已存在生产配置且用户选择不使用先前配置
- **THEN** 脚本 MUST 进入逐项配置向导
- **AND** 用户 MUST 能重新填写并覆盖配置项
- **AND** 逐项配置项 MUST NOT 默认显示或沿用原配置值

#### Scenario: 首次部署没有先前配置

- **WHEN** 生产配置文件不存在或仅包含初始化占位值
- **THEN** 脚本 MUST 直接进入首次配置向导，不要求用户确认复用不存在的配置

#### Scenario: 非交互部署

- **WHEN** 使用 `--non-interactive` 执行部署
- **THEN** 脚本 MUST 不等待复用确认输入
- **AND** 脚本 MUST 按现有配置完整性检查决定继续或失败

### Requirement: 邮件服务可以暂不配置

生产配置向导 MUST 提供“暂不配置邮件”选项；选择该选项时生产配置校验 MUST 通过邮件相关检查，且系统不得尝试发送邮件或记录包含密码重置令牌的链接。

#### Scenario: 用户跳过邮件服务

- **WHEN** 用户在配置向导中选择暂不配置邮件
- **THEN** 脚本 MUST 写入表示邮件服务已关闭的配置
- **AND** 脚本 MUST 跳过邮件服务密钥提问
- **AND** 生产服务 MUST 能通过启动配置校验

#### Scenario: 邮件功能未配置时请求找回密码

- **WHEN** 邮件服务处于暂不配置状态且系统收到找回密码请求
- **THEN** 系统 MUST 不发送邮件
- **AND** 系统 MUST 不把重置链接或令牌写入日志
