## Context

生产部署入口已经能保留已有 `.env.prod` 并在配置不完整时进入交互式补齐流程。当前交互向导没有在入口处说明是否复用配置，重复安装时容易让用户误以为必须重新填写。

## Goals / Non-Goals

**Goals:**

- 在已有配置时提供清晰的复用确认。
- 复用选择为“是”时不改写配置。
- 选择“否”时复用现有逐项向导完成覆盖。
- 保持首次部署和非交互模式的既有行为。

**Non-Goals:**

- 不新增环境变量或命令行参数。
- 不改变配置字段、密钥生成规则、部署校验和备份策略。

## Decisions

- 在 `initialize_env` 判断已有配置完整后、进入部署动作前发起确认，而不是把确认放入每一个字段提示中。这样复用配置可以真正跳过所有重填操作。
- 仅对交互模式且已有 `.env.prod` 提问。首次配置不显示复用问题；不完整配置选择复用时保留已有值并进入现有补齐向导。
- 使用现有 TTY 读取机制，以支持 `curl | bash` 场景；非交互模式沿用配置门禁，不引入阻塞。
- 复用确认默认为“是”，降低升级/续装的操作成本；明确选择“否”才覆盖配置。

## Risks / Trade-offs

- [用户误选复用] → 提示中明确说明将跳过逐项填写，并提供 `N` 进入覆盖流程。
- [管道输入无法交互] → 继续使用 `/dev/tty`；没有 TTY 时保持现有手工编辑提示。
- [旧配置已过期] → 复用前仍执行现有完整配置、HTTPS、socket 和镜像校验。

## Migration Plan

无需数据迁移。升级后首次进入已有完整配置的交互式部署时会看到一次确认；选择 `Y` 保持原行为，选择 `N` 可重新填写。
