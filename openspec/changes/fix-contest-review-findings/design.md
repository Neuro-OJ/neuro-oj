## Context

竞赛题目路由目前无条件要求访问者已参赛，违反竞赛结束后公开可见的既有业务规则。ICPC 排名查询已用报名时间和用户 ID 使结果稳定，但规范只描述了前三个排序字段，造成代码与规范不一致。

## Goals / Non-Goals

**Goals:**

- 在结束状态跳过参赛者检查，同时保留登录要求和赛前限制。
- 将现有 ICPC 确定性平局规则写入可测试的规格。
- 以服务和路由测试锁定行为。

**Non-Goals:**

- 不改变非公开竞赛详情的可见性。
- 不更改竞赛提交、历史提交或排名公开策略。
- 不在本次修复中重构其他管理路由的 RBAC 守卫。

## Decisions

- 在 `requireContestAccess` 取得动态 `status` 后，只有非 `ended` 的竞赛才检查参赛资格；因此结束后的题目端点仍使用认证中间件，但向任意登录用户开放。该策略最小化变更，且不会让未登录用户绕过端点认证。
- 保留 SQL 中的 `registered_at ASC, user_id ASC` 作为前三项相等时的稳定次序，并将其明确为 ICPC 规则的次级排序字段。移除字段会导致同分行的顺序不确定。

## Risks / Trade-offs

- [结束后的私有竞赛题目向任意登录用户开放] → 这是题目访问规则的明确要求；竞赛详情端点仍保留非公开可见性校验。
- [稳定次级排序让完全相同成绩获得不同序号] → 现有响应使用连续 `ROW_NUMBER`，明确规则可避免客户端观察到不稳定顺序。
