## Context

设置页已经在选择文件时检查头像类型和 2MB 大小限制，但上传接口调用没有独立的错误分支。统一 API 层虽然会处理未静默的请求错误，但头像流程需要明确控制“失败通知”和“成功通知”互斥，尤其要覆盖服务端再次拒绝超限文件的路径。

## Goals / Non-Goals

**Goals:**

- 保留前端即时大小校验，避免明显超限文件发起请求。
- 对上传接口返回的大小限制及其他可识别错误展示错误通知。
- 上传失败时不更新头像状态、不展示成功通知，并始终结束 loading 状态。

**Non-Goals:**

- 不调整后端 2MB 限制、文件类型校验、存储策略或 API 响应格式。
- 不引入新的通知组件或第三方依赖。

## Decisions

- 头像上传请求使用 `silent: true`，由设置页在 `catch` 中通过已有的 `extractApiError` 展示通知。这样避免统一 API 层与页面同时 toast，且让该流程明确拥有错误反馈。
- 大小限制文案沿用后端已有中文错误文案，并与选择阶段的即时提示保持一致；其他错误沿用后端/统一错误提取结果。
- 以纯函数测试覆盖错误提取/大小判断相关行为，页面只负责组合 API 调用与通知，避免引入难以稳定挂载 Nuxt 页面测试的测试依赖。

## Risks / Trade-offs

- [Risk] `silent: true` 会跳过 API 层默认通知 → 页面上传流程统一在 `catch` 中通知，其他请求行为不受影响。
- [Risk] 浏览器端预校验与后端限制存在重复 → 重复校验用于减少无效请求，后端仍是最终安全边界。
