# 变更提案：使用服务器 IP 作为域名默认值

## 背景

前后端生产安装向导当前要求用户手动填写 `DOMAIN`。对没有域名的新用户，这一步不直观；但直接自动使用公网 IP 也可能受到云厂商 NAT、内网地址、多网卡和 HTTPS 证书限制。

## 目标

- 自动检测服务器首选 IPv4，并作为 `DOMAIN` 的默认值。
- 用户直接回车即可使用检测到的 IP，也可以输入正式域名覆盖。
- 根据 IP 或域名给出合适的 `APP_URL` 默认值和生产 HTTPS 提醒。
- 不放宽 core 对生产 `APP_URL` 必须使用 HTTPS 的校验。

## 方案

优先使用系统路由到公共 DNS 的出口 IPv4（`ip -4 route get` 的 `src`），失败时从 `hostname -I` 选择第一个非回环 IPv4。检测不到时保持现有必填输入行为。域名输入框将展示“可直接回车使用服务器 IP”的提示，IP 默认只作为临时或已有 HTTPS 代理场景的便利选项。

## 风险与回滚

云服务器可能返回私有地址或某个非公网网卡地址，用户仍可在提示中改填域名。IP 场景不自动启用 HTTP，避免破坏生产安全策略。回滚时移除 IP 检测函数和默认值即可。
