# 变更提案：前后端生产部署兼容服务器面板

## 背景

NOJ 的前后端生产部署通过 `install.sh` 下载源码，再由 `deploy.sh` 使用 Docker Compose 启动 core、ui、Judge、数据库、Redis、对象存储和反向代理。使用宝塔等服务器面板的用户通常已经通过面板安装 Docker，但当前安装流程没有识别面板，也没有说明域名和反向代理应由谁管理。

## 目标

- 在前后端 bootstrap 和生产部署检查阶段自动识别宝塔。
- 复用面板已安装的标准 Docker/Compose，不依赖不稳定的面板 API。
- 明确前后端 Compose 自带 Nginx，面板只需将域名转发到 `NGINX_PORT`，避免重复占用 80/443。
- 不覆盖宝塔已有站点、反向代理、容器和配置。
- 保留生产部署的镜像签名、配置权限、Judge 隔离 socket 等安全检查。

## 非目标

- 不自动调用宝塔 API 创建站点或反向代理。
- 不自动修改宝塔 Nginx、证书、防火墙或 DNS。
- 不自动安装、升级或替换 Docker daemon。

## 方案

两个脚本都增加 `--panel auto|baota|none`，默认自动检查宝塔常见全局安装目录和命令入口。识别到宝塔时显示兼容提示，说明 Docker 状态可在面板中查看、域名需要在面板中转发到宿主机 `NGINX_PORT`，并提醒该端口不可与宝塔已有服务冲突。实际服务生命周期仍由 `deploy.sh` 调用标准 Docker Compose 完成。

## 风险与回滚

该变更只增加检测、提示和参数传递，不改变生产 Compose 服务定义。误识别可以通过 `--panel none` 关闭；非标准面板可通过 `--panel baota` 强制提示。回滚时移除两个脚本的检测逻辑和文档即可。
