## Why

生产安装不应要求用户在服务器控制台提前填写管理员邮箱和密码；这会增加一键部署的理解成本，也把长期凭据暴露在部署配置中。安装完成后由第一个真实注册用户成为平台管理员，可以让用户直接完成“安装—打开网站—注册—管理”的流程。

## What Changes

- 移除生产部署向导中的管理员邮箱和管理员密码输入，不再把 `ADMIN_EMAIL`、`ADMIN_PASS` 作为新部署必填项。
- 生产 Compose 初始化只执行数据库迁移和系统数据初始化，不再自动生成临时管理员账号。
- 注册接口在数据库中还没有任何真实用户（排除系统 root 用户）时，将第一个成功注册的用户分配 `admin` 角色并返回管理员状态。
- 使用数据库事务和并发保护确保并发注册最多只有一个首个管理员。
- 已有用户的站点升级、重新部署和后续注册不得自动提权；保留旧管理员环境变量和 CLI 引导能力以兼容已有运维流程。
- 更新生产配置校验、配置模板、部署文档和注册/部署测试。

## Capabilities

### New Capabilities

- `first-user-admin-registration`: 首个真实注册用户获得平台管理员权限，并保证仅在空站点初始化时生效。

### Modified Capabilities

- `production-deploy`: 生产部署不再要求预先填写管理员账号，安装完成后提示首个注册用户获得管理员权限。

## Impact

- 修改 `noj-core` 注册服务、RBAC 角色分配、生产配置校验和启动初始化流程。
- 修改生产 Docker Compose、`.env.prod.example`、部署向导和运营文档。
- 不新增外部依赖；使用现有 PostgreSQL 事务与锁能力保证并发安全。
