## Context

见 proposal.md。当前模板服务直接读取
`problems-src/<number>/`，但题目导入可自动分配题号，目录名不能作为稳定关联键。

## Goals / Non-Goals

**Goals:**

- 仅向题目编辑器返回与数据库题目一致的模板。
- 兼容现有目录名恰好等于题号的题目源。

**Non-Goals:**

- 不修改支持包的评测内容、数据库 schema 或模板 API 响应格式。
- 不为生产环境新增对象存储中的模板持久化。

## Decisions

- 由路由把题目的 `number` 和 `title`
  一起交给模板服务。服务遍历一级源码目录并读取合法 JSON
  manifest，以二者共同匹配目标目录。标题可区分同题号的遗留目录，题号保证不会因为同标题而串题。
- 无匹配或匹配不唯一时返回无模板（HTTP
  404），不回退到同名目录，以避免向用户展示错误题目代码。
- 保留可注入的 `srcRoot`，让纯文件系统的单元测试覆盖解析规则。

## Risks / Trade-offs

- [每次读取需要扫描一级目录] →
  仅在编辑器加载模板时调用，目录数量通常有限；正确性优先于一次不安全的直接定位。
- [旧题目源 manifest 缺少 title/number] → 无法证明归属时返回 404，管理员可补全
  manifest。
