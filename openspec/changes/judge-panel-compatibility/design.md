# 设计：服务器面板兼容模式

## 检测

脚本在环境预检阶段执行面板检测：

- `auto`：检查宝塔常见安装目录和命令入口；命中后标记为宝塔。
- `baota`：强制启用宝塔提示，适合面板安装目录不同的环境。
- `none`：关闭检测和面板提示。

检测只读取文件系统和命令是否存在，不调用面板 API，也不向面板写入配置。检测失败或未命中时按普通 Linux Docker 环境继续。

## 运行行为

识别到宝塔后，在 `install-env`、`install`、`check` 的环境检查阶段提示：

1. 可在宝塔 Docker 页面确认 Docker 已安装并运行。
2. 脚本继续使用系统的 `docker` 和 `docker compose` 命令。
3. 脚本不会接管已有容器、站点、反向代理或面板设置。
4. Judge 必须使用专用 rootless Docker socket，不能使用 `/run/docker.sock` 或 `/var/run/docker.sock`。

普通环境的输出和行为保持不变。Redis 本机模式创建的容器和卷可以被面板 Docker 页面查看，但脚本仍负责连接信息、权限和冲突校验。

## 测试策略

- 离线测试自动检测宝塔标记目录并输出兼容提示。
- 测试 `--panel baota` 强制模式和 `--panel none` 禁用模式。
- 测试面板模式仍拒绝共享 Docker socket。
- 运行 Judge 部署脚本现有回归测试、脚本语法检查和 OpenSpec 校验。

配置向导从管道执行时优先使用 `/dev/tty`，避免读取到脚本源码；无终端时继续按非交互模式提示用户手工配置。
