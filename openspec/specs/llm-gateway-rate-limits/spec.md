## Purpose

为不同部署规模和上游 Provider 额度提供可控的 LLM 网关分钟级保护，同时保持现有部署升级后的默认限流行为一致。

## Requirements

### Requirement: 独立配置用户和 IP 分钟限流

网关 SHALL 支持通过 `NOJ_LLM_USER_RATE_LIMIT_PER_MINUTE` 独立配置每个用户在 UTC 分钟窗口内允许的调用次数，并通过 `NOJ_LLM_IP_RATE_LIMIT_PER_MINUTE` 独立配置每个 IP 在同一窗口内允许的调用次数。

#### Scenario: 使用自定义限流值

- **WHEN** 网关配置用户限流为 `120`、IP 限流为 `30`
- **THEN** 用户维度限流使用 `120`，IP 维度限流使用 `30`，且两者互不影响

#### Scenario: 未配置时保持兼容默认值

- **WHEN** 两个环境变量均未设置
- **THEN** 用户和 IP 维度均使用每分钟 `60` 次

### Requirement: 启动阶段校验限流配置

网关 SHALL 在启动配置加载阶段要求两个限流配置为正整数；缺失配置使用默认值，非正整数、带小数或包含其它字符的值 SHALL 导致启动失败并给出对应配置名称。

#### Scenario: 配置为合法正整数

- **WHEN** 配置值为 `1` 或其它正整数
- **THEN** 网关接受该配置并正常完成配置加载

#### Scenario: 配置为非法值

- **WHEN** 任一配置值为 `0`、负数、小数、空字符串或非数字字符串
- **THEN** 网关配置加载失败，并在错误信息中指出非法配置

### Requirement: 分钟限流使用配置值且不改变其它配额

网关 SHALL 将用户和 IP 的独立配置值用于原子分钟限流检查；提交级、用户/题目/全局日/月调用量、Token 和费用配额 SHALL 继续使用现有逻辑。

#### Scenario: 原子限流脚本接收独立值

- **WHEN** 一次 LLM 调用执行限流检查
- **THEN** Redis 原子脚本收到用户配置值和 IP 配置值，并分别检查对应计数器

#### Scenario: 其它配额逻辑保持不变

- **WHEN** 用户/IP 分钟限流配置发生变化
- **THEN** 提交级及日/月 calls、tokens、cost 配额的键、窗口和判断逻辑不发生变化
