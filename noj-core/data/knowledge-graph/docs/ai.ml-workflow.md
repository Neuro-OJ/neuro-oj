# 机器学习流程（数据、训练、验证、部署）

## 直觉理解

做机器学习项目像做一道完整的菜：先想清楚要给谁吃、做什么菜（问题定义），再采购和清洗食材（数据），按菜谱试做并试味（训练与调参），最后装盘上桌并保证桌桌口味一致（部署与监控）。跳过任何一步都容易"菜端上去才发现没熟"——模型离线分数很高，上线却没用。

## 核心概念

**1.
问题定义**。把业务目标翻译成可测量的预测目标与评价指标：是回归还是分类？错判哪一类的代价更高？上线后以什么信号判定成功？指标要先于建模确定，避免"看结果挑指标"。

**2.
数据**。明确每条样本是什么、标签怎么来、采集时点与预测时点是否一致。要做缺失值、异常值处理和特征构建，并划分训练、验证、测试集，任何用到全量数据的统计量都要格外小心泄露。

**3.
训练与调参**。先建立最简单的基线（如多数类预测、线性模型），再尝试更复杂的方法。调参应在验证集上进行，观察学习曲线判断是欠拟合还是过拟合。

**4.
验证**。除了平均误差，还要看分组表现、最差子群体表现、混淆矩阵。选择最终模型时用测试集只评估一次。

**5.
部署**。保存模型与预处理流水线，固定输入输出契约。线上做推理服务，配置日志与漂移监控，收集真实反馈用于下一轮迭代。

**6. 迭代**。大多数收益来自数据质量和目标定义上的改进，而不单是换更大的模型。

## 常见误区

- 没有基线就直接上复杂模型，无法判断复杂度是否值得。
- 训练时和推理时的预处理不一致（例如线上少做了一次归一化），导致预测分布异常。
- 用测试集反复调参，把测试集变成了验证集，最终评估过于乐观。
- 忽略数据的时间顺序：用未来数据训练、过去数据测试会得到虚高指标。
- 认为上线就是结束：数据分布会漂移，缺了监控，模型退化时无从察觉。
- 把准确率当作唯一指标：类别不平衡时多数类基线就能"骗过"准确率。

## 例题与完整解析

**题目**：一个电商团队想预测"用户本次下单后 7
天内是否会退货"。请搭一个最小可用的流程骨架，并用合成数据跑通"划分—基线—线性模型评估"三件事。

```python
import numpy as np

rng = np.random.default_rng(42)
n = 1000
# 特征1：订单金额（万元）；特征2：历史上以来自动续费次数；标签：是否退货（不平衡）
X = rng.normal(size=(n, 2))
z = -1.5 + 2.0 * X[:, 0] - X[:, 1]
y = (rng.random(n) < 1 / (1 + np.exp(-z))).astype(int)
print("退货比例:", round(y.mean(), 3))

perm = rng.permutation(n)
split = int(0.7 * n)
train, test = perm[:split], perm[split:]
Xtr, ytr, Xte, yte = X[train], y[train], X[test], y[test]

# 基线1：永远预测"不退货"
base_acc = 1 - yte.mean()
# 基线2：逻辑回归（手写梯度下降，标准化后训练）
mu, sd = Xtr.mean(0), Xtr.std(0)
A = np.hstack([np.ones((len(Xtr), 1)), (Xtr - mu) / sd])
w = np.zeros(3)
for _ in range(3000):
    p = 1 / (1 + np.exp(-A @ w))
    w -= 0.1 * A.T @ (p - ytr) / len(ytr)
At = np.hstack([np.ones((len(Xte), 1)), (Xte - mu) / sd])
pred = (1 / (1 + np.exp(-At @ w)) > 0.5).astype(int)
print("多数类基线准确率:", round(base_acc, 3))
print("逻辑回归准确率:", round((pred == yte).mean(), 3))
```

**逐步讲解**：

1. 问题定义层面：退货是不平衡事件，因此除了准确率，还应报告精确率与召回率；这里先用准确率与基线作对比。
2. 划分：用随机置换切出 70% /
   30%，测试集留到最后只用一次。若数据带时间戳，应改按时间切分。
3. 归一化统计量只从训练集计算（`Xtr.mean(0)`、`Xtr.std(0)`），再应用到测试集——这就是"预处理器也属于模型"的含义，部署时需要一起保存。
4. 基线准确率等于测试集中"不退货"样本的比例，约 0.7
   上下。模型必须显著超过基线才算学到东西。实际运行中逻辑回归准确率明显高于基线，说明两个特征确实携带信号。
5. 之后的工作顺序应为：查看分组指标 → 调整正则或特征 → 选择模型 →
   用测试集最终评估 → 保存模型与预处理参数上线并监控。
