# 检索增强生成（RAG）

## 直觉理解

大模型的参数里固化的是一般知识，无法知道你公司最新的制度文档，还会在不知道时自信地编造。RAG
的思路很朴素：**先去资料库里找出相关段落，再把这些段落放进提示，让模型照着材料回答**。像开卷考试——题是新的，但答案的依据当场提供。

## 核心概念

**离线索引**。把文档切块（chunk），用嵌入模型编码为向量，存入向量数据库或索引结构。

**在线流程**：查询 → 检索（向量相似或混合关键词）→ 可选重排 → 组装提示（问题 +
检索到的片段）→ 生成 → 附上引用。

**切块策略**。块太长会稀释相关性并占满上下文，太短会丢失上下文。常见做法是
200–800
词、块间重叠少量字符，并保留标题、表格等结构信息，按自然段落或标题切分优于粗暴定长切分。

**检索**。稠密向量检索擅长语义相近，关键词检索（BM25）擅长专有名词与编号，混合检索取长补短；重排模型对候选做更精细的相关性打分后再取前若干条。

**提示约束**。明确要求"只依据给定资料回答，资料不足时说明无法回答"，并要求标注引用来源，降低编造率。

**评估**。分两层：检索命中率（正确片段是否进入候选）与答案质量（正确性、忠实度、引用是否支持结论）。错误需分层归因——没检索到、检索到但没用上、答错。

## 常见误区

- 把 RAG 当作解决一切幻觉的方案：检索错了或不相关，模型仍会编造。
- 只看最终答案质量，不评估检索召回，导致无法定位问题出在哪一层。
- 切块不考虑文档结构，把一张表格或一个条款切成两半。
- 把检索到的整篇文档一次塞进上下文，既浪费窗口也让关键信息被淹没。
- 忽略权限与隔离：检索结果可能跨用户泄露，必须先做权限过滤再检索。
- 把外部文档内容当作可信指令执行，忽视间接提示注入。

## 例题与完整解析

**题目**：实现一个最小的检索环节：把几段文档向量化，按余弦相似度检索与问题最相关的两段，并组装成带引用编号的提示。

```python
import numpy as np

docs = [
    "图书馆开放时间：周一至周五 8:00-22:00，周末 9:00-17:00。",
    "借阅规则：每证最多借 5 本书，借期 30 天，可续借一次。",
    "自习室预约：需提前一天在校园 App 预约，每次最多 4 小时。",
    "逾期处理：每天 0.2 元，超过 60 天暂停借阅权限。",
]

# 极简"嵌入"：字符级哈希词袋，仅演示流程，真实系统用语义嵌入模型
def embed(text, dim=256):
    v = np.zeros(dim)
    for ch in text:
        v[hash(ch) % dim] += 1.0
    return v / np.linalg.norm(v)

M = np.stack([embed(d) for d in docs])
q = embed("借书最多能借几本，借多久")
sims = M @ q
order = np.argsort(-sims)

top = order[:2]
print("相似度:", np.round(sims[top], 3))
context = "\n".join(f"[{i + 1}] {docs[j]}" for i, j in enumerate(top))
prompt = f"""只依据下列资料回答问题，资料不足时回答"资料中未提及"，并在句末标注引用编号。
资料：
{context}
问题：借书最多能借几本，借多久？
回答："""
print(prompt)
```

**逐步讲解**：

1. 索引阶段把每段文档映射为归一化向量，检索时只需一次矩阵乘法即可得到与查询的余弦相似度（归一化后内积等于余弦）。
2. 字符哈希词袋只能捕捉字面重叠，因此"借书"与"借阅"这类同义改写会漏检——这正是真实系统要用语义嵌入模型和关键词混合检索的原因。它是一个可运行的骨架：换成嵌入模型时只需替换
   `embed`。
3. 取相似度最高的两段，按出现顺序编号后拼进上下文。编号让模型能标注来源，也让使用者可以核对。
4. 提示中明确"资料不足就说未提及"和引用格式要求，是压低幻觉的关键约束；同时程序侧仍应检查回答中的编号是否落在候选范围。
5. 改进方向：切块与重叠、加 BM25
   混合检索、用重排模型精排、把历史对话改写为独立查询、为每个答案记录引用片段以便审计。
